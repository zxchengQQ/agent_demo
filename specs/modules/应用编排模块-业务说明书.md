# 应用编排模块 业务说明书

> **模块工程**：`agent-demo-app`（后端） + `agent-demo-web/WorkflowController`（接口层） + `agent-demo-frontend`（编排页面）
> **迭代来源**：`specs/features/2026-08-13_应用编排层/`（P1 适配层+串行 / P2 多模式+前端 / P3 Supervisor+断点恢复）+ `specs/features/20260824_workflow-hitl/`（工作流 HITL）
> **返回模块索引**：[specs/modules/README.md](README.md)

## 1. 模块概述

应用编排模块是项目的**多 Agent 协作工作流引擎**，基于 `langchain4j-agentic:1.17.2-beta27` 构建。开发者通过 Java 代码声明 Agent 接口与编排模板（启动时自动注册），终端用户通过前端"编排"页面选择模板、填写参数、执行并实时观看每个 Agent 的流式输出。

核心能力：
- **5 种编排模式**：串行（Sequential）、并行（Parallel）、条件分支（Conditional）、循环（Loop，含 maxIterations 上限）、Supervisor 层级（主控拆解→Worker 执行→主控汇总）
- **失败容错**：Agent 失败自动重试（模板级可配，默认 3 次）→ 重试耗尽工作流**暂停**（PAUSED）→ 支持断点恢复（已完成步骤跳过不重跑）
- **HITL 人工确认**：@HumanCheckpoint 注解标注需人工确认的方法，执行至检查点进入 **WAITING_USER** 状态推送 `workflow_waiting` 事件，前端弹确认横幅，`hitl-reply` 端点回复后以 `workflow_resumed` 恢复执行（并行分支多 HITL 排队处理）
- **执行可视化**：SSE 推送 19 种事件（步骤进度、token 流式、重试、暂停、恢复跳过、Supervisor 子任务调度、HITL 等待/恢复）
- **预置模板**：5 个开箱即用模板（见第 3.6 节）

包结构（7 包 44 类）：

| 包 | 职责 | 关键类 |
|----|------|--------|
| `app.adapter` | 桥接项目已有基础设施（不重复造轮子） | `AgenticAgentFactory`（模型解析/工具注入/提示词加载） |
| `app.core` | 领域模型 | `WorkflowTemplate`、`WorkflowExecution`、`AgentDefinition`、`SupervisorDefinition`、`WorkflowExecutionStatus`（含 WAITING_USER）、`@HumanCheckpoint` 注解、`WorkflowHITLState` 等 17 类 |
| `app.strategy` | 编排策略（策略模式） | `Sequential/Parallel/Conditional/Loop/SupervisorExecutionStrategy`、`SubtaskParser`（并行策略含 HITL 异常排队） |
| `app.execution` | 执行基础设施 | `AgentExecutor`（重试+流式回调+@HumanCheckpoint 反射检测）、`WorkflowEventPublisher`（SSE 发送容错） |
| `app.service` | 协调层 | `WorkflowExecutionService`（含 handleHITLPaused / hitlReply 恢复）、`ResumableExecutionState`（暂停快照，含 hitlState HITL 快照）、3 个流程控制异常 |
| `app.registry` | 模板注册中心 | `WorkflowTemplateRegistry`（启动扫描注册） |
| `app.template` | 预置模板与 Agent 接口 | 5 模板 + 13 个 `@Agent` 接口 |

## 3. 业务功能点

### 3.1 模板列表与详情
`GET /api/app/workflows` 返回模板摘要（名称/描述/模式/Agent 数/参数定义）；`GET /{templateId}` 返回详情（每个 Agent 的模型、工具列表、参数定义）。模板不存在返回 `WORKFLOW_NOT_FOUND(5500)`。

### 3.2 执行工作流（SSE）
`POST /{templateId}/execute`，缺少必填参数返回 `WORKFLOW_PARAM_MISSING(5501)`。服务端创建执行实例并返回 SSE 流；前端按 executionId 区分并发执行。

### 3.3 实时可视化
SSE 事件序列：`workflow_start` → `step_start`/`token`/`step_complete`（或 `step_error`/`step_retry`）→ … → `workflow_complete`/`workflow_failed`/`workflow_paused`。模式专属事件：`branch_selected`（条件）、`loop_iteration`（循环）、`group_start`/`group_complete`（并行）、`supervisor_plan`/`supervisor_dispatch`/`supervisor_summary`（Supervisor）。HITL 事件：执行至检查点时推送 `workflow_waiting`（含 HITL 详情与 ask_user 数据），用户回复后推送 `workflow_resumed` 恢复执行。

### 3.4 HITL 人工确认
- 触发：模板中 `@Agent` 接口方法标注 `@HumanCheckpoint` 注解，`AgentExecutor` 在方法执行前反射检测，构造确认型 askUser 数据（type=confirm）；或 hitlEnabled Agent 在 `HITLReActStream` 中调用 ask 级工具（如 httpGet）触发 tool_confirm（20260825 全域统一新增，BR-PERM-012）。
- 等待：执行状态置 **WAITING_USER**（与 PAUSED 语义分离，非终态），推送 `workflow_waiting` + `ask_user`/`tool_confirm` 事件，前端 5 个模式特定执行视图弹出 HITL 等待横幅（AskUserCard/ConfirmCard）。
- 恢复：`POST /executions/{executionId}/hitl-reply`，请求体 `message`/`approved` 至少一个非空，经恢复键 `hitl:{iteration}:{agentName}` 定位恢复点，推送 `workflow_resumed` 继续执行。检查点拒绝（approved=false）则状态置 **TERMINATED**。
- tool_confirm 恢复（20260825 新增）：ask 级工具经 `WorkflowHITLState`（MODE_TOOL_CONFIRM + ToolConfirmData）保存暂停点；批准后执行工具、结果回填续跑；**拒绝=拒绝续跑**（回填脱敏拒绝文案 LLM 换方案，不终止工作流，区别于 checkpoint 拒绝即终止，决策 7）；拒绝文案不暴露权限配置细节。
- 并行排队：并行策略 `join()` 收集多个 HITL 异常——第一个传播给协调层进入 WAITING_USER，其余写入 `WorkflowContext.PENDING_HITL_KEY` 排队列表；hitlReply 恢复时先按序消费队列，避免重复等待。
- 超时清理：WAITING_USER 超过 30 分钟置 **TIMEOUT** 清理（BR-WHITL-007）。

### 3.5 自动重试与暂停
Agent 异常时 `AgentExecutor` 自动重试（`step_retry` 事件含次数）；重试耗尽抛 `WorkflowPausedException`，执行状态置 **PAUSED** 并推送 `workflow_paused`（含失败步骤、错误、可恢复提示）。

### 3.6 断点恢复与终止
- 恢复：`POST /executions/{executionId}/resume`（仅 PAUSED 且快照存在，否则 `WORKFLOW_NOT_RESUMABLE(5507)`）。已完成步骤推送 `step_skipped` 直接复用历史输出，从失败步骤重跑。
- 终止：`DELETE /executions/{executionId}`，执行中 Agent 中断，状态 **TERMINATED**（终态不可恢复）。
- 恢复流与执行流均为 SSE；新 SSE 流跳过已完成步骤。

### 3.7 预置模板（5 个）

| 模板 | 模式 | Agent 组成 | 场景 |
|------|------|-----------|------|
| 研究-分析-总结 | SEQUENTIAL | 研究→分析→总结 | 信息调研类任务 |
| 多视角审查 | PARALLEL | 安全/性能/风格审查 3 组并行 | 内容多维度评审 |
| 智能路由 | CONDITIONAL | 简单回答 ↔ 复杂拆解分支 | 按复杂度分流 |
| 质量评分-修订 | LOOP | 评分↔修订循环（maxIterations=5） | 迭代优化至达标 |
| 任务拆解-执行-汇总 | SUPERVISOR | 主控（拆解/汇总）+ 研究/分析/总结 Worker | 复杂任务自主分解 |

### 3.8 执行历史
`GET /api/app/workflows/executions` 返回执行列表（状态含 COMPLETED/FAILED/TERMINATED/TIMEOUT/PAUSED/**WAITING_USER**）；PAUSED/WAITING_USER 记录可从前端历史页一键跳转恢复/回复。

## 4. 业务流程串联

```
模板注册（启动时）→ 用户选模板填参数 → execute 创建执行实例
  → 策略按模式编排（AgenticScope 自动传递上游输出）
  → AgentExecutor 逐个执行（重试/流式回调）→ SSE 实时推送
  → 成功: workflow_complete（最终结果+耗时）
  → 失败且重试耗尽: PAUSED + 快照 → resume（跳过已完成）或 terminate
  → 遇 @HumanCheckpoint: WAITING_USER + workflow_waiting（前端弹确认横幅）
      → hitl-reply 回复（approved/message）→ workflow_resumed 继续
      → 检查点拒绝: TERMINATED ｜ 超 30 分钟: TIMEOUT
  → 超时: TIMEOUT（默认 5 分钟）｜用户停止: TERMINATED
```

Supervisor 模式细节：主控 PlanAgent 将任务拆解为子任务 JSON（`SubtaskParser` 解析，含 Worker 名路由，未匹配名兜底路由）→ 依次派发 Worker 执行 → 全部完成后主控 SummarizeAgent 汇总。

## 5. 安全与合规

- 工具集在模板中预定义，执行时不可修改（用户无法注入未授权工具）
- SSRF 防护沿用工具模块的白名单机制（`builtin:httpGet` 等）
- 模板引用的模型必须已在 LLM 配置中注册（UUID 优先、modelName 兜底解析），否则拒绝执行
- 无敏感数据持久化：执行状态仅存内存，重启即清空

## 6. 前端入口

导航栏"编排"入口（与对话/知识库/设置并列，BR-APP-016）。组件：`WorkflowPage`（视图切换）、`WorkflowTemplateList`（卡片）、`WorkflowHistoryList`（历史+恢复/回复入口）；按模板模式分派到 5 个模式特定执行视图 `SequentialExecuteView`/`ParallelExecuteView`/`LoopExecuteView`/`ConditionalExecuteView`/`SupervisorExecuteView`（20260824 迭代从单一 `WorkflowExecuteView` 拆分，均含参数表单+步骤面板+暂停 banner+**HITL 等待横幅**，复用 `AskUserCard`/`ConfirmCard`）；API 封装 `api/workflow.ts`（含 SSE 解析与断流兜底、`workflow_waiting`/`workflow_resumed` 事件处理、`replyToWorkflow` HITL 回复接口）。

## 7. 核心数据实体

| 实体 | 说明 |
|------|------|
| `WorkflowTemplate` | 模板定义（模式、Agent 列表、参数、maxRetries、Supervisor 定义） |
| `WorkflowExecution` | 执行实例（executionId、状态、步骤列表、最终结果、起止时间） |
| `StepExecution` / `StepStatus` | 单步执行记录（Agent 名、输出、耗时、状态） |
| `AgentDefinition` | Agent 声明（modelId、toolIds、roleName×scenarioName、interfaceClass） |
| `SupervisorDefinition` | 主控定义（planAgent、workers、summarizeAgent、maxSubtasks） |
| `Subtask` | Supervisor 子任务（描述、路由 Agent 名） |
| `ResumableExecutionState` | 暂停恢复快照（已完成步骤输出、AgenticScope 状态、失败位置 + `hitlState` HITL 检查点快照：迭代号/Agent 名/askUser 数据/恢复键） |
| `WorkflowHITLState` | HITL 暂停状态（iteration、agentName、mode：askUser/checkpoint/toolConfirm、askUserData、toolConfirmData，20260825 扩展 toolConfirm 三模式） |
| `WorkflowContext` | 执行上下文（含 `PENDING_HITL_KEY` 并行 HITL 排队列表） |

状态机：`PENDING → RUNNING → COMPLETED / FAILED / TERMINATED / TIMEOUT / PAUSED / WAITING_USER`（PAUSED → RUNNING 可循环，恢复后再失败可再暂停；WAITING_USER → RUNNING 经 hitl-reply 恢复，检查点拒绝置 TERMINATED、tool_confirm 拒绝续跑（决策 7），超 30 分钟置 TIMEOUT）。

## 10. 异常处理

| 错误码 | 场景 | 处理 |
|--------|------|------|
| WORKFLOW_NOT_FOUND(5500) | 模板/执行不存在 | 全局异常处理器转 JSON |
| WORKFLOW_PARAM_MISSING(5501) | 缺必填参数 | 提示参数名 |
| WORKFLOW_MODEL_NOT_FOUND(5502) | Agent 引用模型未配置 | 提示 Agent 名与模型名 |
| WORKFLOW_EXECUTION_FAILED(5503) | 执行失败 | SSE `workflow_failed` |
| WORKFLOW_TIMEOUT(5504) | 全局超时（默认 5 分钟） | 状态 TIMEOUT，不可恢复 |
| WORKFLOW_ALREADY_TERMINATED(5505) | 重复终止 | 拒绝操作 |
| WORKFLOW_MODE_NOT_SUPPORTED(5506) | 模式无策略实现 | 拒绝执行 |
| WORKFLOW_NOT_RESUMABLE(5507) | 非 PAUSED 态恢复；或非 WAITING_USER 态 hitl-reply / HITL 快照缺失 | 拒绝恢复/回复 |

## 11. 性能要求

- 并发执行互不干扰（独立 executionId + AgenticScope，AC-020）
- SSE emitter 配置为**永不超时（0L）**，长任务（>5 分钟）不被掐断；客户端断开由 onError→cancel 兜底（2026-08-17 BUG 修复沉淀）
- 前端断流兜底：流结束未收到终态事件即提示"连接中断"，页面不卡"执行中"
- token 事件发送失败降级 WARN 不阻断工作流线程（`WorkflowEventPublisher` 容错）
