> **文档定位**：本功能为平台新增**第 10 个能力域**（Agent Skill 能力包机制），横切单 Agent 对话链路的行为增强层，不改变现有 Agent 的 ReAct 推理模式与工具权限体系。
> **关联文档**：`specs/features/20260824_tool-permission-control/`（工具三级权限模型，Skill 工具绑定的协同基础）、`specs/features/20260825_tool-permission-unification/`（权限全域统一管控，BR-PERM 系列规则）、`specs/features/20260826_tool-output-sanitization/`（工具产出清洗，间接注入防护的既有防线）

## 1. 背景与价值 (Context & Value)

* **背景**: 平台已实现 9 大能力域，其中 RAG 解决"知识从哪来"、MCP 解决"外部工具从哪来"，但**领域行为指令**只能硬编码在系统提示词中，存在两类痛点：
    1. **常驻提示词膨胀**：所有领域的风格、流程、约束全部常驻注入，Skill 数量增长后上下文成本线性上升；
    2. **行为不可编排**：学习者无法观察"Agent 如何在运行时按需获得领域能力"这一 Agent 工程核心机制。
* **目标**: 一个 Agent 通过按需加载"能力包"（Skill）在不同领域表现专家行为，无需膨胀常驻提示词；Skill 与 RAG（知识）、MCP（外部工具）正交互补。
* **核心机制**: Skill = 元数据（名称/描述）+ 领域指令 + 只读参考资源 + 自带脚本工具；Agent 平时仅感知元数据目录，对话匹配时按需加载完整内容（**渐进式披露**）。脚本工具为 Skill 预定义参数化脚本（白名单语言 shell/python3），激活时动态注册，不绑定系统既有工具。
* **关联**: 平台能力矩阵第 10 项；工具绑定复用工具权限体系（20260824/20260825 迭代）；间接注入防护与工具产出清洗（20260826 迭代）形成纵深。

## 2. Agent 角色定义 (Agent Persona)

### 2.1 身份定位

* **角色名称**: Agent Skill 能力域（agent-skill）
* **角色类型**: 混合型（对话为主 + 领域任务增强；横切单 Agent 对话链路的能力层，非新增独立 Agent）
* **身份描述**: 为现有单 Agent 对话链路注入"可插拔的领域专家能力"：Agent 通过常驻元数据目录感知全部可用 Skill，在用户消息匹配时自主加载并应用，或由用户手动指定/排除。
* **核心价值**: 学习者可创建、管理、观察 Skill 的按需激活机制（演练价值）；对话用户在领域任务中获得专家级行为而无需切换 Agent（使用价值）。

### 2.2 目标用户与场景

* **目标用户**: 学习者（创建/管理 Skill、观察渐进式披露机制）+ 对话用户（自动受益于激活的 Skill）
* **使用场景**:
    1. 学习者创建自定义 Skill（如"周报撰写"），在对话中提问，观察 Agent 按需激活后的行为变化；
    2. 对话用户请求领域任务，Agent 自动激活匹配 Skill 并遵循其流程/风格/工具；
    3. 管理员在管理页维护 Skill（预置 + 自建）及其自带脚本工具。
* **交互风格**: 沿用平台现状（专业简洁）；Skill 激活状态对用户透明可见（SSE 事件 + 前端展示），激活本身不打断对话流。

## 3. 能力边界与自主性 (Capability & Autonomy)

### 3.1 能力清单（In Scope）

* **Skill 感知与激活**：基于常驻元数据目录的自主匹配激活（高置信直激活）+ 会话级手动指定/排除（混合激活；手动指定支持选择器与 `/skill` 前缀指令双入口，AC-N07）
* **渐进式披露**：仅元数据常驻，完整指令与资源经"加载 Skill"动作按需读取
* **多 Skill 并发**：同一会话最多 3 个 Skill 同时生效，冲突时平台安全规则优先
* **三形态增强**：纯指令型 / 指令+只读资源型 / 指令+自带脚本工具型
* **Skill 管理**：创建/编辑/删除/启用禁用/脚本管理（管理页），内容安全校验
* **标准目录结构**：Skill 按 `data/skills/{id}/SKILL.md + scripts/ + reference/` 持久化，启动时自动迁移旧版单文件 JSON（AC-N08）
* **预置 Skill**：3 个开箱即用（见 8.1）
* **激活状态透明**：激活/退出经 SSE 事件透出，前端展示，用户可回滚（排除）；`/skill` 指令指定在用户消息气泡保留原始输入展示（含技能名，所见即所得，CR-002）

### 3.2 能力禁区（Out of Scope）

* **Skill 自带脚本不进入系统权限模型** - 脚本工具（skill_{id}_{script}）不受 allow/ask/deny 约束，改由脚本自身安全护栏统一管控（语言白名单/参数校验/执行超时/危险命令拦截/输出截断）；系统工具权限判定仍全域唯一（BR-PERM 系列）
* **Skill 不得突破平台既有护栏** - SSRF 防护、目录白名单、响应截断、工具产出清洗等安全机制对 Skill 其余行为同样生效；脚本执行受脚本护栏独立管控
* **对话内容不可修改 Skill 配置** - 配置仅经管理页 API 变更（与 BR-PERM-007 同构）
* **Skill 仅携带预定义参数化脚本** - 脚本语言白名单（shell/python3）+ 声明式参数（类型/必填/取值范围）+ 执行超时/输出截断/危险命令拦截；Agent 只能按声明参数调用，不可编写或执行任意代码（CR-001 推翻 v1.0 "不携带可执行脚本"能力禁区）
* **Skill 指令不得冒充/覆盖系统安全规则** - 创建时校验拦截（见 6.1）

### 3.3 自主性级别

* **级别**: 分层自主性（与工具权限全域统一需求的表述方式一致）：

| 层面 | 自主性级别 | 说明 |
|------|-----------|------|
| Skill 激活决策 | **L3 - 自主执行可回滚** | 高置信匹配即自主激活（激活仅注入指令、无外部副作用），激活状态透明可见，用户可随时排除回滚 |
| Skill 加载（渐进式披露） | **L3 - 自主执行可回滚** | 加载为只读动作，失败可降级 |
| Skill 自带脚本执行 | **L3 - 自主执行可回滚（脚本护栏）** | 激活后脚本工具自动注册可调用；执行经脚本护栏（参数校验/超时/危险命令拦截/输出截断），不进入系统权限确认流（AC-T03/S06） |

* **人类介入点**: ①匹配歧义时（askUser 追问，最多 1 次）；②并发达上限时（引导选择）；③Skill 创建/编辑校验失败时（管理页反馈）；④ask 级系统工具执行前（tool_confirm 确认卡片，与 Skill 无关的全局工具）。

### 3.4 知识边界

* **知识范围**: Skill 指令与资源仅在激活后增强当前会话的领域行为；Agent 通用能力（闲聊、通用问答、常驻工具）不受影响。
* **超出边界处理**: 无匹配 Skill 时以通用能力正常对话，不强行激活；Skill 资源未覆盖的细节由 Agent 通用能力补足，但不得虚构"Skill 要求"的内容。

## 4. 工具与动作空间 (Tools & Action Space)

### 4.1 工具清单

| 工具/动作 | 用途 | 输入 | 输出 | 副作用 | 权限 | 限制 | 常见失败场景 |
|---------|------|------|------|--------|------|------|-------------|
| Skill 元数据目录（常驻注入，非工具调用） | 让 Agent 感知全部启用 Skill | - | 名称+描述清单 | 无 | 只读 | 仅元数据，不含完整指令 | 目录为空（无启用 Skill） |
| loadSkill（加载 Skill） | 激活时加载完整指令+资源 | Skill 标识 | 指令文本+资源内容+脚本工具清单 | 无 | 只读 | 单会话最多 3 个激活；并发上限后拒绝 | 内容读取失败/格式异常 |
| Skill 管理 REST API | CRUD/启用禁用/脚本管理 | Skill 定义+脚本声明 | 操作结果 | **有**（管理数据） | 管理页专用 | **对话通道不可达**；内容安全校验 | 校验失败/存储失败 |
| Skill 自带脚本工具（skill_{id}_{script}，动态注册） | 激活后注册进会话工具集，按声明参数调用 | 声明式参数（name/type/required/取值范围） | 脚本标准输出/错误（截断 4K） | **有**（执行脚本，受护栏约束） | 脚本护栏（语言白名单/超时/参数校验/危险命令拦截） | 不进入系统权限模型，受脚本护栏管控 | 超时/命令被拦/参数非法（护栏提示） |

### 4.2 工具间关系

* **依赖关系**: loadSkill 的输出（指令+资源+脚本清单）注入会话上下文；自带脚本工具的注册依赖对应 Skill 已激活。
* **互斥关系**: Skill 管理 API 与对话通道互斥（对话中无法触达管理操作）；Skill 指令与平台安全规则冲突时后者优先。
* **编排策略**: 元数据目录常驻 -> 用户消息匹配（或 /skill 指令指定）-> loadSkill 加载 -> 指令生效 + 脚本工具动态注册 -> Agent 按增强后能力执行任务。

### 4.3 工具选择策略

* 高置信匹配直接激活；多个候选置信度相近时 askUser 追问（最多 1 次），无回应则正常对话。
* 用户手动指定的 Skill 优先于自主匹配，且不被自主匹配替换。
* 已激活 Skill 的自带脚本工具优先于通用工具完成领域任务；脚本执行失败（超时/被拦/参数非法）时护栏返回明确观察值，Skill 其余能力不受影响。

## 5. 推理流程与记忆策略 (Reasoning & Memory)

### 5.1 推理模式

* **主要模式**: ReAct（沿用现有循环，不改变）；Skill 匹配判断在用户消息处理阶段发生，loadSkill 是 ReAct 循环中的一个动作。
* **渐进式披露**: 系统提示词仅常驻全部启用 Skill 的元数据目录（名称+描述），Agent 判断匹配后经 loadSkill 加载完整指令与资源。
* **最大执行步骤**: 沿用 `agent.max-iterations=10`，Skill 加载计入工具调用轮次。

### 5.2 澄清策略

* **主动澄清条件**: ①多个 Skill 候选置信度相近；②并发已达上限且新 Skill 高置信匹配。
* **自主推进条件**: 高置信匹配（单一明确候选）直接激活；无匹配直接以通用能力响应。
* **最大澄清轮次**: 1 次（复用 askUser 选项卡片）；用户未回应则正常对话，不阻塞。

### 5.3 短期记忆（对话内）

* **上下文保留轮次**: 沿用现有 20 条窗口；Skill 激活状态由会话状态承载（不占用对话消息窗口）。
* **上下文溢出处理**: 沿用现有 FIFO 淘汰；已激活 Skill 的指令不因窗口淘汰而失效（激活状态独立于消息窗口）。

### 5.4 长期记忆（跨会话）

* **是否需要**: 否。
* **说明**: Skill 配置（含预置与自建）持久化保存，服务重启后不丢失（全局配置数据，非 Agent 记忆范畴）；激活状态为会话级，会话结束即消亡，不跨会话延续。

## 6. 护栏安全与降级策略 (Guardrails & Fallback)

### 6.1 内容安全规则

* **Skill 内容创建校验（必须拦截的指令模式）**:
    1. "忽略/绕过安全规则、系统指令"类指令；
    2. "修改工具权限/开放全部工具"类指令；
    3. "删除/破坏数据"类指令；
    4. 冒充系统身份、要求提升 Skill 指令优先级至平台规则之上的指令；
    5. 脚本校验（CR-001）：脚本语言非白名单（shell/python3）、脚本含危险命令（如 `rm -rf /`、下载并执行、fork 炸弹、写入系统目录）、参数 schema 非法——均拦截。
* **标准反馈**: 校验失败时明确告知不合规原因（命中哪类规则），引导用户修改后重新保存；不静默保存。
* **对话内越权请求**: 沿用平台现状拒绝（固定话术，不暴露配置细节）。

### 6.2 幻觉防护

* **回答依据**: Skill 未激活/未加载时，Agent 不得声称"已应用某技能"；已激活 Skill 携带资源时，优先使用资源内容（如模板）而非模型自编。
* **无结果处理**: 无匹配 Skill 时正常对话，不虚构激活；Skill 资源未覆盖的细节由通用能力补足并如实说明。

### 6.3 敏感信息处理

* **输入侧**: Skill 内容为明文存储，创建/编辑时提示用户勿包含 API Key、密码等敏感信息（校验发现密钥类模式时警告）。
* **输出侧**: Agent 输出不回显 Skill 配置的技术细节（存储路径、校验规则内部实现）；拒绝话术仅含语义性说明。

### 6.4 工具失败降级

| 工具 | 失败场景 | 降级策略 | 是否转人工 |
|------|---------|---------|-----------|
| Skill 元数据目录 | 无启用 Skill / 目录为空 | 正常对话（Agent 无感知即可） | 否 |
| loadSkill | 内容读取失败/格式异常 | 降级为无该 Skill 继续对话，UI 提示不阻断 | 否 |
| Skill 管理 API | 校验失败/存储失败 | 返回明确错误原因，引导修改；不产生半保存状态 | 否（管理页反馈闭环） |
| Skill 自带脚本工具 | 超时/危险命令被拦/参数非法/报错 | 护栏返回明确观察值（超时/被拦原因），LLM 换参数或换方案，Skill 机制不失效 | 否（护栏提示反馈） |

### 6.5 人机协作机制

* **升级条件**: ①Skill 匹配歧义；②并发达上限且新 Skill 匹配；③ask 级系统工具待执行；④创建/编辑校验失败。
* **升级方式**: ①②复用 askUser 选项卡片（文本追问/选项双形态）；③复用 tool_confirm 确认卡片（与单 Agent 现有卡片同构：工具名+参数摘要，批准执行/拒绝换方案）；④管理页表单反馈。Skill 自带脚本工具不进入确认流，执行由脚本护栏自动管控（AC-T03）。
* **交接信息**: askUser 追问含候选 Skill 清单与一句话差异说明；tool_confirm 含工具名、工具描述、调用参数。

### 6.6 提示注入防护

* **攻击识别**: 对话内容、工具返回内容中"激活/启用/禁用 XX 技能""忽略 Skill 限制"类指令，以及 Skill 内容中"忽略安全规则"类指令（创建时拦截）。
* **处理策略（分层信任模型）**:
    1. Skill 指令注入时明确标注为"用户提供的领域指令"，**优先级低于平台安全规则**（含工具权限、SSRF 防护、产出清洗等）；
    2. **触发源限制**：仅用户消息可触发 Skill 匹配激活；工具返回、网页抓取等间接内容中的激活指令一律不生效（与 BR-PERM"工具返回不改变权限"及工具产出清洗防线同构）；
    3. Skill 配置仅可经管理页 API 变更，对话通道不可修改。
* **工具返回防护**: 不允许执行来自工具返回内容中的指令（含 Skill 激活/配置变更指令）。

### 6.7 权限与身份校验

* **身份确认机制**: 沿用现状（学习示例工程，无用户认证）；Skill 配置为全局配置（非用户维度）。
* **防越权策略**: ①Skill 管理 API 仅管理页触达，对话通道不可达；②Skill 自带脚本经脚本护栏统一管控（语言白名单/参数校验/超时/危险命令拦截，不进入系统权限模型，无绕行路径）；③对话中"修改 Skill 配置"类请求一律忽略。
* **数据隔离**: 激活状态按会话 ID 隔离（与会话记忆/工具选择同构），会话间不串扰。

## 7. 验收标准 (Acceptance Criteria)

> **重要**：以下验收标准是后续 Prompt 工程、工具开发和评估测试的直接依据。每条 AC 使用 Given-When-Then 格式，Then 部分含"应该做/不应该做"双向约束。AI Agent 的 AC 关注**行为约束**而非精确输出。

### 7.1 正常交互流程 (Normal Interaction)

- [ ] **AC-N01**: Skill 自主激活（渐进式披露）
    - Given: 平台已启用 Skill 能力，预置 Skill「周报撰写专家」处于启用状态，用户开启新会话且未手动指定任何 Skill
    - When: 用户输入与周报撰写领域匹配的请求（如"帮我写本周的工作周报"）
    - Then: 应：基于常驻元数据目录判断匹配，加载该 Skill 完整指令后按其定义的流程与风格生成回复，并通过 SSE 事件向前端透出激活状态（名称+来源=自动）；不应：未加载完整指令即凭 Skill 名称/描述臆造领域流程

- [ ] **AC-N02**: Skill 指令风格生效
    - Given: 纯指令型 Skill（如「周报撰写专家」）已在当前会话激活，其指令定义了周报结构（本周成果/数据/风险/下周计划）
    - When: 用户请求生成周报
    - Then: 应：输出遵循 Skill 指令定义的结构与风格约束；不应：忽略已加载指令按通用风格作答

- [ ] **AC-N03**: 手动指定优先且不被替换（选择器 / `/skill` 指令双入口）
    - Given: 用户通过会话级 Skill 选择器或 `/skill 技能名` 前缀指令手动指定 Skill A，另一 Skill B 处于启用状态且与用户输入部分匹配
    - When: 用户输入与 Skill B 也匹配的请求
    - Then: 应：仅激活用户指定的 Skill A（手动指定优先于自主匹配）；不应：自主替换或追加用户显式指定之外的选择

- [ ] **AC-N07**: `/skill` 前缀指令强制指定技能（CR-001 新增；CR-002 修改展示方式）
    - Given: 平台已启用 Skill 能力，存在启用状态的技能（如「数据查询助手」）
    - When: 用户在消息输入框输入 `/skill 数据查询助手 帮我查 XX 数据`
    - Then: 应：解析 `/skill` 前缀，将指定技能设为会话手动指定（与选择器指定同语义），用户消息气泡**保留原始输入展示（含技能名，所见即所得）**，发送给 LLM 的消息剥离指令前缀；不应：将指令前缀作为普通消息发给 LLM，或指定技能不存在时静默忽略（应提示并保持自动模式），或以 AI 提示消息/可视化区块形式额外展示技能

- [ ] **AC-N08**: 标准目录结构持久化与迁移（CR-001 新增）
    - Given: 平台 skill.storage-dir=data/skills，存在旧版单文件技能 data/skills/{id}.json
    - When: 应用启动
    - Then: 应：将旧 JSON 自动迁移为标准目录结构 data/skills/{id}/SKILL.md（+ scripts/ + reference/），迁移后功能与数据完整（id/name/description/instruction/resources/scripts/enabled/source 全保留）；不应：迁移丢失或损坏用户数据，或重复迁移覆盖已迁移目录

- [ ] **AC-N04**: 多 Skill 并发融合
    - Given: 当前会话已激活 Skill A，激活数未达上限（3 个）
    - When: 用户输入与 Skill B 高置信匹配
    - Then: 应：追加激活 Skill B，两个 Skill 的指令同时生效，指令冲突时以平台安全规则优先；不应：因已有激活 Skill 而拒绝新的高置信匹配，或静默超出并发上限

- [ ] **AC-N05**: Skill 资源被使用
    - Given: 指令+资源型 Skill 已激活，其只读资源中包含文档模板
    - When: 用户请求生成对应文档
    - Then: 应：读取并遵循资源中的模板结构生成内容；不应：忽略已加载的资源自行编造模板结构

- [ ] **AC-N06**: Skill 管理闭环与预置初始态
    - Given: 管理员进入 Skill 管理页，系统含 3 个预置 Skill（周报撰写专家/技术文档撰写助手/数据查询助手），技能按标准目录结构存储
    - When: 管理员执行创建、编辑、删除、启用禁用、脚本管理操作
    - Then: 应：操作成功后 Skill 列表正确刷新，对话链路自下一轮起生效，Skill 配置持久化（重启不丢失、目录结构完整）；不应：管理操作导致进行中会话的已加载 Skill 内容中途突变（变更自下一轮生效）

### 7.2 工具选择与调用 (Tool Selection & Invocation)

- [ ] **AC-T01**: 渐进式加载（仅匹配后加载全文）
    - Given: 系统提示词仅含全部启用 Skill 的元数据目录（名称+描述），完整指令未注入
    - When: 用户请求与某 Skill 匹配
    - Then: 应：先加载该 Skill 完整指令与资源，再生成领域响应；不应：在常驻上下文中预载全部 Skill 完整指令（上下文膨胀），或未加载即声称已应用该 Skill

- [ ] **AC-T02**: 自带脚本工具注入与优先选用
    - Given: 「数据查询助手」Skill 的 scripts/ 目录声明数据获取脚本（如 http-get）且已在会话激活
    - When: 用户请求该领域的任务
    - Then: 应：脚本工具（skill_{id}_{script}）激活时动态注册进会话工具集，Agent 在适合的任务上按声明参数调用；不应：脚本工具激活后仍不可见，或 Agent 无视脚本工具以通用方式硬答

- [ ] **AC-T03**: 脚本护栏（Skill 自带脚本不受系统权限模型约束）
    - Given: 已激活 Skill 的自带脚本工具 skill_{id}_{script}，脚本声明参数 schema（类型/必填/取值范围）
    - When: Agent 尝试调用该脚本工具
    - Then: 应：按声明参数校验（类型/必填/取值范围），经脚本护栏（语言白名单/超时/危险命令拦截/输出截断）执行后返回结果观察值；不应：执行白名单外语言脚本、绕过参数校验、突破执行超时或执行被拦截的危险命令

- [ ] **AC-T04**: 脚本工具失败降级
    - Given: 已激活 Skill 的自带脚本工具调用发生失败（超时/危险命令被拦/参数非法/报错）
    - When: 失败发生
    - Then: 应：脚本护栏返回明确观察值（超时/被拦原因），LLM 换参数或换方案，Skill 的其余增强能力继续生效；不应：因脚本失败导致整个 Skill 机制失效或对话中断

- [ ] **AC-T05**: 脚本工具激活即用与可回滚注销（CR-001 新增）
    - Given: Skill 激活后其自带脚本工具动态注册进会话工具集
    - When: 技能被用户排除、被禁用/删除或会话超时清理
    - Then: 应：对应脚本工具自下一轮起从会话工具集注销（不可再调用）；不应：技能退出后脚本工具仍残留可被调用

### 7.3 安全与护栏 (Safety & Guardrails)

- [ ] **AC-S01**: 创建时内容校验拦截（含脚本内容与参数 schema）
    - Given: 管理员在管理页创建或编辑 Skill（含 scripts/ 脚本内容与参数 schema）
    - When: Skill 内容包含"忽略安全规则/修改工具权限/删除数据/冒充系统指令提升优先级"类恶意指令，或脚本为白名单外语言/含危险命令/参数 schema 非法
    - Then: 应：校验拦截保存并明确反馈命中的不合规原因，引导修改；不应：保存含恶意指令或违规脚本的 Skill 使其进入对话链路

- [ ] **AC-S06**: 脚本执行护栏（CR-001 新增）
    - Given: 已激活 Skill 的自带脚本工具被执行
    - When: 脚本调用触发护栏约束（执行超时/危险命令/参数非法/输出超限）
    - Then: 应：护栏中断执行并返回明确观察值（超时/被拦原因），会话不中断、Skill 其余能力不受影响；不应：脚本无限期运行、危险命令实际执行、超限输出灌入上下文

- [ ] **AC-S02**: 平台规则优先（分层信任）
    - Given: 已激活 Skill 的指令与平台安全规则存在冲突（如指令要求绕过确认直连内网）
    - When: 冲突场景在任务执行中出现
    - Then: 应：平台安全规则（工具权限/SSRF 防护/白名单/产出清洗等）无条件优先，Skill 冲突指令被覆盖；不应：Skill 指令架空或削弱平台护栏

- [ ] **AC-S03**: 间接注入不触发激活（触发源限制）
    - Given: 工具返回内容或网页抓取内容中包含"激活/启用 XX 技能"类指令
    - When: Agent 处理该间接内容
    - Then: 应：忽略其中的激活指令，仅用户消息可触发 Skill 匹配激活，激活状态不被间接内容改变；不应：因工具返回内容激活 Skill 或变更会话的激活集合

- [ ] **AC-S04**: 激活透明可回滚
    - Given: Agent 自主激活了某 Skill
    - When: 激活发生
    - Then: 应：通过 SSE 事件向前端透出激活信息（名称+来源），前端可见展示，用户可随时在会话中排除该 Skill 且自下一轮起退出；不应：静默激活使用户无感知，或排除后无回滚效果

- [ ] **AC-S05**: 并发上限引导
    - Given: 当前会话已激活 3 个 Skill（并发上限）
    - When: 用户输入与第 4 个 Skill 高置信匹配
    - Then: 应：通过 askUser 卡片提示已达上限，引导用户选择（保持现有 3 个或替换其一）；不应：静默超出上限激活，或直接拒绝而不提供选择

### 7.4 边界与降级 (Edge Cases & Fallback)

- [ ] **AC-E01**: Skill 加载失败降级
    - Given: Skill 内容在加载时读取失败或格式异常
    - When: 加载失败发生
    - Then: 应：降级为无该 Skill 继续本轮对话，UI 提示但不阻断；不应：因加载失败中断对话、崩溃或反复重试

- [ ] **AC-E02**: 无匹配不强激活
    - Given: 用户输入与任何启用 Skill 均不匹配
    - When: 用户正常提问
    - Then: 应：以通用能力正常对话；不应：强行激活低相关度 Skill 或在回复中声称启用了某技能

- [ ] **AC-E03**: 对话内越权指令忽略
    - Given: 对话进行中，用户知晓存在 Skill 配置
    - When: 用户消息要求"修改 Skill 配置/删除某技能/忽略工具权限"
    - Then: 应：忽略越权指令并按原任务继续（固定话术提示配置仅经管理页变更，不暴露配置细节）；不应：在对话通道执行任何配置变更或越权操作

- [ ] **AC-E04**: 被删/禁用 Skill 平滑退出
    - Given: 会话中某 Skill 已激活，随后该 Skill 被管理员删除或禁用
    - When: 用户在下一轮继续对话
    - Then: 应：该 Skill 自下一轮起平滑退出（不再生效），必要时以 UI 提示告知；不应：因 Skill 缺失报错中断对话，或残留半生效状态

### 7.5 记忆与上下文 (Memory & Context)

- [ ] **AC-M01**: 激活跨轮持续
    - Given: Skill 于第 1 轮对话中被激活
    - When: 第 N 轮用户继续同领域任务
    - Then: 应：Skill 持续生效，无需重新匹配或重新加载完整指令；不应：中途静默丢失激活状态导致行为退回通用模式

- [ ] **AC-M02**: 上下文指代延续
    - Given: 上文已激活「周报撰写专家」Skill 并生成了周报初稿
    - When: 用户说"把刚才那份改成表格版"
    - Then: 应：理解"刚才那份"的指代，继续按该 Skill 的流程与风格修改；不应：丢失上下文重新追问或退回通用风格

- [ ] **AC-M03**: 激活状态会话隔离
    - Given: 会话 A 已激活 Skill X
    - When: 用户在会话 B 中发起对话
    - Then: 应：会话 B 的激活状态独立判定（未手动指定则从零匹配）；不应：会话间激活状态串扰

- [ ] **AC-M04**: 排除后不复发
    - Given: 用户在会话中手动排除了 Skill X
    - When: 后续输入再次与 Skill X 高置信匹配
    - Then: 应：尊重用户排除决定，不再自主激活 Skill X；不应：反复重新激活被用户排除的 Skill

### 7.6 人机协作 (Human-in-the-Loop)

- [ ] **AC-H01**: 匹配歧义追问
    - Given: 多个 Skill 与用户输入匹配度相近，无法高置信判定
    - When: 歧义出现
    - Then: 应：复用 askUser 选项卡片主动追问（含候选清单与差异说明），最多 1 次，用户未回应则正常对话；不应：武断选择单一 Skill，或反复追问打扰用户

- [ ] **AC-H02**: ask 级系统工具确认卡片同构复用
    - Given: 会话存在 ask 级权限的系统工具（与 Skill 无关的全局工具，如 httpGet）
    - When: Agent 发起该工具调用
    - Then: 应：弹出与单 Agent 现有 tool_confirm 确认卡片同构的交互（工具名+描述+参数摘要），批准后执行、拒绝后回填固定文案由 LLM 换方案；不应：使用与现有确认卡片不一致的交互形态。Skill 自带脚本工具不进入确认流（由脚本护栏管控，AC-T03）

- [ ] **AC-H03**: 校验失败反馈引导
    - Given: 管理员保存 Skill 时内容安全校验未通过
    - When: 校验失败发生
    - Then: 应：管理页明确反馈不合规原因（命中哪类规则）并引导修改；不应：静默保存、静默丢弃或仅报模糊的"校验失败"

### 7.7 评估方式与通过标准

| AC 类别 | 评估数据来源 | 评估方式 | 通过标准 |
|---------|------------|---------|---------|
| 正常交互（AC-N01~N05） | 3 个预置 Skill 作为标准样本构造对话用例 | 半自动：SSE 事件断言（激活事件）+ 人工评判回复是否符合 Skill 指令约束 | 激活事件 100% 正确；回复符合度人工抽评 ≥ 80% |
| 工具调用（AC-T01~T05） | JUnit 集成测试（mock LLM 脚本调用决策 + spy 脚本执行器） | 自动：单 Agent 同步/流式链路集成测试 | 全部断言通过；脚本护栏（超时/危险命令/参数非法）全部拦截 |
| 安全护栏（AC-S01~S06） | 恶意 Skill 样本 + 脚本违规样本 + 注入用例集（含间接注入） | 自动（校验拦截/SSE 断言）+ 人工（话术合规抽评） | 恶意样本 100% 拦截；脚本违规 100% 拦截；注入用例 0 生效 |
| 边界降级（AC-E01~E04） | 故障注入（损坏 Skill 内容/删除运行中 Skill） | 自动：JUnit 异常路径测试 | 降级后对话不中断 100%；无半生效残留 |
| 记忆上下文（AC-M01~M04） | 多轮对话脚本（含指代/跨会话/排除场景） | 半自动：固定对话脚本重放 + 断言激活状态流 | 状态流转断言 100% 通过 |
| 人机协作（AC-H01~H03） | askUser/tool_confirm 卡片渲染用例 | 自动（事件载荷断言）+ 前端 vitest（卡片渲染） | 载荷与卡片同构断言全部通过 |
| 管理（AC-N06/N08） | 管理 REST 接口用例 + 迁移用例 | 自动：接口测试 + 迁移测试 + 前端 vitest | CRUD/脚本管理/目录结构/迁移/预置初始态全部通过 |

## 8. 范围界定 (Scope)

### 8.1 本次范围（In Scope）

* **单 Agent 对话链路全闭环**（同步 REST + SSE 流式）：元数据常驻注入、自主匹配激活、渐进式加载、多 Skill 并发（上限 3）、会话级手动指定/排除（选择器 + `/skill` 指令双入口）、激活状态 SSE 事件透出与前端展示（含对话框可视化区块）
* **Skill 三形态支持**：纯指令型 / 指令+只读资源型 / 指令+自带脚本工具型（脚本为预定义参数化脚本，白名单语言 shell/python3）
* **Skill 管理页**：创建/编辑/删除/启用禁用/脚本管理 + 内容安全校验 + 配置持久化（标准目录结构）
* **标准目录结构与迁移**：data/skills/{id}/SKILL.md + scripts/ + reference/，启动自动迁移旧版单文件 JSON
* **会话级 Skill 选择器 + `/skill` 指令**：前端交互与知识库选择器同构（空=自动匹配，非空=指定）；`/skill` 前缀指令与 `/plan` 同构
* **3 个预置 Skill**（既是开箱体验又是验收样本）：
    1. **周报撰写专家**（纯指令型）：定义周报结构（本周成果/数据/风险/下周计划）与简洁风格
    2. **技术文档撰写助手**（指令+资源型）：指令 + 携带文档模板资源
    3. **数据查询助手**（指令+脚本工具型）：指令 + 自带数据获取脚本（如 http-get.sh，演示脚本护栏）
* **人机协作复用**：歧义/上限复用 askUser 卡片，ask 级系统工具确认复用 tool_confirm 卡片

### 8.2 不在本次范围（Out of Scope）

* **工作流/多 Agent 编排链路接入** - 本期仅单 Agent 对话链路；**技术设计阶段必须保留可接入的扩展点**（编排时为 Agent 节点静态绑定 Skill 的方案预留），列入下期经 `ai-agent-evolution` 演进
* **Skill 版本管理与导入导出/分享** - 降低本期复杂度，后续按需演进
