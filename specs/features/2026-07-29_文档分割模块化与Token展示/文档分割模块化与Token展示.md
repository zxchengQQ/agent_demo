# 功能需求说明书 (Feature Requirements Document)

## 1. 背景与价值 (Context & Value)

*   **背景**: 当前项目的 RAG 知识库模块中，文件解析和分割逻辑内嵌在 `agent-demo-rag` 模块的 `DocumentService` 和 `DocumentLoader` 中。所有文件类型（txt/md/pdf）共用同一套通用递归分割策略（`DocumentSplitters.recursive`），无法针对不同文件类型的结构特征进行语义感知分割，导致检索精度不够理想。同时，前端对话页面缺乏 Token 消耗可视化，用户无法感知会话的资源消耗量。
*   **目标**: 将文件解析和分割逻辑抽取为独立 Maven 模块，为每种文件类型实现专属的结构感知分割策略，支持按文件类型独立配置分割参数，并在对话页面实时展示会话级 Token 消耗量。
*   **关联**: 关联 RAG 知识库问答模块迭代、前端对话模块增强。

## 2. 功能范围 (Scope)

### 2.1 本次范围（In Scope）

*   新建独立 Maven 模块，将文件解析（DocumentLoader）和分割逻辑从 RAG 模块抽取
*   为 Markdown 文件实现标题层级感知 + 代码块/表格原子单元保护的专属分割策略
*   为 PDF 文件实现页面边界感知 + 段落递归组合的专属分割策略
*   为 TXT 文件实现段落->句子->行->字符多级优先级递归分割策略
*   超大语义单元通过多级优先级级联切分处理（段落->句子->行->Token滑动窗口）
*   第一轮分割后对过短分块执行合并后处理，避免 chunk 太小太碎（CR-001 新增）
*   每种文件类型可独立配置最小分块大小 minSize，低于此值的分块触发合并（CR-001 新增）
*   专属分割器执行失败时自动回退到通用递归分割器
*   在 application.yml 中按文件类型独立配置分割参数（size + overlap）
*   后端从 LLM API 响应中提取真实 Token 用量并通过 SSE 事件推送给前端
*   前端在输入框区域展示当前会话累计 Token 消耗量
*   LLM API 不返回 Token 用量时，使用本地 Tokenizer 估算并标记"估算值"

### 2.2 不在本次范围（Out of Scope）

*   新增 Word/Excel/PPT 等新文件格式支持 - 下一期考虑
*   前端可视化分割配置界面 - 当前仅通过配置文件方式
*   知识库级别的分割策略配置 - 复杂度高，暂不考虑
*   语义分块（基于 Embedding 的分块策略） - 计算成本高，暂不引入
*   跨会话 Token 消耗统计/对比 - 当前仅支持会话级
*   已有文档的重新分割 - 不影响已处理文档，仅对新上传文档生效
*   图片原图向量化（多模态 Embedding） - CR-002 采用视觉模型生成描述+文本向量化方案，不直接对图片像素向量化

## 3. 用户角色 (Actors)

*   **学习者/开发者**: 上传文档到知识库，使用专属分割策略提升检索质量；在对话页面查看 Token 消耗量
*   **运维者**: 通过 application.yml 配置不同文件类型的分割参数

## 5. 详细需求与流程 (Detailed Requirements)

### 5.1 核心流程

#### 5.1.1 文档解析与分割流程

1. 用户上传文档到知识库
2. 系统调用新模块的 DocumentLoader 解析文件，提取文本内容
3. 系统根据文件扩展名选择对应的专属分割器（MarkdownSplitter / PdfSplitter / TxtSplitter）
4. 专属分割器按各自策略执行结构感知分割：
   - **Markdown**：按标题层级分割，代码块/表格作为原子单元保护，超大段落多级级联切分
   - **PDF**：按页面边界分割，保留页码元数据，单页超限时按段落递归切分
   - **TXT**：按段落->句子->行->字符多级优先级递归切分
5. 超大语义单元通过多级优先级级联切分（段落->句子->行->Token滑动窗口）
6. 第一轮分割完成后，对过短分块执行合并后处理：低于 minSize 的分块与同组（同页/同节）相邻分块合并，合并后不超过 maxSize（CR-001 新增）
7. 分割失败时自动回退到通用递归分割器（DocumentSplitters.recursive）
8. 为每个分块添加来源元数据（knowledgeBaseId、documentId、文件类型等）
9. **PDF 文档额外执行图片处理**：提取 PDF 中的图片保存到文件系统，调用视觉模型生成图片文本描述，将描述作为独立分块（metadata 标记 chunkType=image，含 imagePath）（CR-002 新增）
10. 分块结果（含文本分块和图片描述分块）交付给 RAG 模块进行向量化处理

#### 5.1.2 Token 消耗展示流程

1. 用户在对话页面发送消息
2. 后端调用 LLM API，收到响应后提取 Token 用量（输入Token/输出Token）
3. 若 API 响应包含 Token 用量，使用真实数据；若不包含，使用本地 Tokenizer 估算并标记
4. 后端在 SSE done 事件中携带 Token 消耗数据推送给前端
5. 前端更新当前会话的累计 Token 消耗量，展示在输入框区域
6. Token 累计值同步保存到 localStorage，页面刷新后可恢复

### 5.2 交互/界面规则 (UI/UX Rules)

*   Token 消耗量展示位置：对话输入框区域，始终可见
*   Token 消耗量在每轮对话结束时（收到 SSE done 事件）更新
*   当 Token 数据为估算值时，需展示"估算"标记以区分真实值
*   Token 消耗量格式：数字千分位展示（如 1,234 Tokens）
*   页面刷新后会话 Token 累计值从 localStorage 恢复

### 5.3 业务规则 (Business Rules)

*   分块大小的计量单位为 Token 数（非字符数），使用 LangChain4j 内置 Tokenizer 计算
*   每种文件类型可独立配置 size 和 overlap 参数
*   代码块和表格作为原子单元，分割时不被切断
*   超大语义单元依次尝试按段落->句子->行->Token滑动窗口逐级切分
*   第一轮分割后对过短分块执行合并后处理，低于 minSize 的分块与同组相邻分块合并，合并后不超过 maxSize（CR-001 新增）
*   合并时遵守结构边界约束：PDF 不跨页合并，Markdown 不跨标题节合并（CR-001 新增）
*   每种文件类型可独立配置 minSize 参数，默认为 size 的 50%（CR-001 新增）
*   专属分割器失败时自动回退到通用递归分割器，记录警告日志
*   空文件（解析后无文本内容）报错拒绝处理
*   分块元数据保留来源信息（knowledgeBaseId、documentId、文件类型、页码/标题层级等）
*   PDF 文档中的图片通过 PDFBox PDFRender 提取，保存为 PNG 文件到 `${rag.document.temp-dir}/images/{documentId}/` 目录（CR-002 新增）
*   图片文本描述由视觉模型（如 doubao-vision）生成，描述内容作为独立 TextSegment 向量化，metadata 标记 chunkType=image 并含 imagePath/imageDescription（CR-002 新增）
*   图片描述向量化复用现有文本 Embedding 模型，不引入多模态 Embedding 模型（CR-002 新增）
*   视觉模型调用失败时跳过该图片（不影响文档整体处理），记录 WARN 日志（CR-002 新增）

## 6. 验收标准 (Acceptance Criteria)

> **重要**：以下验收标准是后续技术方案、任务规划和 TDD 测试用例的直接依据。每条 AC 必须使用 Given-When-Then 格式，必须可被测试验证。

### 6.1 正常流程 (Happy Path)

- [ ] **AC-001**: 新建独立 Maven 模块抽取解析与分割逻辑
   - Given: 项目当前文件解析和分割逻辑内嵌在 agent-demo-rag 模块中
   - When: 新建独立 Maven 模块，将 DocumentLoader 和分割器抽取到新模块
   - Then: RAG 模块通过依赖新模块使用解析和分割能力，编译通过且现有功能不受影响

- [ ] **AC-002**: Markdown 文件按标题层级分割
   - Given: 用户上传一个包含多级标题（#/##/###）的 Markdown 文件
   - When: 系统对该文件执行分割处理
   - Then: 每个分块以标题为边界，分块内容包含所属标题及标题下内容，保留标题层级上下文

- [ ] **AC-003**: Markdown 代码块和表格作为原子单元不被切断
   - Given: 用户上传的 Markdown 文件包含代码块（```）或表格
   - When: 系统对该文件执行分割处理
   - Then: 代码块和表格作为不可分割的原子单元，不会被切断到两个分块中

- [ ] **AC-004**: PDF 文件按页面边界分割
   - Given: 用户上传一个多页 PDF 文件
   - When: 系统对该文件执行分割处理
   - Then: 每个分块以页面为边界，分块元数据中包含页码信息，不跨页拼接内容

- [ ] **AC-005**: PDF 单页内容超限时按段落递归切分
   - Given: 用户上传的 PDF 文件中某一页内容超过配置的最大分块大小
   - When: 系统对该页执行分割处理
   - Then: 该页内容按段落（换行符）递归切分为多个分块，每个分块不超过配置大小，页码元数据保留

- [ ] **AC-006**: TXT 文件按多级优先级递归切分
   - Given: 用户上传一个 TXT 纯文本文件
   - When: 系统对该文件执行分割处理
   - Then: 文本按段落（\n\n）->句子（。/!/?/.）->行（\n）->字符的优先级递归切分，优先保留高一级语义边界

- [ ] **AC-007**: 超大语义单元通过多级优先级级联切分
   - Given: 某个语义单元（如一个超长段落或超大代码块）超过配置的最大分块大小
   - When: 系统对该语义单元执行切分
   - Then: 依次尝试按段落->句子->行->Token滑动窗口（带overlap）逐级切分，直到每个分块不超过配置大小；切分后对过短分块执行合并后处理（CR-001 修改）

- [ ] **AC-008**: 每种文件类型独立配置分割参数
   - Given: 运维人员在 application.yml 中为不同文件类型配置不同的 size 和 overlap
   - When: 系统处理不同类型的文件
   - Then: 每种文件类型使用各自配置的 size 和 overlap 参数进行分割

- [ ] **AC-009**: 对话页面展示会话累计 Token 消耗量
   - Given: 用户在对话页面进行对话
   - When: 每轮对话结束（收到 SSE done 事件）
   - Then: 输入框区域更新展示当前会话的累计 Token 消耗总量

- [ ] **AC-010**: 后端从 LLM API 响应中提取真实 Token 用量并推送
   - Given: 用户发送一条对话消息
   - When: 后端收到 LLM API 的响应
   - Then: 后端从 API 响应中提取 Token 用量（输入Token/输出Token），通过 SSE 事件推送给前端

- [ ] **AC-019**: 分割后合并过短分块（CR-001 新增）
   - Given: 系统对文件执行第一轮分割后产生了多个分块，其中部分分块的 Token 数低于配置的 minSize
   - When: 系统对分割结果执行合并后处理
   - Then: 低于 minSize 的分块与同组（同页/同节/全局）相邻分块合并，合并后 Token 数不超过 maxSize，最终结果中不存在低于 minSize 的碎片块（最后一个分块除外）

### 6.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-011**: 空文件报错拒绝处理
   - Given: 用户上传一个解析后无任何文本内容的文件（如空白 PDF、空 TXT）
   - When: 系统尝试对该文件执行分割处理
   - Then: 系统报错拒绝处理，返回明确的错误提示"文件内容为空"，文档状态标记为处理失败

- [ ] **AC-012**: 专属分割器失败时自动回退通用分割
   - Given: 某种文件类型的专属分割器执行失败（如 Markdown 格式异常解析出错）
   - When: 分割过程中捕获到异常
   - Then: 系统自动回退到通用递归分割器（DocumentSplitters.recursive）进行分割，同时记录警告日志，文档处理不中断

- [ ] **AC-013**: PDF 加密文件处理失败的回退
   - Given: 用户上传一个加密的 PDF 文件
   - When: 系统尝试解析该 PDF
   - Then: PDF 解析失败触发回退机制，使用通用分割器处理可提取的文本内容；如完全无法提取则报错标记文档处理失败

- [ ] **AC-014**: LLM API 不返回 Token 用量时本地估算
   - Given: 火山引擎 Coding Plan API 响应中不包含 Token 用量数据
   - When: 后端检测到 API 响应无 Token 用量
   - Then: 后端使用本地 Tokenizer 估算输入和输出 Token 数，前端展示时标记为"估算值"

- [ ] **AC-015**: Token 消耗量页面刷新后保持
   - Given: 用户在对话过程中刷新页面
   - When: 页面重新加载
   - Then: 会话累计 Token 消耗量从 localStorage 中恢复，展示刷新前的累计值

- [ ] **AC-024**: 视觉模型调用失败时跳过图片不影响文档处理（CR-002 新增）
   - Given: PDF 文档包含图片，但视觉模型 API 不可用或调用超时
   - When: 系统处理该 PDF 文档
   - Then: 图片提取和文本分块正常完成，视觉模型失败的图片被跳过并记录 WARN 日志，文档状态为已完成（非失败），文本分块正常向量化入库

### 6.3 业务规则验证 (Business Rules)

- [ ] **AC-016**: 分块大小按 Token 数计算
   - Given: 系统配置了分块大小参数
   - When: 系统执行分割时
   - Then: 分块大小的计量单位为 Token 数（非字符数），使用 LangChain4j 内置 Tokenizer 计算

- [ ] **AC-017**: 分块元数据保留来源信息
   - Given: 文件被分割为多个分块
   - When: 分割完成
   - Then: 每个分块的元数据包含 knowledgeBaseId、documentId、文件类型、页码/标题层级等来源信息（适用时）

- [ ] **AC-018**: 新模块的模块依赖关系正确
   - Given: 新模块抽取完成
   - When: 编译整个项目
   - Then: RAG 模块依赖新模块，新模块依赖 common 模块，编译顺序正确，无循环依赖

- [ ] **AC-020**: 每种文件类型独立配置 minSize 参数（CR-001 新增）
   - Given: 运维人员在 application.yml 中为不同文件类型配置不同的 minSize
   - When: 系统对不同类型的文件执行分割后合并
   - Then: 每种文件类型使用各自配置的 minSize 参数作为合并阈值，未配置时默认为 size 的 50%

- [ ] **AC-021**: PDF 文档中的图片被提取并保存（CR-002 新增）
   - Given: 用户上传一个包含图片的多页 PDF 文件
   - When: 系统解析该 PDF 文件
   - Then: PDF 中的图片被提取并保存为 PNG 文件到 `${rag.document.temp-dir}/images/{documentId}/` 目录，每张图片的元数据记录所属页码和图片索引

- [ ] **AC-022**: 图片通过视觉模型生成文本描述（CR-002 新增）
   - Given: 系统已提取 PDF 中的图片
   - When: 系统对每张图片调用视觉模型生成描述
   - Then: 视觉模型返回图片的文本描述，描述内容涵盖图片中的可见信息（如文字、图表内容、示意图含义）；视觉模型调用失败时跳过该图片，不影响文档整体处理

- [ ] **AC-023**: 图片描述向量化并作为独立分块支持检索（CR-002 新增）
   - Given: 系统已获取图片的文本描述
   - When: 系统执行向量化处理
   - Then: 图片描述作为独立 TextSegment 通过现有文本 Embedding 模型向量化并存入向量存储，metadata 标记 chunkType=image 并包含 imagePath、imageDescription、pageNumber；检索时可通过图片描述内容命中并返回图片路径引用

## 附录：调研依据

### 文档分割策略调研结论

| 文件类型 | 推荐方案 | 调研依据 |
|---------|---------|---------|
| Markdown | 结构感知切分：按标题层级(H1/H2/H3)分割 + 代码块/表格作为原子单元 + 超大段落多级级联切分 | LangChain `MarkdownHeaderTextSplitter`；LangChain4j PR #4276 `MarkdownSectionSplitter`（commonmark-java）；MDKeyChunker 论文(2026.03) |
| PDF | 页面边界感知 + 段落递归组合：保留页码元数据，单页超限时按段落递归切分 | 结构感知切分是 PDF 检索精度提升的核心策略（Atlan 2026 指南）；当前已有 tabula 表格提取基础 |
| TXT | 增强递归切分：定制分隔符优先级（段落->句子->行->字符） | 递归切分是工业界通用兜底策略（LangChain 默认实现） |

### 超大块处理调研结论

多级优先级级联切分（Adaptive Chunking 论文 2026.03 + LightRAG 实践）：
1. 第一级：按自然边界（段落 `\n\n`）切分
2. 第二级：仍超限则按句子（`。`/`!`/`?`/`. `）切分
3. 第三级：仍超限则按行（`\n`）切分
4. 第四级：最终兜底按 Token 数强制滑动窗口切分（带 overlap）

### Token 消耗统计调研结论

项目使用火山引擎 Coding Plan（按次计费），API 响应中可能不包含 Token 用量数据。方案：
1. 优先从 API 响应中提取真实 Token 用量
2. 若 API 不返回，使用本地 Tokenizer 估算并标记"估算值"
