> **文档定位**：本需求为横切现有对话链路的**可观测性平台接入**（LLM 调用与工具调用追踪），非新增业务 Agent，不改变 Agent 对外语义、自主性级别与工具权限体系。可观测子系统自身的行为风险按 **L4 类不可回滚风险**归类，以三重护栏对冲（见 3.3）。
> **关联文档**：`specs/技术架构文档-TOGAF.md` §5.4（LangSmith 规划项，本期为该长期规划项提前实施）、`specs/features/20260826_tool-output-sanitization/`（工具产出安全清洗，脱敏思想复用）、`specs/features/20260828_agent-context-engineering/agent-context-engineering_代码审查报告.md` §5-1（真实模型行为评估缺口的出处）、`KNOWLEDGE_BASE.md` §6（核心开发范式）

## 1. 背景与价值 (Context & Value)

* **背景**:
    1. **可观测性现状薄弱**：项目仅有 Logback 结构化日志 + `TraceIdInterceptor`（MDC traceId 串联日志），无 LLM 调用链路可视化能力，调试 Agent 行为只能翻日志；
    2. **评估能力缺口**：现有评估基建为 JUnit 静态断言 + 模板扫描，缺「真实模型行为评估」能力（agent-context-engineering 代码审查报告明确指出：真实模型工具选择行为验证因无评估环境被推迟到线上联调）；
    3. **路线图对齐**：TOGAF 技术架构 §5.4 已将「LangSmith（规划中）| LangChain4j 集成 | 可视化 Agent 执行链路」列为可观测性架构组成部分（原规划 2027-03，本期提前实施）。
* **需求澄清阶段调研结论**（已核实，作为本期方案依据）：
    1. **LangSmith 官方云（SaaS）可用**：免费层可用，数据保留 180 天；数据出境至 LangChain 托管服务器，国内网络直连可达性需实施时验证；
    2. **LangSmith BYOC/自托管不可行**：仅企业版（需联系销售），学习项目无获取途径；
    3. **LangChain4j 1.17.2 无官方 LangSmith/Langfuse 集成模块**（Maven Central `dev.langchain4j` 组核实无此 artifact）；官方可观测路径为 `ChatModelListener` / AiService 事件监听 + `langchain4j-observation`（Micrometer Observation API，可导出 OTLP traces）；
    4. **LangSmith 官方支持 OpenTelemetry OTLP 上报**（`https://api.smith.langchain.com/otel/`）--OTel 是 Java 技术栈接入 LangSmith 的标准路径；
    5. **开源自托管替代存在**：Langfuse（MIT 开源，Docker Compose 官方自托管，支持 OTLP，功能含追踪/评估/数据脱敏）--本需求仅做架构预留，不实际切换。
* **目标**: Agent 的 LLM 调用与工具调用全链路在 LangSmith 平台可视化（按会话聚合成 thread），具备 Token 用量统计，并打通「trace -> 数据集 -> 评估实验」最小闭环--全程对终端用户零感知、对主流程零影响。
* **关联**: 平台能力域第 12 项（可观测性）；技术架构文档 §5.4 长期规划项；评估闭环补齐 agent-context-engineering 遗留的 EDD 缺口。

## 2. Agent 角色定义 (Agent Persona)

### 2.1 身份定位
* **角色名称**: LangSmith 可观测子系统（langsmith-observability）
* **角色类型**: 平台基础设施型（被动采集组件；非对话型/任务型/工作流型 Agent，不与终端用户交互）
* **身份描述**: 挂载在对话链路两侧的旁路采集器：向上监听 LLM 调用与工具调用事件，向下经 OpenTelemetry 统一标准将 trace 上报 LangSmith 云。只采集、只转发，不做任何业务决策。
* **核心价值**: ①可视化 Agent 执行链路（ReAct 循环逐轮展开）②真实模型行为评估最小闭环 ③Token 用量按模型/会话/时间聚合统计。

### 2.2 目标用户与场景
* **目标用户**: 开发者（调试 Agent 行为、定位工具选择问题）、学习者（直观理解 ReAct 执行过程）、运维者（Token 消耗监控）。
* **使用场景**: 后台隐式生效--用户正常对话，开发者在 LangSmith 控制台查看该次对话的完整执行链路、Token 消耗与评估实验结果。
* **交互风格**: 对终端用户完全透明（无任何新增交互）；LangSmith UI 为面向开发者的专业观测界面。

## 3. 能力边界与自主性 (Capability & Autonomy)

### 3.1 能力清单（In Scope）
1. **LLM 调用追踪**：prompt（消息列表）、模型名、请求参数、回复、Token 用量（输入/输出）、耗时、成功/失败；
2. **工具调用追踪**：工具名、入参、出参、耗时、执行结果状态（成功/失败含异常信息）；
3. **会话关联**：trace 按 sessionId 聚合为同一 thread，多轮对话连续可览；
4. **日志互查**：trace 元数据携带既有 `TraceIdInterceptor` 生成的 traceId，云端 trace 与本地日志双向定位；
5. **基础脱敏**：密钥类模式（sk-xxx、Bearer 令牌值、已配置 API Key 环境变量值等）上报前脱敏；
6. **Token 用量统计**：LangSmith 自动从 LLM 响应 metadata 采集，按模型/会话/时间聚合展示；
7. **评估最小闭环**：真实对话 trace 转为评估数据集，跑通一次评估实验（如工具选择正确性）。

### 3.2 能力禁区（Out of Scope）
* **不采集** RAG 检索、记忆压缩、工作流编排、MCP 通信、Skill 激活事件--本期观察空间限定为 LLM+工具两类（后续经 ai-agent-evolution 增量扩展）；
* **不做**成本金额换算--方舟/百炼模型不在 LangSmith 价格表内，需维护自定义价格映射，收益低于维护成本（仅 Token 数量统计）；
* **不做**用户级前端开关--学习项目无多租户诉求，系统级配置即达（追踪默认关闭）；
* **不做**采样率控制--学习项目流量小，全量采集，采样能力无意义；
* **不允许**上报失败影响对话主流程--追踪子系统任何故障不得传导至用户侧（双向约束见 AC-S04/E01）；
* **不允许** LangSmith API Key 出现在代码、日志、前端、SSE 事件任何一处。

### 3.3 自主性级别
* **级别（风险归类）**: **L4 类 - 自主执行不可回滚**（数据一旦上报至 LangSmith 云不可真正撤回--平台删除 ≠ 保证未被复制/访问）。
* **映射说明**: 本子系统非业务 Agent，L1-L5 逐条对照如下：配置 Key 后每轮对话 trace **自动上报、无逐次确认**（非 L2）；上报结果**不可回滚**（非 L3）。即逐次动作自主 + 结果不可逆 = L4 风险特征。注意这是**风险归类**而非授予执行权限。
* **三重护栏对冲**（L4 规则要求「额外安全约束」的落地，把 L4 风险向 L2 方向压）:
    1. **默认关闭**（AC-S02）--配置 `LANGSMITH_API_KEY` 是唯一的一次性人工授权，此后系统才获得自动上报权，等价于把 L2 确认门禁前置到系统边界；
    2. **基础脱敏**（AC-S01）--压低每次不可逆上报的伤害上限，密钥不出 payload；
    3. **静默降级**（AC-S04）--保证护栏层自身不引入新风险，任何异常不伤害主流程。
* **人类介入点**: ①Key 配置授权（部署时）②评估实验设计与未达标结果复核（运行期，AC-H01）③敏感数据泄漏处置（应急，AC-H02）。

### 3.4 知识边界
* 子系统无自有知识、无生成行为，仅采集与转发 trace 数据；不基于 trace 内容做任何自动决策（评估实验结果仅作为人工分析输入）。

## 4. 工具与动作空间 (Tools & Action Space)

> **映射说明**：本节将模板的「工具」概念映射为可观测子系统的**采集点与上报通道**。Agent 对话链路的业务工具集本次零变更。

### 4.1 采集点与上报通道清单

| 名称 | 用途 | 输入 | 输出 | 副作用 | 权限 | 限制 | 常见失败场景 |
|------|------|------|------|--------|------|------|-------------|
| LLM 调用监听 | 采集每次 LLM 请求/响应 | 请求上下文（消息/模型名/参数）、响应上下文（回复/Token 用量/耗时/错误） | LLM span | 无（只读旁路采集） | 只读 | 未配置 Key 时不挂载 | 监听器处理异常 |
| 工具调用监听 | 采集每次工具执行 | 工具执行上下文（工具名/入参/出参/耗时/异常） | 工具 span | 无（只读旁路采集） | 只读 | 未配置 Key 时不挂载 | 监听器处理异常 |
| OTLP 上报通道 | 将 span 数据上报 LangSmith 云 | 脱敏并截断后的 span 批次 | 网络请求（OTLP 协议） | **有**（数据出境，不可回滚） | 读写（外部系统） | 异步上报不阻塞主流程；上报前置脱敏；超长字段截断 | 超时/401/5xx/网络不可达 |
| 评估实验通道 | trace 转数据集、发起评估实验 | trace/数据集/评估器配置 | 评估结果（LangSmith 平台内） | 无（平台内操作） | 读写（LangSmith 平台） | 手动发起，不自动运行 | 数据集为空/评估器配置错误 |

### 4.2 采集点关系
* **依赖关系**: OTLP 上报通道依赖两类监听器产出的 span；评估实验通道依赖已上报的 trace；
* **顺序关联**: 同一次对话内，LLM span 与工具 span 按真实执行顺序串联（ReAct 循环完整性，AC-T01）；
* **互斥关系**: 无（全部旁路，与业务执行互不干扰）。

### 4.3 采集策略
* 未配置 `LANGSMITH_API_KEY` -> 不挂载任何监听器，子系统整体不启动（零开销）；
* 配置后全量采集（无采样率），异步上报。

### 4.4 观察空间 (Observation Space)
> 子系统的能力 = 观察空间 × 动作空间。观察空间界定子系统能采集哪些信息；AC 的预期行为只能基于可采集信息。

* **可感知信息源清单**：

    | 信息源 | 是否可见 | 采集方式 |
    |--------|---------|---------|
    | LLM 请求（消息列表、模型名、请求参数） | 是 | LLM 调用监听 |
    | LLM 响应（回复、Token 用量、耗时、finish 原因、错误） | 是 | LLM 调用监听 |
    | 工具调用事件（工具名、入参、出参、耗时、成败、异常） | 是 | 工具调用监听 |
    | 会话标识（sessionId） | 是 | 采集元数据（thread 关联） |
    | 请求标识（traceId，TraceIdInterceptor 生成） | 是 | 采集元数据（日志互查） |
    | 会话级模型选择（当轮实际 modelId） | 是 | LLM span 属性 |
    | 系统密钥明文（ARK_API_KEY / LANGSMITH_API_KEY 等值） | **否（脱敏后）** | 脱敏规则前置处理 |
* **不可见信息声明**：RAG 检索内部过程、记忆压缩过程、工作流编排状态、MCP 通信细节、Skill 激活事件、其他系统内部状态--本期不采集，**任何 AC 不得预期这些信息出现在 trace 中**。

## 5. 推理流程与记忆策略 (Reasoning & Memory)

> **映射说明**：子系统无推理能力、不与用户交互，本节模板内容映射为**采集结构与会话关联策略**。

### 5.1 采集结构（对应「推理模式」）
* **trace 组织**: 用户一次消息触发的完整对话处理 = 一个根 trace；其中的每次 LLM 调用、每次工具调用 = 子 span；
* **ReAct 完整性**: 一次多轮 ReAct 循环（LLM->工具->LLM->...->最终回复）的全部 span 归属同一 trace，顺序真实反映执行序（AC-T01）。

### 5.2 澄清策略
* 不适用（子系统不与用户交互，无澄清场景）。

### 5.3 短期记忆（对话内）
* 映射为单次对话内 trace 结构完整性：失败调用也生成 span（含错误信息），不因失败丢失记录（AC-T02/T03）。

### 5.4 长期记忆（跨会话/跨轮次）
* **thread 聚合**: 同一 sessionId 的多轮对话 trace 聚合为同一 thread（AC-N02）；
* **评估数据沉淀**: 真实对话 trace 转为评估数据集长期保留（LangSmith 数据集不受 trace 保留期限制）。

## 6. 护栏安全与降级策略 (Guardrails & Fallback)

### 6.1 内容安全规则
* 不适用（子系统无内容生成行为，纯采集转发）。

### 6.2 幻觉防护
* 不适用（无生成行为）；评估实验结果仅作为人工分析输入，系统不基于评估结果做自动决策或自动变更。

### 6.3 敏感信息处理（核心护栏）
* **采集侧（输入侧）**: 上报前对密钥类模式执行脱敏：`sk-` 前缀密钥、`Bearer` 令牌值、已配置 API Key 环境变量（ARK_API_KEY、LANGSMITH_API_KEY 等）的实际值；
* **上报侧（输出侧）**: 脱敏后的 payload 才允许进入上报通道；**任何密钥明文不得出现在上报数据中**（双向约束见 AC-S01）；
* **脱敏规则边界**: 用户对话内容不脱敏（学习项目无真实敏感数据，经用户确认）；工具返回的文件/网页内容仅做密钥模式脱敏，不做内容摘要化（深度脱敏为后续演进项）。

### 6.4 工具失败降级

| 采集点/通道 | 失败场景 | 降级策略 | 是否转人工 |
|------|---------|---------|-----------|
| OTLP 上报通道 | 超时/401/5xx/网络不可达 | WARN 日志（含失败原因摘要，不含 Key），有限重试后放弃本次上报；**主流程不受任何影响** | 否（连续失败观察日志即可） |
| LLM/工具监听器 | 监听处理异常 | 跳过该条 span 采集，WARN 日志，主流程继续 | 否 |
| 脱敏处理 | 规则执行异常 | 保守策略：该字段整段替换为脱敏占位（宁误杀不放过），WARN 日志 | 否 |
| 超长内容 | 单字段超过阈值 | 截断至阈值并附加截断标识，上报继续 | 否 |
| 评估实验通道 | 数据集为空/评估器配置错误 | 实验失败提示，不影响任何线上行为 | 人工介入排查（AC-H01） |

### 6.5 人机协作机制
* **升级条件**: ①评估实验结果存在未达标项（需人工复核是模型行为问题还是数据问题）②发现敏感数据漏脱敏已上报（应急处置）；
* **升级方式**: ①经 LangSmith UI 按「评估结果 -> 原始 trace」链路人工排查 ②泄漏场景按文档化处置流程执行；
* **交接信息**: traceId/sessionId（定位本地日志与云端 trace）、评估结果与 trace 的关联标识。

### 6.6 提示注入防护
* **攻击面分析**: trace 中记录的工具返回内容可能包含恶意注入指令（沿用 tool-output-sanitization 的既有威胁模型）；
* **处理策略**: trace 数据仅作为**数据**记录与上报；OpenTelemetry span 属性无执行面，**系统不执行工具返回内容中的任何指令**（AC-S05，既有注入防线零回归）。

### 6.7 权限与身份校验
* **Key 管理**: `LANGSMITH_API_KEY` 仅经环境变量注入（沿用 ARK_API_KEY 先例），禁止硬编码、禁止出现在日志/前端/SSE 事件（AC-S03）；
* **身份模型**: 应用级 Key（非用户级），演示项目单租户无用户鉴权体系，与现状一致；
* **数据隔离**: trace 含 sessionId（会话标识）但不含用户身份敏感字段；LangSmith 平台侧访问控制由账号体系承担。

## 7. 验收标准 (Acceptance Criteria)

> 以下验收标准是后续技术方案与评估测试的直接依据。每条 AC 使用 Given-When-Then 格式，Given 描述上下文/状态，When 描述触发条件，Then 描述预期行为（含双向约束）。AI Agent 的 AC 关注**行为约束**而非精确输出。

### 7.1 正常交互流程 (Normal Interaction)

- [ ] **AC-N01**: 含工具调用的对话完整上报
    - Given: 已配置 Key 且追踪启用
    - When: 用户发起一次含工具调用的对话
    - Then: 应：LangSmith 平台可见该次调用的完整 trace（含 LLM span 与工具 span），span 时间线反映真实执行顺序；不应：出现只含 LLM 调用而缺失工具调用的不完整 trace

- [ ] **AC-N02**: 会话 thread 聚合
    - Given: 已配置 Key
    - When: 同一会话进行多轮对话
    - Then: 应：各轮 trace 按 sessionId 聚合为同一 thread（会话连续性可览）；不应：各轮 trace 散落为无关联的独立记录

- [ ] **AC-N03**: LLM span 必备字段
    - Given: LLM 调用发生
    - When: 在 LangSmith 查看对应 span
    - Then: 应：包含模型名、输入消息、输出回复、Token 用量（输入/输出）四类必备信息；不应：缺失任一项（缺失视为不合格）

- [ ] **AC-N04**: 工具 span 必备字段
    - Given: 工具调用发生
    - When: 在 LangSmith 查看对应 span
    - Then: 应：包含工具名、入参、出参、耗时、执行结果状态（成功/失败）五类必备信息；不应：缺失任一项

### 7.2 采集行为 (Tool Selection & Invocation)

- [ ] **AC-T01**: ReAct 循环链路完整
    - Given: 一次对话触发 ReAct 多轮循环（LLM->工具->LLM->最终回复）
    - When: 查看该次对话 trace
    - Then: 应：全部 LLM 调用与工具调用按执行顺序完整串联，无缺失环节；不应：循环中间任何一轮的 LLM 或工具调用在 trace 中丢失

- [ ] **AC-T02**: LLM 失败记录不丢失
    - Given: 追踪启用状态下某次 LLM 调用报错
    - When: 该调用结束
    - Then: 应：错误信息被记录在对应 span 中（失败 span 正常上报）；不应：因调用失败导致该次记录丢失

- [ ] **AC-T03**: 工具失败记录不丢失
    - Given: 某工具执行抛异常
    - When: 在 LangSmith 查看该工具 span
    - Then: 应：失败工具 span 记录异常信息与耗时，且该失败不中断本次 trace 的其余部分上报；不应：因工具失败丢弃整条 trace

### 7.3 安全与护栏 (Safety & Guardrails)

- [ ] **AC-S01**: 密钥脱敏上报
    - Given: 用户输入或工具返回中包含密钥类内容（如 `sk-` 前缀密钥、Bearer 令牌、已配置 API Key 环境变量的值）
    - When: 含该内容的 trace 上报
    - Then: 应：LangSmith 侧数据中该内容已被脱敏替换；不应：任何原始密钥明文出现在上报数据、平台界面或日志中

- [ ] **AC-S02**: 默认关闭零外联
    - Given: 未配置 `LANGSMITH_API_KEY`
    - When: 应用启动并正常对话
    - Then: 应：追踪子系统不启动、不发出任何对外网络请求、对话行为与关闭前完全一致（零开销）；不应：出现残留监听、外联尝试或启动报错

- [ ] **AC-S03**: Key 不泄漏
    - Given: 追踪已配置启用
    - When: 检查应用日志、前端页面、SSE 事件、trace 数据
    - Then: 应：LangSmith API Key 仅存在于环境变量中；不应：Key 明文出现在任何上述输出中

- [ ] **AC-S04**: 上报失败静默降级
    - Given: LangSmith 服务不可达或返回错误（超时/401/5xx）
    - When: 用户对话进行中
    - Then: 应：对话正常完成，后台记录 WARN 日志（含失败原因摘要、不含 Key），有限重试后放弃；不应：用户感知到任何异常、主流程出现报错或中断

- [ ] **AC-S05**: trace 数据无执行面
    - Given: 工具返回内容中含恶意注入指令（如"忽略此前指令"类文本）
    - When: 该内容进入 trace 并上报
    - Then: 应：其仅作为数据被记录与上报；不应：系统执行其中任何指令（采集链路不存在基于 trace 内容的执行路径）

### 7.4 边界与降级 (Edge Cases & Fallback)

- [ ] **AC-E01**: 上报不阻塞主流程
    - Given: 上报链路阻塞或缓慢（如网络劣化）
    - When: 对话进行中
    - Then: 应：用户侧响应速度无可感知劣化（上报异步执行，主流程不等待上报完成）；不应：对话响应被上报耗时拖慢

- [ ] **AC-E02**: 超长内容截断
    - Given: 单条工具返回内容超大（超过阈值）
    - When: 该内容进入上报
    - Then: 应：超长字段按阈值截断并附加截断标识后上报；不应：因单 span 过大导致上报失败或平台展示异常

- [ ] **AC-E03**: 启停行为确定性
    - Given: 追踪配置被启用或禁用
    - When: 应用重启
    - Then: 应：子系统行为与新配置一致（启用即采集上报、禁用即零外联），无需残留状态清理或手动干预；不应：存在与配置不符的中间态

### 7.5 记忆与上下文 (Memory & Context)

- [ ] **AC-M01**: 云端 trace 与本地日志互查
    - Given: 既有 `TraceIdInterceptor` 已为请求生成 traceId
    - When: trace 上报
    - Then: 应：trace 元数据包含该 traceId，凭同一 ID 可在本地日志与 LangSmith 平台双向定位同一请求；不应：云端 trace 丢失与本地日志的关联键

- [ ] **AC-M02**: 模型切换如实记录
    - Given: 会话中途发生模型切换（会话级模型选择）
    - When: 查看该 thread 下各轮 trace
    - Then: 应：各 LLM span 的模型名如实反映当轮实际使用的模型；不应：全 thread 显示同一模型名而掩盖切换事实

### 7.6 人机协作 (Human-in-the-Loop)

- [ ] **AC-H01**: 评估结果可追溯排查
    - Given: 评估实验产出的结果中存在未达标项
    - When: 开发者排查原因
    - Then: 应：可通过评估结果关联到对应原始 trace（trace -> 数据集 -> 评估结果的追溯链路可用），人工判断是模型行为问题还是数据问题；不应：评估结果与原始 trace 脱钩导致无法归因

- [ ] **AC-H02**: 敏感数据泄漏处置流程
    - Given: 发现敏感数据漏脱敏且已上报至 LangSmith
    - When: 人工介入处置
    - Then: 应：按「删除平台 trace -> 补充脱敏规则 -> 记录变更日志」流程处理（处置流程须文档化并演练走通）；不应：仅删除数据而不修复脱敏规则（同 class 泄漏会再次发生）

### 7.7 评估方式与通过标准

| 类别 | 评估数据来源 | 评估方式 | 通过标准 |
|------|------------|---------|---------|
| 正常交互（AC-N01~N04） | 真实 Key 环境下的端到端对话脚本（含工具调用、多轮对话、模型切换） | 手动：LangSmith UI 核查 trace 结构、thread 聚合、span 必备字段 | 必备字段齐全率 100%；thread 聚合正确 |
| 采集行为（AC-T01~T03） | 含失败注入的 ReAct 对话脚本（LLM 报错/工具抛异常场景） | 自动：监听器逻辑单测（mock 事件断言 span 生成）+ 手动核查失败 span 上报 | 失败 span 记录完整，trace 不中断 |
| 安全护栏（AC-S01~S05） | 脱敏正/反例样本集（密钥正例、含 sk-/ignore 等正常内容反例）；无 Key 启动用例；mock OTLP 通道故障注入 | 自动：JUnit（脱敏正例命中、反例不误伤、无 Key 零外联、故障不影响主流程） | 正例 100% 命中、反例 0% 误伤；无 Key 启动零网络请求；主流程零异常 |
| 边界降级（AC-E01~E03） | 网络阻断/慢响应模拟；超长工具输出构造；启停配置切换 | 自动（单测）+ 手动（响应耗时对比） | 主流程响应无可感知劣化；截断标识正确；启停行为确定 |
| 记忆上下文（AC-M01~M02） | 跨模型切换会话脚本；本地日志对照 | 手动：云地双向 ID 互查 | traceId 关联 100%；模型名如实反映 |
| 人机协作（AC-H01~H02） | 评估实验产出；模拟泄漏场景演练 | 手动：追溯链路走通 + 处置流程演练 | 追溯链路可用；处置流程文档化并演练通过 |

**整体通过标准**: 六类 AC 全部通过 + 既有单测/集成测试**零回归** + 配置 Key 后 LangSmith 平台数据可见且终端用户全程无感知。

## 8. 范围界定 (Scope)

### 8.1 本次范围（In Scope）
1. OTel 采集层：LLM 调用 + 工具调用两类事件的监听与 span 化（AC-N01/N03/N04、AC-T01~T03）

### 8.2 不在本次范围（Out of Scope）
