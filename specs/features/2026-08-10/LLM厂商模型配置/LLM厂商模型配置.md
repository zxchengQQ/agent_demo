# 功能需求说明书 (Feature Requirements Document)

## 1. 背景与价值 (Context & Value)

*   **背景**: 当前项目的 LLM 厂商和模型配置通过 `application.yml` 静态文件管理，修改配置需要重启服务。用户无法在使用过程中动态切换厂商或模型，也无法同时使用多个厂商的模型。这限制了平台的灵活性和用户体验。
*   **目标**: 将 LLM 厂商和模型配置提取到前端页面，由用户动态配置和管理，支持多厂商同时配置、按会话维度选择模型，实现配置即生效无需重启。
*   **关联**: 关联 CR-002（LLM 模块注册表路由重构），本次变更将配置源从静态 yml 文件切换为动态用户配置，注册表路由架构保持不变但配置源变更。

## 2. 功能范围 (Scope)

### 2.1 本次范围（In Scope）

*   LLM 配置管理页面（厂商的增删改查、模型配置、API Key 管理）
*   预定义厂商列表（火山引擎方舟、阿里百炼、OpenAI 等）+ 自定义厂商录入
*   预定义厂商常用模型列表供选择 + 自定义模型名称手动录入
*   模型类型管理：chat（对话）、embedding（向量化）、rerank（重排）、multimodal（多模态生图/视频），每种类型可配置多个模型
*   chat 模型支持标注"是否支持视图理解"
*   API Key 测试连接功能（保存前验证 Key 有效性）
*   API Key 脱敏显示
*   对话界面模型选择器（按会话维度，与知识库选择器、深度思考开关行为一致）
*   后端内存配置存储 + REST API 管理接口
*   前端 localStorage 配置持久化 + 后端重启后自动恢复
*   完全移除 `application.yml` 中的 LLM 相关配置（`llm`、`ark`、`bailian` 配置段）
*   RAG 模块的 embedding 模型从动态配置获取（替代原 yml 配置）

### 2.2 不在本次范围（Out of Scope）

*   rerank 模型的实际功能集成（本次仅作为配置项保存，不接入 RAG 检索重排流程） - 后续迭代接入
*   多模态模型的实际功能集成（本次仅作为配置项保存，不实现生图/视频功能） - 后续迭代接入
*   多用户认证与按用户隔离配置 - 当前项目无认证机制，全局共享配置
*   配置导入/导出功能 - 后续按需补充
*   模型用量统计与 Token 消耗追踪 - 后续按需补充
*   数据库持久化存储 - 本次使用内存 + localStorage，未来可引入数据库
*   配置变更审计日志 - 后续按需补充

## 3. 用户角色 (Actors)

*   **配置管理员**: 配置 LLM 厂商、API Key 和模型信息。当前项目无认证机制，所有访问者均为配置管理员。
*   **对话用户**: 在对话界面选择模型进行对话。当前项目无认证机制，所有访问者均为对话用户。

> **说明**: 配置管理员和对话用户可能是同一个人（学习/演示场景）。

## 4. 用户故事 (User Stories)

*   **US-001**: 作为 **配置管理员**，我想要 **在前端页面添加和管理 LLM 厂商配置**，以便 **无需修改配置文件和重启服务即可切换或新增 LLM 厂商**。
    *   关联验收标准：AC-001, AC-002, AC-010, AC-011, AC-018

*   **US-002**: 作为 **配置管理员**，我想要 **从预定义厂商列表中选择并自动填充配置**，以便 **快速完成常见厂商的配置而不用手动填写所有信息**。
    *   关联验收标准：AC-001, AC-023

*   **US-003**: 作为 **配置管理员**，我想要 **为每个厂商按类型配置多个模型**，以便 **不同任务使用最合适的模型**。
    *   关联验收标准：AC-003, AC-024

*   **US-004**: 作为 **配置管理员**，我想要 **为 chat 模型标注是否支持视图理解**，以便 **在对话时知道哪些模型可以处理图片**。
    *   关联验收标准：AC-004, AC-025

*   **US-005**: 作为 **配置管理员**，我想要 **在保存前测试 API Key 连接是否有效**，以便 **避免保存无效配置后对话才发现问题**。
    *   关联验收标准：AC-005, AC-015

*   **US-006**: 作为 **对话用户**，我想要 **在对话界面选择不同的模型**，以便 **针对不同对话使用最合适的模型**。
    *   关联验收标准：AC-006, AC-007, AC-008, AC-030

*   **US-007**: 作为 **对话用户**，我想要 **配置在后端重启后自动恢复**，以便 **不用每次重启后重新配置**。
    *   关联验收标准：AC-009, AC-021, AC-029

*   **US-008**: 作为 **配置管理员**，我想要 **API Key 在界面上脱敏显示**，以便 **防止 Key 被旁观者看到**。
    *   关联验收标准：AC-019

*   **US-009**: 作为 **对话用户**，我想要 **在未配置模型时得到明确引导**，以便 **知道需要先完成配置才能使用对话功能**。
    *   关联验收标准：AC-013, AC-014

## 5. 详细需求与流程 (Detailed Requirements)

### 5.1 核心流程

#### 5.1.1 首次配置流程

1. 用户打开应用，系统检测到无 LLM 配置
2. 对话页面显示空状态引导，提示"请先配置 LLM 模型"
3. 用户点击引导链接进入 LLM 配置页面
4. 用户点击"添加厂商"，从预定义列表选择厂商（或选择"自定义"）
5. 预定义厂商自动填充 Base URL，用户填写 API Key
6. 用户点击"测试连接"验证 API Key 有效性
7. 验证成功后，用户为该厂商添加模型（选择类型、填写/选择模型名称）
8. 对于 chat 类型模型，用户可勾选"支持视图理解"
9. 用户保存配置，配置同步保存到后端内存和前端 localStorage
10. 用户返回对话页面，模型选择器中出现已配置的 chat 模型，可开始对话

#### 5.1.2 对话中切换模型流程

1. 用户进入对话页面，模型选择器默认显示上次使用的模型（或第一个可用 chat 模型）
2. 用户点击模型选择器，展开按厂商分组的模型列表
3. 用户选择目标模型，选择器收起并显示新选模型
4. 用户输入消息并发送，后端使用当前会话选中的模型进行对话
5. 切换到另一个会话时，该会话保持各自独立的模型选择状态

#### 5.1.3 后端重启恢复流程

1. 后端重启后，后端内存中的 LLM 配置丢失
2. 用户打开/刷新页面，前端检测到后端无配置（或配置不完整）
3. 前端从 localStorage 读取已保存的配置
4. 前端将配置推送到后端，后端恢复内存中的配置
5. 用户无感恢复，可继续使用对话功能

#### 5.1.4 编辑/删除厂商配置流程

1. 用户进入 LLM 配置页面，查看已配置的厂商列表
2. **编辑**：用户点击厂商卡片上的"编辑"按钮，修改 API Key 或模型配置，保存后即时生效
3. **删除**：用户点击"删除"按钮，确认后该厂商及其所有模型配置被删除
4. 删除后，正在使用该厂商模型的会话自动切换到第一个可用 chat 模型

### 5.2 交互/界面规则 (UI/UX Rules)

*   **导航入口**: NavBar 新增"LLM 配置"入口（与"对话"、"知识库"并列），点击进入配置页面
*   **配置页面布局**: 厂商列表以卡片形式展示，每张卡片显示厂商名称、类型标签（预定义/自定义）、Base URL、模型数量及类型摘要、API Key 状态（已配置/未配置）
*   **添加厂商**: 点击"添加厂商"按钮弹出配置弹窗/抽屉，包含以下区域：
    *   厂商选择区：预定义厂商下拉列表 + "自定义"选项
    *   基础信息区：厂商名称、Base URL（预定义厂商自动填充，可修改）
    *   API Key 区：密码输入框（支持显示/隐藏切换）+ "测试连接"按钮
    *   模型配置区：按类型分组（chat/embedding/rerank/multimodal），每类下可添加多个模型
*   **模型添加行**: 模型类型下拉 + 模型名称（预定义厂商提供常用模型下拉 + 自定义输入框）+ 视图理解勾选框（仅 chat 类型显示）+ 删除按钮
*   **API Key 脱敏**: 已保存的 API Key 在展示时脱敏（如 `sk-****abcd`），编辑时需重新输入
*   **测试连接按钮**: 点击后显示 loading 状态，返回结果后显示成功（绿色提示）或失败（红色提示 + 错误原因）
*   **对话模型选择器**: 位于对话输入区域附近，下拉菜单按厂商分组展示 chat 模型，每个模型显示名称 + "支持视图"标记（如有），设计风格与知识库选择器一致
*   **空状态引导**: 对话页面在无可用 chat 模型时，输入框禁用并显示引导文案 + 跳转配置页面的链接
*   **删除确认**: 删除厂商时弹出二次确认框，提示"将删除该厂商及旗下所有模型配置"
*   **样式风格**: 遵循项目 Refined Dark Tech 暗色科技风设计系统

### 5.3 业务规则 (Business Rules)

*   **BR-LLM-CONF-001**: 厂商名称全局唯一，不允许重复（预定义厂商和自定义厂商统一校验）
*   **BR-LLM-CONF-002**: 每个厂商必须配置 API Key 才能保存（API Key 不可为空）
*   **BR-LLM-CONF-003**: 每个厂商必须配置 Base URL（预定义厂商自动填充，自定义厂商手动填写，均不可为空）
*   **BR-LLM-CONF-004**: 模型名称不可为空，同一厂商下同一类型的模型名称不可重复
*   **BR-LLM-CONF-005**: 模型类型限定为四种：chat（对话）、embedding（向量化）、rerank（重排）、multimodal（多模态生图/视频）
*   **BR-LLM-CONF-006**: 仅 chat 类型模型支持"支持视图理解"标记，其他类型不显示此选项
*   **BR-LLM-CONF-007**: 保存厂商配置前必须通过 API Key 测试连接（测试失败不允许保存）
*   **BR-LLM-CONF-008**: API Key 在前端界面展示时必须脱敏，禁止明文显示已保存的 Key
*   **BR-LLM-CONF-009**: 配置修改保存后即时生效，后续对话使用新配置，无需重启服务
*   **BR-LLM-CONF-010**: 模型选择按会话维度保持状态，切换会话互不影响，同一会话内保持状态
*   **BR-LLM-CONF-011**: 模型选择按消息维度控制（发送消息时使用当前选择的模型，不影响历史消息）
*   **BR-LLM-CONF-012**: 新建会话时默认选择上次使用的 chat 模型，无历史记录时选择第一个可用 chat 模型
*   **BR-LLM-CONF-013**: 删除厂商后，正在使用该厂商模型的会话自动切换到第一个可用 chat 模型，无可用模型时禁用对话
*   **BR-LLM-CONF-014**: 配置同时保存到后端内存和前端 localStorage，确保后端重启后可从 localStorage 恢复
*   **BR-LLM-CONF-015**: 后端重启后前端检测到后端无配置时，自动从 localStorage 推送配置到后端恢复
*   **BR-LLM-CONF-016**: 对话功能依赖至少一个已配置的 chat 模型，无 chat 模型时对话禁用并引导配置
*   **BR-LLM-CONF-017**: RAG 文档向量化依赖已配置的 embedding 模型，无 embedding 模型时阻止文档上传并引导配置
*   **BR-LLM-CONF-018**: 预定义厂商列表包含：火山引擎方舟、阿里百炼、OpenAI、DeepSeek、Ollama（本地），每个预定义厂商自带默认 Base URL 和常用模型清单
*   **BR-LLM-CONF-019**: 移除 `application.yml` 中 `llm`、`ark`、`bailian` 配置段，LLM 配置完全由前端动态管理
*   **BR-LLM-CONF-020**: 后端 LLM 模型实例缓存按厂商+模型名称维度管理，配置变更时清除对应缓存

## 6. 验收标准 (Acceptance Criteria)

> **重要**：以下验收标准是后续技术方案、任务规划和 TDD 测试用例的直接依据。每条 AC 必须使用 Given-When-Then 格式，必须可被测试验证。

### 6.1 正常流程 (Happy Path)

- [ ] **AC-001**: 添加预定义厂商配置
    - Given: 用户进入 LLM 配置页面，尚未配置任何厂商
    - When: 用户点击"添加厂商"，从预定义列表中选择"火山引擎方舟"（Base URL 自动填充），填写 API Key，添加一个 chat 模型（从常用模型列表中选择 doubao-seed-2.0-pro），点击"测试连接"成功后保存
    - Then: 厂商配置保存到后端内存和前端 localStorage，配置列表中显示"火山引擎方舟"厂商及其模型信息，对话页面模型选择器中出现该 chat 模型

- [ ] **AC-002**: 添加自定义厂商配置
    - Given: 用户进入 LLM 配置页面
    - When: 用户点击"添加厂商"，选择"自定义"，手动填写厂商名称"MyAI"、Base URL、API Key，手动输入 chat 模型名称"my-model-v1"，测试连接成功后保存
    - Then: 自定义厂商配置保存成功，在配置列表中与预定义厂商并列显示，对话页面可选择该模型

- [ ] **AC-003**: 为同一厂商配置多个不同类型模型
    - Given: 用户已添加火山引擎方舟厂商并配置了 1 个 chat 模型
    - When: 用户编辑该厂商，添加第二个 chat 模型（doubao-seed-2.0-lite）和一个 embedding 模型（doubao-embedding-large-text-240915），保存
    - Then: 该厂商下显示 2 个 chat 模型和 1 个 embedding 模型，按类型分组展示，对话选择器中出现 2 个 chat 模型可选

- [ ] **AC-004**: chat 模型标注视图理解支持
    - Given: 用户正在为某厂商添加 chat 类型模型
    - When: 用户勾选"支持视图理解"选项后保存
    - Then: 该模型在配置列表和对话模型选择器中显示"支持视图"标记（如图标或标签），未勾选的模型不显示该标记

- [ ] **AC-005**: 测试 API Key 连接成功
    - Given: 用户在添加/编辑厂商时已填写 API Key 和 Base URL
    - When: 用户点击"测试连接"按钮
    - Then: 系统使用该 API Key 向对应 Base URL 发送简单验证请求，成功后显示"连接成功"绿色提示，保存按钮变为可用状态

- [ ] **AC-006**: 在对话中选择模型并发送消息
    - Given: 用户已配置至少一个含 chat 模型的厂商，进入对话页面
    - When: 用户在模型选择器中选择某个 chat 模型，输入消息并发送
    - Then: 后端使用所选厂商和模型进行对话，通过 SSE 流式返回结果，对话界面正常显示回复

- [ ] **AC-007**: 不同会话使用不同模型
    - Given: 用户已配置多个 chat 模型（如火山引擎的 doubao-seed-2.0-pro 和阿里百炼的 deepseek-v4-flash），存在会话 A 和会话 B
    - When: 用户在会话 A 中选择 doubao-seed-2.0-pro 发送消息，在会话 B 中选择 deepseek-v4-flash 发送消息
    - Then: 会话 A 使用 doubao-seed-2.0-pro 对话，会话 B 使用 deepseek-v4-flash 对话，两个会话的模型选择互不影响

- [ ] **AC-008**: 新会话默认选择上次使用的模型
    - Given: 用户上次对话使用的模型为 doubao-seed-2.0-pro
    - When: 用户新建一个会话
    - Then: 新会话的模型选择器默认选中 doubao-seed-2.0-pro；如无上次使用记录，则默认选中第一个可用 chat 模型

- [ ] **AC-009**: 后端重启后自动恢复配置
    - Given: 用户已配置厂商和模型，配置已保存在前端 localStorage 中
    - When: 后端重启后用户打开或刷新页面
    - Then: 前端检测到后端无配置，自动将 localStorage 中的配置推送到后端，所有厂商和模型配置恢复，用户可正常使用对话功能

- [ ] **AC-010**: 编辑已有厂商配置
    - Given: 用户已配置火山引擎方舟厂商，API Key 为 Key-A
    - When: 用户点击该厂商的"编辑"按钮，将 API Key 修改为 Key-B，保存
    - Then: 配置更新成功，新 API Key（Key-B）立即生效，后续对话使用新 Key，配置列表中 API Key 状态更新

- [ ] **AC-011**: 删除厂商配置
    - Given: 用户已配置多个厂商（如火山引擎和阿里百炼）
    - When: 用户点击火山引擎厂商的"删除"按钮，在确认框中点击"确认删除"
    - Then: 火山引擎厂商及其所有模型配置被删除，配置列表中不再显示，对话模型选择器中不再出现该厂商的模型

- [ ] **AC-012**: 查看配置列表
    - Given: 用户已配置多个厂商和模型
    - When: 用户进入 LLM 配置页面
    - Then: 以卡片形式展示所有已配置厂商，每张卡片显示厂商名称、类型标签、Base URL、模型数量及类型摘要、API Key 配置状态

### 6.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-013**: 无任何配置时的空状态引导
    - Given: 系统首次启动或所有配置被删除，无任何 LLM 配置
    - When: 用户进入对话页面
    - Then: 对话输入框禁用，显示"请先配置 LLM 模型"提示文案，提供"去配置"链接跳转到 LLM 配置页面

- [ ] **AC-014**: 有厂商配置但无 chat 模型时对话禁用
    - Given: 用户已配置某厂商但仅配置了 embedding 模型，无任何 chat 模型
    - When: 用户进入对话页面
    - Then: 对话输入框禁用，显示"请先配置 chat 类型模型才能对话"提示，提供跳转链接

- [ ] **AC-015**: 测试连接失败
    - Given: 用户填写了错误的 API Key（如随机字符串）
    - When: 用户点击"测试连接"按钮
    - Then: 系统显示"连接失败"红色提示及错误原因（如"认证失败：API Key 无效"），保存按钮保持禁用状态，不允许保存该配置

- [ ] **AC-016**: 对话过程中 API Key 失效
    - Given: 用户正在对话，所选模型的 API Key 已过期或被撤销
    - When: 用户发送消息
    - Then: 对话界面显示错误提示（如"API Key 无效，请检查配置"），不导致应用崩溃，用户可切换到其他可用模型继续对话

- [ ] **AC-017**: 删除正在使用模型的厂商后自动切换
    - Given: 会话 A 正在使用厂商 X 的模型 M 对话，用户已配置厂商 Y 的模型 N
    - When: 用户在配置页面删除厂商 X
    - Then: 厂商 X 配置被删除，会话 A 的模型选择器自动切换到厂商 Y 的模型 N（第一个可用 chat 模型），用户可继续对话

- [ ] **AC-018**: 重复厂商名称校验
    - Given: 用户已配置名为"火山引擎方舟"的厂商
    - When: 用户尝试添加另一个名为"火山引擎方舟"的厂商
    - Then: 系统提示"厂商名称已存在"，不允许保存

- [ ] **AC-019**: API Key 脱敏显示
    - Given: 用户已保存某厂商的 API Key（如 sk-abcdefgh1234567890）
    - When: 用户查看或编辑该厂商配置
    - Then: API Key 以脱敏形式显示（如 sk-****7890），不显示完整内容；编辑时需重新输入完整 Key

- [ ] **AC-020**: 模型名称为空校验
    - Given: 用户正在添加模型
    - When: 用户未填写模型名称就尝试保存配置
    - Then: 系统提示"模型名称不能为空"，不允许保存

- [ ] **AC-021**: 后端重启且 localStorage 也无配置
    - Given: 后端重启，且前端 localStorage 中无任何 LLM 配置（如用户清除了浏览器数据或首次使用新浏览器）
    - When: 用户打开页面
    - Then: 显示空配置状态，对话功能禁用，引导用户进行首次配置

- [ ] **AC-022**: 同一厂商下同类型模型名称重复
    - Given: 用户已为厂商 X 添加了名为"model-a"的 chat 模型
    - When: 用户尝试为厂商 X 再添加一个名为"model-a"的 chat 模型
    - Then: 系统提示"该类型下已存在同名模型"，不允许保存

### 6.3 业务规则验证 (Business Rules)

- [ ] **AC-023**: 预定义厂商自动填充 Base URL
    - Given: 用户在添加厂商弹窗中选择预定义厂商"火山引擎方舟"
    - When: 选择完成后
    - Then: Base URL 字段自动填充为 `https://ark.cn-beijing.volces.com/api/coding/v3`，用户可修改但不可清空

- [ ] **AC-024**: 模型类型分类管理
    - Given: 用户为厂商添加模型
    - When: 选择模型类型时
    - Then: 可选类型为：chat（对话）、embedding（向量化）、rerank（重排）、multimodal（多模态），每种类型可添加多个模型；仅 chat 类型显示"支持视图理解"勾选框

- [ ] **AC-025**: 模型选择器按厂商分组并显示视图标记
    - Given: 用户已配置多个厂商的 chat 模型，部分标注了"支持视图理解"
    - When: 用户在对话界面打开模型选择器
    - Then: 模型列表按厂商分组展示，每个模型显示名称，标注了视图理解的模型额外显示"支持视图"标记

- [ ] **AC-026**: 配置修改即时生效
    - Given: 用户修改了某厂商的 API Key 或新增了模型
    - When: 保存修改后
    - Then: 新配置立即生效，后续对话使用新配置，无需重启服务；后端模型实例缓存中对应旧配置的实例被清除

- [ ] **AC-027**: RAG 使用已配置的 embedding 模型
    - Given: 用户已配置含 embedding 模型的厂商
    - When: 用户在知识库中上传文档进行向量化
    - Then: 系统使用已配置的 embedding 模型进行文档向量化处理

- [ ] **AC-028**: 无 embedding 模型时 RAG 阻止文档上传
    - Given: 用户未配置任何 embedding 模型
    - When: 用户尝试上传文档到知识库
    - Then: 系统提示"请先配置 embedding 模型才能上传文档"，阻止上传操作

- [ ] **AC-029**: 配置同步至 localStorage 持久化
    - Given: 用户在前端页面添加、修改或删除了厂商/模型配置
    - When: 操作保存成功后
    - Then: 配置变更同步写入前端 localStorage，后续页面刷新或重新打开时配置不丢失

- [ ] **AC-030**: 会话级模型选择状态隔离
    - Given: 用户在会话 A 中选择了模型 X，在会话 B 中选择了模型 Y
    - When: 用户在会话 A 和会话 B 之间切换
    - Then: 会话 A 保持模型 X 选中状态，会话 B 保持模型 Y 选中状态，切换不影响彼此
