## 四、子任务详情

### 4.1 任务 5.1：短期记忆封装 ChatMemoryManager

- **目标**：基于 LangChain4j 的 MessageWindowChatMemory 封装短期记忆
- **接口设计**：
  ```java
  @Service
  public class ChatMemoryManager {
      // 获取指定会话的记忆（不存在则创建）
      public ChatMemory getMemory(String sessionId);
      // 创建新会话记忆
      public ChatMemory createMemory(String sessionId);
      // 创建带窗口大小的会话记忆
      public ChatMemory createMemory(String sessionId, int maxMessages);
      // 添加用户消息
      public void addUserMessage(String sessionId, String message);
      // 添加助手消息
      public void addAssistantMessage(String sessionId, String message);
      // 清空会话记忆
      public void clearMemory(String sessionId);
  }
  ```
- **实现要点**：
  - 默认窗口大小：20 条消息（可配置）
  - 内部使用 `ConcurrentHashMap<String, ChatMemory>` 存储会话记忆
  - 基于 `MessageWindowChatMemory.withMaxMessages(20)` 创建
  - 线程安全：会话级别隔离，不同 sessionId 互不干扰
- **调用方**：agent 层（构建 AiServices 时传入 memory）
- **核心逻辑注释**：注明窗口大小选择的业务原因（平衡上下文长度与 Token 消耗）

### 4.2 任务 5.2：会话管理器 SessionManager

- **目标**：管理会话生命周期，支持会话创建、查询、关闭、超时清理
- **接口设计**：
  ```java
  @Service
  public class SessionManager {
      // 创建新会话
      public String createSession();
      // 创建会话并指定元信息
      public String createSession(SessionMetadata metadata);
      // 获取会话元信息
      public SessionMetadata getSession(String sessionId);
      // 关闭会话
      public void closeSession(String sessionId);
      // 判断会话是否存在
      public boolean exists(String sessionId);
      // 清理超时会话（定时任务调用）
      public void cleanupExpiredSessions(Duration timeout);
  }
  ```
- **SessionMetadata 字段**：
  - `String sessionId`：会话 ID（UUID）
  - `String userId`：用户标识（预留多租户）
  - `long createdAt`：创建时间戳
  - `long lastActiveAt`：最后活跃时间戳
  - `Map<String, Object> attributes`：扩展属性
- **实现要点**：
  - 基于 `ConcurrentHashMap<String, SessionMetadata>` 存储
  - 默认会话超时：30 分钟无活跃自动清理
  - 提供 `@Scheduled` 定时清理任务（bootstrap 启用调度）
- **调用方**：web 层（每次请求创建/查询会话）、agent 层

### 4.3 任务 5.3：记忆持久化接口 MemoryRepository

- **目标**：抽象记忆持久化，支持后续接入数据库
- **接口设计**：
  ```java
  public interface MemoryRepository {
      // 保存会话消息
      void saveMessages(String sessionId, List<ChatMessage> messages);
      // 加载会话历史消息
      List<ChatMessage> loadMessages(String sessionId);
      // 删除会话消息
      void deleteMessages(String sessionId);
  }
  ```
- **实现**：
  - `InMemoryMemoryRepository`：基于 ConcurrentHashMap 的内存实现（开发阶段使用）
  - 预留 `DbMemoryRepository`：基于 MySQL + MyBatis-Plus 的实现（后续阶段）
- **调用方**：ChatMemoryManager 内部调用（自动持久化）
- **设计原则**：接口与实现分离，便于后续替换存储方案

### 4.4 任务 5.4：长期记忆接口 LongTermMemory（预留）

- **目标**：定义长期记忆接口，支持将重要对话向量化存储，供后续检索
- **接口设计**：
  ```java
  public interface LongTermMemory {
      // 存储记忆（自动向量化）
      void store(String sessionId, String content, Map<String, Object> metadata);
      // 语义检索相关记忆
      List<String> retrieve(String query, int topK);
      // 按会话检索
      List<String> retrieveBySession(String sessionId, String query, int topK);
  }
  ```
- **实现**：
  - 本阶段提供 `EmptyLongTermMemory` 空实现（所有方法返回空集合）
  - 后续 RAG 模块实现后，替换为基于 Milvus 的实现
- **依赖**：ModelFactory.getEmbeddingModel()（向量化）
- **设计原因**：提前定义接口，避免后续重构 agent 层

## 七、风险与注意事项

1. **内存泄漏**：会话记忆存储在内存，长期运行会积累大量数据，需通过定时清理任务释放超时会话
2. **线程安全**：多用户并发访问，ChatMemoryManager 与 SessionManager 必须使用线程安全的数据结构
3. **窗口大小与 Token 消耗**：窗口过大消耗 Token 多，过小丢失上下文，默认 20 条需根据实际效果调整
4. **持久化时机**：本阶段 InMemory 实现不持久化，重启后丢失，后续接入 DB 后需考虑事务一致性
5. **会话 ID 安全**：sessionId 使用 UUID，防止可预测；web 层需校验会话归属（预留 userId 字段）
6. **长期记忆接口稳定性**：LongTermMemory 接口一旦定义应保持稳定，后续只替换实现，避免影响 agent 层
