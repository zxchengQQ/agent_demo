# 功能需求说明书 (Feature Requirements Document)

## 1. 背景与价值 (Context & Value)

*   **背景**: 当前 Agent 仅支持单轮 ReAct 循环（思考->工具调用->回复），面对复杂任务时缺乏规划能力，容易陷入局部最优或遗漏关键步骤。用户无法直观了解 Agent 的工作进度和思路。需要一种机制让 Agent 先"规划"再"执行"，将复杂任务拆解为可管理的子任务，逐步完成并实时展示进度。
*   **目标**: 为 Agent 新增复杂任务拆解能力，使其能够自主判断任务复杂度、拆解为子任务、按序全自动执行、实时展示进度、失败即停并报错，最终生成总结。前端提供开关控制和可视化任务列表。
*   **关联**: 属于 Agent 编排能力域的增强，对应 KNOWLEDGE_BASE.md 1.4 能力矩阵中"Agent 编排"能力的扩展。CR 编号：CR-002。

## 2. 功能范围 (Scope)

### 2.1 本次范围（In Scope）

*   后端：Agent 新增复杂任务拆解能力（LLM 判断复杂度 -> 拆解子任务 -> 按序执行 -> 失败即停 -> 生成总结）
*   后端：任务拆解过程的流式事件推送（子任务状态变更实时通知前端）
*   前端：输入区新增「复杂任务拆解」开关（与深度思考独立共存）
*   前端：助手消息内嵌可折叠任务列表（状态图标 + 标题 + 可展开详情）
*   前端：停止生成按钮适配任务取消场景
*   前端：任务列表随消息持久化到 localStorage

### 2.2 不在本次范围（Out of Scope）

*   多 Agent 协作执行子任务 - 每个子任务仍由单 Agent 执行，暂不引入多 Agent 编排
*   用户手动编辑/重排子任务 - 子任务由 Agent 自动生成和执行，用户不干预拆解结果
*   子任务失败重试机制 - 失败即停止，不自动重试，用户可重新发送消息
*   跨会话任务拆解历史 - 仅当前会话 localStorage 持久化，不做后端持久化
*   后端持久化任务拆解记录 - 仅前端 localStorage 存储，后端会话超时后不保留拆解记录

## 3. 用户角色 (Actors)

*   **学习者/开发者**: 通过前端对话界面与 Agent 交互，开启拆解模式后观察 Agent 的任务规划和执行过程，理解 Agent 的编排能力。

## 4. 用户故事 (User Stories)

*   **US-001**: 作为 **学习者**，我想要 **开启复杂任务拆解模式后让 Agent 自动将复杂任务拆为子任务并逐步执行**，以便 **直观了解 Agent 的工作思路和进度**。
    *   关联验收标准：AC-001, AC-003, AC-004
*   **US-002**: 作为 **学习者**，我想要 **在任务列表中展开查看每个子任务的执行详情（含执行中实时 ReAct 过程）**，以便 **理解 Agent 在每个步骤中做了什么**。
    *   关联验收标准：AC-005, AC-016, AC-017
*   **US-003**: 作为 **学习者**，我想要 **在 Agent 执行过程中随时停止任务**，以便 **在发现方向错误时及时中断避免浪费 Token**。
    *   关联验收标准：AC-007
*   **US-004**: 作为 **学习者**，我想要 **拆解模式与深度思考模式独立开关、可同时使用**，以便 **根据需要灵活组合 Agent 能力**。
    *   关联验收标准：AC-011, AC-012
*   **US-005**: 作为 **学习者**，我想要 **刷新页面后仍能查看之前的任务拆解过程**，以便 **回顾 Agent 的完整工作记录**。
    *   关联验收标准：AC-014

## 5. 详细需求与流程 (Detailed Requirements)

### 5.1 核心流程

1.  用户在前端输入区开启「复杂任务拆解」开关（独立于「深度思考」开关，两者可同时开启）
2.  用户输入消息并发送，前端通过流式接口将消息及拆解模式标识发送给后端
3.  后端 Agent 接收消息后，通过 LLM 判断任务复杂度：
    *   **需要拆解**：LLM 生成 1-10 个子任务列表，通过流式事件推送给前端
    *   **无需拆解**：直接以普通对话方式流式回复，不展示任务列表
4.  前端收到子任务列表后，在助手消息内展示可折叠的任务列表区块，所有子任务初始状态为"待执行"
5.  Agent 按子任务顺序自动执行：
    *   某个子任务开始执行时，状态变更为"执行中"，前端实时更新
    *   子任务执行完成时，状态变更为"已完成"，前端实时更新
    *   子任务执行过程中可调用已有工具（计算器、时间、HTTP、文件读取等）
6.  **全部子任务完成后**：Agent 生成一段最终总结回复，展示在任务列表下方
7.  **子任务执行失败时**：立即停止，该子任务标记"失败"并显示原因，后续子任务标记"已取消"
8.  **用户中途停止时**：取消当前及后续子任务，已完成的保持不变
9.  任务列表随消息持久化到 localStorage，刷新页面可回看

### 5.2 交互/界面规则 (UI/UX Rules)

*   「复杂任务拆解」开关位于输入区，与「深度思考」开关并排展示，样式风格一致（Refined Dark Tech 暗色科技风）
*   开关状态按消息维度控制，当前会话内保持状态，切换会话互不影响（与 BR-FE-011 深度思考开关行为一致）
*   任务列表为可折叠区块，位于助手消息内容区域，风格与现有"推理内容"折叠区块一致（BR-FE-012）
*   任务列表标题示例："任务拆解（3/5 已完成）"，完成后折叠为"已完成 5 个子任务"
*   每个子任务以"状态图标 + 序号 + 标题"形式展示，状态图标对应：待执行（○）、执行中（◐ 旋转动画）、已完成（✓ 绿色）、失败（✕ 红色）、已取消（— 灰色）
*   已完成和执行中的子任务可点击展开，显示该子任务的 ReAct 过程（Thought/Action/Observation）和结果摘要；执行中的子任务自动展开，ReAct 步骤实时更新
*   流式输出过程中禁用输入框，提供"停止生成"按钮（与 BR-FE-009 一致）
*   点击"停止生成"时，取消当前及后续子任务，已接收的内容保留

### 5.3 业务规则 (Business Rules)

*   子任务数量上限为 10 个，LLM 生成超过 10 个时需自动合并或精简
*   LLM 自主判断任务是否需要拆解，简单任务（如"现在几点"）直接回复，不强制拆解
*   子任务按序执行，不可并行，前一个完成后才开始下一个
*   子任务失败即停止整个任务，不跳过失败项继续执行
*   拆解模式与深度思考模式独立开关，可同时开启，互不影响
*   任务列表随消息持久化到 localStorage（含各子任务状态和详情），遵循 50 会话 FIFO 淘汰策略（BR-FE-007）
*   最终总结在所有子任务完成后由 Agent 自动生成
*   子任务执行过程中可使用 Agent 已有的全部工具能力

## 6. 验收标准 (Acceptance Criteria)

> **重要**：以下验收标准是后续技术方案、任务规划和 TDD 测试用例的直接依据。每条 AC 必须使用 Given-When-Then 格式，必须可被测试验证。

### 6.1 正常流程 (Happy Path)

- [ ] **AC-001**: 开启拆解模式发送复杂任务
    - Given: 用户已在前端输入区开启「复杂任务拆解」模式
    - When: 用户发送一个复杂任务消息（如"帮我调研 Vue3 和 React 的区别，并给出技术选型建议"）
    - Then: Agent 将任务拆解为多个子任务（1-10个），在前端助手消息内以可折叠任务列表展示，按顺序自动执行每个子任务，每个子任务状态实时更新（待执行->执行中->已完成）

- [ ] **AC-002**: 开启拆解模式发送简单任务
    - Given: 用户已开启「复杂任务拆解」模式
    - When: 用户发送一个简单任务消息（如"现在几点"）
    - Then: Agent 判断该任务无需拆解，直接以普通对话方式流式回复，不展示任务列表

- [ ] **AC-003**: 子任务状态实时流转
    - Given: 任务列表已在前端展示且 Agent 开始按序执行
    - When: 某个子任务开始执行时
    - Then: 该子任务状态从"待执行"变为"执行中"（前端实时更新显示执行中图标）；当该子任务执行完成时，状态变为"已完成"（前端实时更新显示完成图标）

- [ ] **AC-004**: 全部完成后生成最终总结
    - Given: 任务列表中所有子任务均已执行完成（全部为"已完成"状态）
    - When: 最后一个子任务标记为"已完成"后
    - Then: Agent 生成一段最终总结回复文本，展示在任务列表区块下方，总结整体任务完成情况和关键结论

- [ ] **AC-005**: 展开查看子任务详情（执行中/已完成）
    - Given: 任务列表中某子任务处于"执行中"或"已完成"状态
    - When: 用户点击该子任务条目（执行中状态下自动展开）
    - Then: 展开显示该子任务的 ReAct 过程（Thought/Action/Observation）和结果摘要；执行中状态下 ReAct 步骤实时更新

- [ ] **AC-017**: 执行中实时展示 ReAct 过程
    - Given: 任务列表中某子任务状态从"待执行"变为"执行中"
    - When: 子任务开始执行，后端推送 task_thought/task_action/task_observation 事件
    - Then: 该子任务自动展开，ReAct 步骤（Thought/Action/Observation）实时出现在详情区域，用户无需手动点击即可观察执行过程

### 6.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-006**: 子任务执行失败
    - Given: Agent 正在按序执行任务列表中的子任务
    - When: 某个子任务执行失败（如工具调用返回错误、LLM 调用超时等）
    - Then: 立即停止整个任务执行，将该子任务状态标记为"失败"并显示失败原因，后续所有未执行的子任务状态标记为"已取消"，不生成最终总结

- [ ] **AC-007**: 用户中途停止任务
    - Given: 任务列表中有子任务正在执行中，其余子任务处于待执行状态
    - When: 用户点击"停止生成"按钮
    - Then: 取消当前执行中的子任务和所有未执行的子任务，状态标记为"已取消"；已完成的子任务保持"已完成"状态不变；已接收的部分内容保留在界面中

- [ ] **AC-008**: 子任务数量超过上限
    - Given: LLM 判断任务需要拆解并开始生成子任务列表
    - When: LLM 生成的子任务数量超过 10 个
    - Then: 自动合并或精简至 10 个以内的子任务，确保最终展示和执行的子任务不超过 10 个

- [ ] **AC-009**: LLM 判断无需拆解
    - Given: 用户已开启「复杂任务拆解」模式并发送消息
    - When: LLM 判断该任务不需要拆解（任务简单或为闲聊）或返回空子任务列表
    - Then: 以普通对话方式流式回复，不展示任务列表区块，行为与未开启拆解模式时一致

- [ ] **AC-010**: 网络中断导致流式连接断开
    - Given: 任务列表中有子任务正在执行中，部分子任务已完成
    - When: 网络连接中断导致 SSE 流式连接断开
    - Then: 已完成的子任务保持"已完成"状态，当前执行中的子任务标记为"失败"，后续未执行的子任务标记为"已取消"

- [ ] **AC-011**: 拆解模式与深度思考模式共存
    - Given: 用户同时开启「复杂任务拆解」和「深度思考」两个模式
    - When: 用户发送一个复杂任务消息
    - Then: Agent 先拆解为子任务并展示任务列表，每个子任务执行时可伴随推理过程展示，任务列表区块与推理内容区块独立展示，互不干扰

### 6.3 业务规则验证 (Business Rules)

- [ ] **AC-012**: 拆解开关状态保持与会话隔离
    - Given: 用户在当前会话中开启了「复杂任务拆解」模式
    - When: 用户继续在同一会话中发送消息
    - Then: 拆解模式保持开启状态；当用户切换到另一个会话时，另一个会话的拆解模式状态不受影响（按消息维度控制，会话内保持，切换会话互不影响）

- [ ] **AC-013**: 子任务数量上限规则
    - Given: Agent 正在进行任务拆解
    - When: LLM 生成子任务列表
    - Then: 子任务数量必须不超过 10 个，超过时自动合并或精简

- [ ] **AC-014**: 任务列表持久化到 localStorage
    - Given: 一条包含任务拆解的助手消息已生成（含任务列表和各子任务状态、详情）
    - When: 用户刷新页面或重新打开浏览器
    - Then: 该消息的任务列表完整保留（含各子任务的标题、状态、执行详情），可重新展开查看，遵循 50 会话 FIFO 淘汰策略

- [ ] **AC-015**: 任务列表 UI 风格一致性
    - Given: 任务列表在前端助手消息中展示
    - When: 用户查看任务列表区块
    - Then: 任务列表采用可折叠区块设计，风格与现有"推理内容"折叠区块一致（Refined Dark Tech 暗色科技风），流式中展开（标题"任务拆解（X/Y 已完成）"），完成后折叠（标题"已完成 Y 个子任务"）

- [ ] **AC-016**: 子任务数据结构完整性
    - Given: 任务列表中的任意子任务
    - When: 用户查看该子任务
    - Then: 子任务包含完整数据：序号（1-based）、标题描述、执行状态（待执行/执行中/已完成/失败/已取消）、可展开的执行详情（执行过程和结果摘要）
