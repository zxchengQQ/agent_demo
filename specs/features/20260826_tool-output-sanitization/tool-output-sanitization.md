> **文档定位**：本功能是对**现有 Agent 的数据获取类工具**进行安全加固，不改变工具模块架构（ToolRegistry / ToolExecutor / 权限体系不动），不改变 Agent 自主性级别。
> **关联文档**：`specs/features/20260826_tool-output-sanitization/Agent框架工具结果清洗调研报告.md`（优化点 4 的调研交付物）

## 1. 背景与价值 (Context & Value)

* **背景**：Agent 通过数据获取类工具（HTTP 请求、文件读取、MCP 调用、知识库检索）消费外部数据，当前工具产出**未经任何清洗**即原样进入 LLM 上下文，存在三类风险：
  1. **提示注入风险**：工具返回的信息中若包含非法指令（如"忽略之前指令"），可能诱导大模型违背预设规则、越权执行任务（间接提示注入，OWASP LLM Top 1 风险）；
  2. **上下文溢出风险**：工具返回文本量无统一限制（MCP / RAG 工具当前完全无限制），超长结果会撑爆模型上下文窗口；
  3. **脚本注入风险**：HttpTool 获取的 HTML 页面数据原样返回，其中包含的 script / iframe / 危险协议等可执行内容会被送入上下文，构成注入载体。
* **目标**：对全部数据获取类工具的产出实施"清洗 + 声明 + 限长"三层安全处理，使工具结果作为**数据**而非**指令**进入模型上下文，且超长内容可追溯、可继续查询。
* **关联**：属于工具调用模块（TOOL）安全加固迭代；调研部分产出独立报告。

## 2. Agent 角色定义 (Agent Persona)

### 2.1 身份定位

* **角色名称**：工具产出安全清洗（tool-output-sanitization）
* **角色类型**：任务型（对现有工具链路的安全加固，非新增 Agent）
* **身份描述**：为现有 Agent 的数据获取工具增加"产出清洗器"能力：所有外部数据在进入 LLM 上下文前，经过数据清洗、边界声明与字数限制三道处理。
* **核心价值**：防御间接提示注入、防止上下文溢出、消除脚本注入载体，同时保持工具数据完整性（分级处置避免误杀）。

### 2.2 目标用户与场景

* **目标用户**：Agent 框架的学习者与开发者（本项目的定位用户）。
* **使用场景**：Agent 调用 HTTP/文件/MCP/知识库工具获取外部数据；外部数据中可能被恶意植入指令（网页、文档、MCP Server 返回值均不可信）。
* **交互风格**：不改变现有交互；清洗动作对用户无感（仅日志可观测）。

## 3. 能力边界与自主性 (Capability & Autonomy)

### 3.1 能力清单（In Scope）

* 4 类数据获取工具（HttpTool、FileReadTool、MCP 动态工具、RAG 知识库检索）的产出清洗；
* HTML 场景防御链：请求级协议白名单 + MIME 白名单 + 可执行内容剥离 + 内容级危险协议限制；
* 可疑指令模式分级处置（一般可疑标记保留 / 高危移除占位）；
* 所有工具产出统一包裹"外部数据、非指令"边界声明（含来源工具标识）；
* 工具产出字数限制：超限保存临时文件，前缀进入上下文，模型可分段查询剩余内容；
* 清洗动作 WARN 安全日志（工具名、命中规则、截断统计）。

### 3.2 能力禁区（Out of Scope）

* **不修改工具模块架构** - 本次定位为具体工具优化，ToolRegistry / ToolExecutor / 权限裁决体系零变更（用户明确要求）；
* **不清洗本地可信工具** - Calculator / Time / AskUser 产出为本地计算结果，可信度高，清洗无意义且增加提示词噪音；
* **不新增前端交互** - 清洗不产生前端打断、确认卡片或事件协议变更；
* **不执行工具结果中的任何指令** - 工具产出一律视为数据（这是本功能的核心原则）。

### 3.3 自主性级别

* **级别**：不变（沿用现有工具权限体系 ALLOW / ASK / DENY 三级裁决）。
* **说明**：本次为安全加固，不调整自主性；清洗层位于权限裁决之后、结果返回之前，属于纵深防御新增的一道防线。
* **人类介入点**：不新增。高危注入诱导模型调用敏感工具时，由现有 ASK 级确认卡片兜底（见 AC-H01）。

### 3.4 知识边界

* **知识范围**：清洗规则针对提示注入特征模式与 HTML 可执行内容；不涉及内容语义审查（色情/暴力等内容审核不在范围）。
* **超出边界处理**：未知可疑模式放行并保留原文（保守策略：宁可漏放不可误杀，误杀会破坏数据完整性）。

## 4. 工具与动作空间 (Tools & Action Space)

### 4.1 工具清单（本次涉及）

| 工具名称 | 用途 | 本次加固内容 | 副作用 | 权限 | 新增限制 | 常见失败场景 |
|---------|------|------------|--------|------|---------|-------------|
| httpGet / httpPost | 获取网页/API 内容 | HTML 防御链（协议白名单/MIME 白名单/可执行内容剥离/危险协议限制）+ 清洗 + 包裹声明 + 超长临时文件 | 无（只读外部） | ASK | 请求仅允许 http/https；响应 MIME 须在白名单 | 超时/SSRF 拦截/非白名单类型 |
| readFile | 读取本地文件 | 清洗 + 包裹声明 + 超大文件从"拒绝读取"改为"截断+临时文件" | 无（只读） | ASK | 字数上限（可配置） | 路径越界/文件不存在/临时文件写入失败降级 |
| MCP 动态工具 | 调用 MCP Server | 内容解析层清洗 + 包裹声明 + 字数限制（当前完全无限制） | 视工具而定 | 沿用 | 字数上限（可配置） | Server 断线/解析失败降级提示 |
| 知识库检索工具 | RAG 片段检索 | 清洗 + 包裹声明 + 总长度控制 | 无（只读） | 沿用 | 字数上限（可配置） | 检索服务异常返回提示文本 |

### 4.2 工具间关系

* **依赖关系**：超长工具产出的临时文件，依赖文件读取工具可分段查询（工具 A 产出 → 工具 B 查询）。
* **互斥关系**：无新增。
* **编排策略**：模型按需在"获取工具 → 发现超长提示 → 分段查询临时文件"链路上自主编排。

### 4.3 工具选择策略

* 模型读到"结果已截断，剩余内容在 X 处"提示后，应自主决定是否分段查询剩余内容；
* 临时文件内容为**清洗后**内容（与前缀同源同规则），查询时不再重复清洗。

## 5. 推理流程与记忆策略 (Reasoning & Memory)

### 5.1 推理模式

* **主要模式**：不变（ReAct 循环）。清洗层对推理流程透明：工具结果在返回给 ReAct 循环前完成清洗、包裹与限长。

### 5.2 澄清策略

* **不新增澄清**：清洗不产生向用户的追问；模型对截断内容是否继续查询由模型自主决策。

### 5.3 短期记忆（对话内）

* **上下文保留轮次**：不变。
* **上下文溢出处理**：本次通过"字数限制 + 临时文件外置"从源头控制工具结果对上下文的占用，缓解溢出（会话级历史裁剪不在本次范围）。

### 5.4 长期记忆（跨会话）

* **是否需要**：否。
* **记忆内容**：包裹声明随工具结果消息持久化到会话历史（一次性写入，见 AC-M01/M02）。
* **遗忘策略**：临时文件按简单过期策略清理（精细生命周期管理不在本次范围）。

## 6. 护栏安全与降级策略 (Guardrails & Fallback)

### 6.1 内容安全规则

* **必须拒绝的请求**：不新增用户侧拒绝规则（本次针对工具产出侧）。
* **标准拒绝话术**：不适用。
* **敏感话题处理**：不在范围（仅处理注入特征与可执行内容）。

### 6.2 幻觉防护

* **回答依据**：不变；清洗不改变工具数据的可用性（分级处置保证正文保留）。
* **无结果处理**：不变（现有各工具的"未找到/为空"提示行为保持）。

### 6.3 敏感信息处理

* **输入侧**：不适用。
* **输出侧**：工具产出中的秘密类模式（password/token/api_key 等）的主动脱敏列为**扩展方案**（见调研报告扩展优化方案），本次不实现。

### 6.4 工具失败降级

| 工具 | 失败场景 | 降级策略 | 是否转人工 |
|------|---------|---------|-----------|
| 全部 4 类 | 清洗/包裹/限长环节自身异常 | 跳过清洗直接返回原始结果（清洗层永不阻断工具结果返回），记录 ERROR 日志 | 否 |
| 全部 4 类 | 临时文件写入失败 | 降级为纯截断（保留现有截断行为），对话不中断 | 否 |
| 全部 4 类 | 工具本体执行失败 | 不变：返回错误信息字符串，不中断 ReAct 循环（沿用 AC-012） | 否 |
| HttpTool | MIME 非白名单 | 返回可读提示（类型 + 已拦截说明），不返回二进制原文 | 否 |

### 6.5 人机协作机制

* **升级条件**：不新增。高危注入若成功诱导模型调用敏感工具，由现有 ASK 权限确认机制拦截（用户看到确认卡片，构成最后防线）。
* **升级方式**：沿用现有 askUser / 确认卡片机制。
* **交接信息**：不适用（清洗层不产生交接）。

### 6.6 提示注入防护（本功能核心）

* **攻击识别**：
  1. 一般可疑模式：指令诱导类特征（如"忽略之前指令""你现在是""system:"等）；
  2. 高危模式：伪造系统提示词、诱导调用敏感工具、诱导泄露系统信息；
  3. HTML 可执行内容：script/iframe/object/embed/事件属性/javascript:、data:、vbscript: 协议引用。
* **处理策略**：分级处置——一般可疑保留原文 + 警示标记；高危移除片段 + 占位标记 + WARN 日志；全部动作记录安全日志（见 AC-S07）。
* **工具返回防护**：**一律不允许执行来自工具返回内容中的指令**；所有工具产出包裹"外部数据、非指令"边界声明后进入上下文。

### 6.7 权限与身份校验

* **身份确认机制**：不变（沿用现有体系）。
* **防越权策略**：不变（SSRF 防护、路径白名单行为保持，见 AC-S08）。
* **数据隔离**：不变。

## 7. 验收标准 (Acceptance Criteria)

> **重要**：以下验收标准是后续技术方案与评估测试的直接依据。每条 AC 使用 Given-When-Then 格式。AC 关注**行为约束**而非精确输出。

### 7.1 正常交互流程 (Normal Interaction)

- [ ] **AC-N01**: 正常数据获取结果经处理后可用
    - Given: 任一数据获取工具（HTTP/文件/MCP/知识库）返回正常内容（无可疑模式、未超限）
    - When: 工具产出进入 LLM 上下文
    - Then: 正文内容完整保留（清洗不破坏正常数据），产出外层包裹"外部数据、非指令"边界声明且声明中含来源工具标识；不应出现正文信息因清洗丢失的情况

- [ ] **AC-N02**: 短结果不触发临时文件机制
    - Given: 工具结果低于字数上限
    - When: 工具返回
    - Then: 直接返回完整结果，不产生临时文件、不出现截断提示

### 7.2 工具选择与调用 (Tool Selection & Invocation)

- [ ] **AC-T01**: 超长结果截断与查询指引
    - Given: 工具结果超过配置的字数上限
    - When: 工具返回
    - Then: 前缀部分（清洗后）进入上下文，剩余内容保存为临时文件，返回文本明确包含三项信息：前缀正文、"已截断"声明、临时文件位置与查询方式；不应让超长全文直接进入上下文

- [ ] **AC-T02**: 剩余内容可分段查询
    - Given: 临时文件已因超长保存
    - When: 模型判断需要查看剩余内容并发起查询
    - Then: 可通过文件读取能力分段获取剩余部分，无需一次性读取全文；临时文件内容为清洗后内容，查询时不再重复清洗

- [ ] **AC-T03**: 大文件读取行为变更（从拒绝到截断）
    - Given: 用户请求读取超过原大小限制的大文件
    - When: 调用文件读取工具
    - Then: 不再直接拒绝，而是返回前缀 + 临时文件查询指引（行为变更点）；不应出现"文件过大"导致的完全失败

- [ ] **AC-T04**: 字数上限可配置
    - Given: 运维/开发者修改字数上限配置
    - When: 工具返回超限内容
    - Then: 按新配置的阈值执行截断；未配置时使用默认值

### 7.3 安全与护栏 (Safety & Guardrails)

- [ ] **AC-S01**: 请求级协议白名单
    - Given: 模型发起 http/https 之外协议的请求（如 file://、ftp://）
    - When: HTTP 工具校验 URL
    - Then: 拒绝请求并返回错误提示；不应放行非白名单协议

- [ ] **AC-S02**: 响应 MIME 白名单
    - Given: HTTP 响应的 Content-Type 不在白名单（如二进制、可执行文件、图片类）
    - When: HTTP 工具处理响应
    - Then: 不返回原始内容，返回可读提示（说明返回了不支持的类型）；白名单类型（text/html、text/plain、application/json、application/xml 等）正常进入清洗流程

- [ ] **AC-S03**: HTML 可执行内容剥离
    - Given: 获取的 HTML 页面包含 script、iframe、object、embed 标签或事件属性（onclick 等）
    - When: HTTP 工具返回
    - Then: 可执行内容被剥离且正文文本保留；不应将脚本代码原样送入上下文

- [ ] **AC-S04**: 内容级危险协议限制
    - Given: HTML 内容中包含 javascript:、data:、vbscript: 等危险协议的资源引用
    - When: 清洗执行
    - Then: 危险协议引用被移除，http/https 及相对路径等安全引用保留

- [ ] **AC-S05**: 可疑指令分级处置
    - Given: 工具结果中嵌入可疑指令模式
    - When: 清洗检测命中
    - Then: 一般可疑（指令诱导类特征）→ 保留原文 + 警示标记；高危（伪造系统提示词/诱导调用敏感工具）→ 移除该片段 + 占位标记；不应出现"一般可疑即删除"的过度清洗

- [ ] **AC-S06**: 统一包裹边界声明
    - Given: 任一数据获取工具产出结果
    - When: 结果进入 LLM 上下文
    - Then: 产出被"外部数据、非指令"边界声明包裹，声明指明数据来源工具；模型不执行工具结果中的指令（声明 + 分级处置 + 现有权限体系共同构成纵深防御）

- [ ] **AC-S07**: 清洗动作安全日志
    - Given: 任一清洗动作发生（剥脚本/标注入/移除高危/截断/降级）
    - When: 动作执行
    - Then: 记录 WARN 级安全日志，含工具名、命中规则、截断统计；不应向前端暴露清洗细节或打断对话

- [ ] **AC-S08**: 现有安全机制保持不变
    - Given: 现有 SSRF 防护、路径白名单、工具权限裁决体系
    - When: 本次优化上线
    - Then: 三者行为不变（回归验证通过）；不应出现加固引入的安全机制回退

### 7.4 边界与降级 (Edge Cases & Fallback)

- [ ] **AC-E01**: 临时文件写入失败降级
    - Given: 超长结果需写临时文件但写入失败（磁盘满/权限）
    - When: 工具返回
    - Then: 降级为纯截断（保留截断声明），对话不中断，记录降级日志

- [ ] **AC-E02**: 清洗层异常不阻断工具结果
    - Given: 清洗/包裹/限长环节自身抛出异常
    - When: 异常发生
    - Then: 跳过清洗返回原始结果并记录 ERROR 日志；不应因清洗层缺陷导致工具结果丢失或 ReAct 循环中断

- [ ] **AC-E03**: 工具执行失败提示保持
    - Given: 工具本体执行失败（超时/连接失败等）
    - When: 异常发生
    - Then: 仍按现有行为返回错误信息字符串（沿用 AC-012），清洗层不吞掉、不改写工具错误

- [ ] **AC-E04**: 清洗规则误命中容忍
    - Given: 正常内容中恰含可疑特征词（如知识库文档本身在讨论提示注入话题）
    - When: 分级处置生效
    - Then: 内容按"一般可疑"保留 + 标记，正文不丢失；不应因误命中导致数据残缺

### 7.5 记忆与上下文 (Memory & Context)

- [ ] **AC-M01**: 包裹声明一次性写入
    - Given: 工具结果已包裹边界声明并随消息持久化到会话历史
    - When: 会话恢复/断点续执行重放历史消息
    - Then: 历史中的工具结果不重复包裹（声明只出现一次）；不应出现嵌套声明导致上下文膨胀

- [ ] **AC-M02**: 历史结果不重算
    - Given: 会话历史中已存在按旧规则清洗的工具结果
    - When: 清洗规则后续升级
    - Then: 历史消息保持原样，仅新工具结果按新规则处理

### 7.6 人机协作 (Human-in-the-Loop)

- [ ] **AC-H01**: 高危注入的权限兜底
    - Given: 高危注入内容未被完全清除并诱导模型发起敏感工具调用
    - When: 模型发起 ASK/DENY 级工具调用
    - Then: 由现有权限确认机制拦截（ASK 弹确认卡片由用户裁决，DENY 直接拒绝）；清洗层本身不应中断对话或直接转人工

### 评估方式
* **自动评估**：注入 payload 单测用例集——每条安全 AC 至少 1 个正例（攻击应被拦截/标记）+ 1 个反例（正常内容应原样保留）；截断/临时文件行为断言。
* **手动评估**：构造含注入指令的网页、文档、MCP 返回值，端到端验证 Agent 不执行工具结果中的指令；验证超长内容的前缀 + 分段查询链路可用。
* **通过标准**：安全类 AC 全部通过；正常内容零误杀（反例全部原样保留）；回归验证现有安全机制（SSRF/路径白名单/权限）行为不变。

## 8. 范围界定 (Scope)

### 8.1 本次范围（In Scope）
* 4 类数据获取工具（HttpTool、FileReadTool、MCP 动态工具、RAG 知识库检索）产出清洗；
* HTML 防御链：请求级协议白名单、MIME 白名单、可执行内容剥离、内容级危险协议限制；
