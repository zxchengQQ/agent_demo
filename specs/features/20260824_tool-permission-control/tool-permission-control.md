## 1. 背景与价值 (Context & Value)

*   **背景**：当前单 Agent 工具调用链路（`ToolRegistry` → `SessionToolResolver` → LLM Function Calling → `ToolExecutor`）缺少权限控制，存在双重缺陷：
    *   **加载期无过滤**：Agent 构建工具列表时无法按"当前 Agent 可执行性"筛选工具，所有注册工具对 LLM 一视同仁；
    *   **执行期无校验**：LLM 决定调用工具后 `ToolExecutor` 反射直调，无任何权限门槛，工具是否执行完全取决于 LLM 的自主决策。
*   **目标**：为工具调用链路引入 **allow / ask / deny 三级权限模型**，实现"加载期过滤（deny 不可见）+ 执行期管控（allow 直执行 / ask 人工确认 / deny 兜底拦截）"双重控制。
*   **关联**：工具调用模块（`specs/modules/工具调用模块-业务说明书.md`）；复用 HITL 人机交互基础设施（`20260820_agent-human-interaction`）；工具按需加载机制（`2026-08-12_Agent工具按需加载`）。

## 2. Agent 角色定义 (Agent Persona)

### 2.1 身份定位

*   **角色名称**：单 Agent（SimpleAgent / UnifiedChatStream）——本功能不新增 Agent，为现有 Agent 的工具权限管控增强
*   **角色类型**：混合型（对话 + 任务，ReAct 循环）
*   **身份描述**：Agent 在权限模型约束下执行工具调用：allow 工具自主执行，ask 工具经用户确认后执行，deny 工具不可见不可调
*   **核心价值**：将工具执行的自主权从"LLM 全权决策"收敛为"按风险分级的受控自主"，高风险操作必须经人工确认

### 2.2 目标用户与场景

*   **目标用户**：
    *   **管理员**：在工具管理页为每个工具配置/调整权限等级
    *   **普通用户**：在对话中触发 ask 确认卡片，行使批准/拒绝权
*   **使用场景**：
    *   管理员封禁危险工具（deny），防止 LLM 被诱导调用
    *   用户对 Http/FileRead 等有副作用的工具调用进行人工把关
    *   只读安全工具（计算器/时间/知识库检索）无感直行，不增加交互负担
*   **交互风格**：ask 确认卡片复用现有 HITL 卡片范式（文本/选项卡片），风格保持一致

## 3. 能力边界与自主性 (Capability & Autonomy)

### 3.1 能力清单（In Scope）

*   全局工具级三等级权限配置（allow / ask / deny），管理页可视化调整，持久化存储
*   新工具注册时按风险分级自动分配默认权限
*   加载期过滤：deny 工具不注入 LLM 工具列表（所有对话路径）
*   执行期管控：allow 直接执行；ask 触发 HITL 暂停-恢复确认；deny 执行器兜底拦截
*   ask 拒绝结果回填 LLM，由 LLM 自主调整后续方案
*   前端适配：工具管理页展示权限等级；对话页工具选择器隐藏 deny 工具

### 3.2 能力禁区（Out of Scope）

*   LLM 不得调用 deny 级工具——加载期不可见 + 执行期兜底拦截，双保险
*   LLM 不得在用户拒绝 ask 确认后以完全相同参数立即重试同一工具
*   权限配置不可被对话内容（含提示注入）动态修改——配置仅管理员通过管理页变更
*   同步对话路径不得执行 ask 级工具（无暂停能力，加载期即排除）

### 3.3 自主性级别

*   **级别**：按工具粒度细化的混合级别
    *   **allow 工具 = L3（自主执行）**：LLM 决策即执行，结果回填继续推理
    *   **ask 工具 = L2（确认后执行）**：LLM 提出调用方案，用户批准后执行；拒绝则回填调整
    *   **deny 工具 = 禁区**：LLM 无感知（工具列表中不存在）
*   **说明**：三等级权限模型的本质是将自主性从全局单一级别细化为按工具风险粒度配置，与工具风险分级（3.4 节）对齐
*   **人类介入点**：ask 级工具被 LLM 调用时，暂停等待用户批准/拒绝

### 3.4 知识边界

*   **知识范围**：权限模型仅约束工具调用行为，不改变 Agent 的知识范围（LLM 自身知识 + 工具数据 + 知识库检索）
*   **超出边界处理**：与现状一致；工具被 deny 后 LLM 因"工具不存在"无法完成相关任务时，由 LLM 向用户说明能力受限

## 4. 工具与动作空间 (Tools & Action Space)

### 4.1 工具清单与默认权限分级

| 工具名称 | 用途 | 副作用 | 默认权限 | 分级依据 | 现有安全机制 |
|---------|------|--------|---------|---------|-------------|
| calculator | 数学计算 | 无 | **allow** | 只读安全 | 纯计算无外部交互 |
| time | 时间查询 | 无 | **allow** | 只读安全 | 纯查询 |
| kbTool_{kbId}（知识库工具） | 知识库检索 | 无 | **allow** | 只读检索 | 仅读取已授权知识库 |
| http | HTTP 请求 | 有 | **ask** | 外部交互不可控 | SSRF 防护 + 响应截断 |
| fileRead | 文件读取 | 有 | **ask** | 敏感数据访问 | 目录白名单 |
| MCP 工具（动态注册） | 外部能力调用 | 有 | **ask** | 外部不可控 | 依赖 MCP Server 侧约束 |
| askUser | HITL 向用户提问 | 无 | **allow（豁免）** | 交互工具本身 | 权限模型固定豁免，防确认死锁 |

> **deny 不设默认值**：deny 仅作为管理员手动封禁手段，任何工具类别注册时不默认 deny。

### 4.2 工具间关系

*   **依赖关系**：与现状一致（如知识库检索结果供 LLM 综合作答）
*   **互斥关系**：无新增；deny 工具在加载期即被移除，不参与任何编排
*   **编排策略**：复杂任务的多工具编排中，若任一工具为 ask 级，则该环节触发确认；deny 工具导致的链路缺失由 LLM 感知"工具不存在"后自行调整

### 4.3 工具选择策略

*   LLM 仅能"看见"allow + ask 工具，选择策略不变（Function Calling）
*   ask 工具的调用决策由 LLM 发起，执行权由用户行使（批准/拒绝）
*   用户在对话页显式选择的工具（ToolSelector）仍需叠加权限过滤：deny 工具即使被选中也不注入（见 AC-M01）

## 5. 推理流程与记忆策略 (Reasoning & Memory)

### 5.1 推理模式

*   **主要模式**：ReAct（现状不变）
*   **模式增强**：ReAct 循环中工具执行环节插入权限判定——
    *   allow → 正常执行
    *   ask（流式路径）→ 拦截 → 暂停保存状态 → SSE 确认事件 → 用户批准 → resume 执行 / 用户拒绝 → 拒绝结果作为工具执行结果回填
    *   deny → 执行器兜底拦截，返回权限拒绝提示
*   **最大执行步骤**：与现状一致

### 5.2 澄清策略

*   **主动澄清条件**：ask 确认被拒绝后，LLM 可调用 askUser 向用户询问替代方案（现有 HITL 能力）
*   **自主推进条件**：allow 工具调用无任何额外确认，保持现有流畅度

### 5.3 短期记忆（对话内）

*   **上下文保留轮次**：与现状一致
*   **会话工具绑定缓存**：现有 `sessionToolIds` 会话缓存机制保留，权限过滤在缓存解析后叠加；权限配置变更后**下一轮对话生效**（本轮沿用已加载列表，避免会话中途工具突变）

### 5.4 长期记忆（跨会话）

*   **是否需要**：权限配置本身持久化（跨重启）；对话级无新增长期记忆

## 6. 护栏安全与降级策略 (Guardrails & Fallback)

### 6.1 内容安全规则

*   **必须拒绝的请求**：对 deny 工具的调用请求（无论来源是 LLM 正常决策还是提示注入诱导）
*   **标准拒绝提示**：返回权限拒绝信息（如"该工具已被禁止调用"），LLM 据此向用户说明无法完成
*   **敏感话题处理**：与现状一致，本功能不改变内容安全策略

### 6.2 幻觉防护

*   **回答依据**：与现状一致（工具数据 + 知识库 + LLM 知识）
*   **无结果处理**：deny 工具不可用导致的任务无法完成，LLM 应如实告知用户能力受限，不得虚构工具结果

### 6.3 敏感信息处理

*   **输入侧**：与现状一致
*   **输出侧**：权限拒绝提示不暴露权限配置细节（配置者、配置时间等），仅说明调用被禁止

### 6.4 工具失败降级

| 工具/场景 | 失败场景 | 降级策略 | 是否转人工 |
|------|---------|---------|-----------|
| deny 工具调用 | LLM 尝试调用（含注入诱导） | 执行器拦截，返回权限拒绝提示回填 LLM | 否 |
| ask 确认 | 用户拒绝 | 拒绝结果回填 LLM，LLM 自主调整方案 | 由 LLM 决定是否 askUser 追问 |
| ask 暂停中 | SSE 连接中断 | 复用现有 HITL 暂停-恢复机制，重进会话可恢复确认 | 否（用户自助恢复） |
| 同步路径 | ask 工具需求 | 加载期排除，LLM 无感知该工具 | 否 |

### 6.5 人机协作机制

*   **升级条件**：ask 级工具被 LLM 调用
*   **升级方式**：SSE ask 确认事件 → 前端确认卡片（工具名 + 描述 + 参数摘要 + 批准/拒绝操作）
*   **交接信息**：确认卡片需提供充分的决策上下文——工具名称、工具用途描述、调用参数摘要；批准后自动恢复执行，拒绝后走 6.4 拒绝降级

### 6.6 提示注入防护

*   **攻击识别**：本权限模型天然提供防护纵深——deny 工具对 LLM 不可见，注入诱导调用不存在的工具时 LLM 收到"工具不存在/权限拒绝"
*   **处理策略**：执行期 deny 兜底拦截是第二道防线，即使 LLM 被诱导生成对 deny 工具的调用请求，方法体也不会触发
*   **工具返回防护**：与现状一致；权限配置本身不受对话内容影响

### 6.7 权限与身份校验

*   **身份确认机制**：本功能为单用户演示系统，不引入用户鉴权；权限配置操作入口为设置页工具管理（管理员视角）
*   **防越权策略**：对话内容（含提示注入）不能修改权限配置，配置仅经管理页变更
*   **数据隔离**：不涉及多用户数据隔离

## 7. 验收标准 (Acceptance Criteria)

> **重要**：以下验收标准是后续 Prompt 工程、工具开发和评估测试的直接依据。每条 AC 使用 Given-When-Then 格式。

### 7.1 正常交互流程 (Normal Interaction)

- [ ] **AC-N01**: 工具管理页权限配置与持久化
    - Given: 全局工具级权限模型已启用
    - When: 管理员在工具管理页将某工具权限调整为 ask 并保存
    - Then: 配置持久化存储（服务重启后不丢失），页面正确回显当前权限等级；应支持三等级下拉切换；不应需要重启服务即可变更配置

- [ ] **AC-N02**: allow 工具直接执行
    - Given: 工具（如 calculator）权限为 allow
    - When: 流式对话中 LLM 决定调用该工具
    - Then: 工具直接执行，无用户确认环节，结果回填 LLM 继续推理；不应弹出任何确认卡片

- [ ] **AC-N03**: ask 工具批准后执行
    - Given: 工具（如 http）权限为 ask，用户处于流式对话
    - When: LLM 决定调用该工具
    - Then: Agent 暂停并保存执行状态，前端展示确认卡片（含工具名与参数摘要），用户批准后恢复执行该工具，结果回填 LLM；不应在批准前触发工具方法体

- [ ] **AC-N04**: 权限修改下一轮生效
    - Given: 会话进行中且工具列表已加载
    - When: 管理员将某工具权限从 allow 调整为 deny
    - Then: 当前会话本轮沿用已加载工具列表（不中途突变），下一轮对话或新会话按新配置构建工具列表；不应出现会话中途工具消失导致的 LLM 困惑

### 7.2 工具选择与调用 (Tool Selection & Invocation)

- [ ] **AC-T01**: deny 工具加载期过滤
    - Given: 工具（如 fileRead）权限为 deny
    - When: 任意对话路径（同步/流式/统一模式）构建 LLM 工具列表
    - Then: 该工具不注入工具列表，LLM 不可见、不可调用；不应在 tools 定义中出现该工具的任何痕迹

- [ ] **AC-T02**: 同步路径 ask 工具不加载
    - Given: 工具（如 http）权限为 ask
    - When: 用户使用同步 chat 接口对话
    - Then: 该工具不注入 LLM 工具列表（同步路径无暂停能力，不执行 ask 流程）；流式路径应正常加载并走确认流程

- [ ] **AC-T03**: 新工具默认权限分级
    - Given: 权限模型已启用
    - When: 新工具注册到 ToolRegistry（含动态注册的知识库工具/MCP 工具）
    - Then: 按风险分级自动分配初始权限——只读安全工具默认 allow、有副作用工具默认 ask、MCP 工具默认 ask、askUser 固定 allow；不应出现无权限状态的工具

### 7.3 安全与护栏 (Safety & Guardrails)

- [ ] **AC-S01**: 执行期 deny 兜底拦截
    - Given: 工具（如 fileRead）权限为 deny
    - When: 工具执行器收到对该工具的调用请求（含提示注入诱导 LLM 调用不可见工具的场景）
    - Then: 拒绝执行且工具方法体不被触发，返回权限拒绝提示回填 LLM；不应向 LLM 暴露权限配置细节

- [ ] **AC-S02**: ask 拒绝结果回填
    - Given: ask 确认卡片展示中
    - When: 用户选择拒绝
    - Then: 该工具方法体不执行，拒绝结果（如"用户拒绝了本次调用"）回填 LLM，LLM 自主调整方案（换工具/询问用户/告知无法完成）；LLM 不应以完全相同参数立即重试同一工具

- [ ] **AC-S03**: askUser 工具权限豁免
    - Given: 权限模型已启用
    - When: 构建 LLM 工具列表（含 HITL 模式自动补入）
    - Then: askUser 工具固定视为 allow，不受权限配置影响；不应因权限控制导致 HITL 确认流程本身死锁（确认操作本身需要确认）

### 7.4 边界与降级 (Edge Cases & Fallback)

- [ ] **AC-E01**: 动态注册工具权限继承
    - Given: 权限模型已启用
    - When: 用户新建知识库（触发动态工具注册）或添加 MCP Server（触发工具批量注册）
    - Then: 新工具按默认分级自动获得权限（知识库检索 → allow，MCP 工具 → ask）并立即按权限规则参与后续对话；删除知识库/MCP Server 时对应权限配置同步清理，不应残留孤儿配置

- [ ] **AC-E02**: ask 暂停电断恢复
    - Given: ask 确认暂停期间 SSE 连接中断
    - When: 用户重新进入会话
    - Then: 复用现有 HITL 暂停-恢复机制，确认卡片可重新展示，批准/拒绝操作仍有效；不应因中断丢失待确认的工具调用上下文

### 7.5 记忆与上下文 (Memory & Context)

- [ ] **AC-M01**: 会话工具选择与权限过滤叠加
    - Given: 用户在对话页通过 ToolSelector 显式选择工具集合并绑定会话
    - When: 构建本次对话的 LLM 工具列表
    - Then: 所选工具逐一经权限过滤——deny 工具即使被用户显式选中也不注入；ask 工具在流式路径正常注入并走确认流程；默认工具合并逻辑（默认不可排除）与权限过滤叠加生效

### 7.6 人机协作 (Human-in-the-Loop)

- [ ] **AC-H01**: ask 确认卡片信息完整性
    - Given: ask 级工具被 LLM 调用
    - When: 前端展示确认卡片
    - Then: 卡片包含工具名称、工具用途描述、调用参数摘要、批准与拒绝操作；批准后自动恢复执行，拒绝后走 AC-S02 流程；卡片样式与现有 HITL 确认卡片范式保持一致

- [ ] **AC-H02**: 权限等级前端可视化
    - Given: 管理页与对话页分别展示工具
    - When: 管理员/用户查看工具列表
    - Then: 工具管理页（管理员视角）展示全部工具及当前权限等级（可见可改）；对话页工具选择器（用户视角）隐藏 deny 工具（不可选）；两个视角各取所需，不应在对话页暴露被封禁工具

## 8. 范围界定 (Scope)

### 8.1 本次范围（In Scope）

*   全局工具级三等级权限模型（allow / ask / deny）核心机制
*   权限配置持久化存储与管理页可视化配置（下拉切换三等级）
*   新工具注册的默认风险分级（只读→allow / 副作用→ask / MCP→ask / askUser 豁免）
*   加载期过滤：deny 工具不注入（所有 Agent 对话路径）；同步路径 ask 工具不加载
*   执行期管控：allow 直执行、ask 触发 HITL 暂停-恢复确认（复用现有基础设施）、deny 执行器兜底拦截
*   ask 拒绝结果回填 LLM，LLM 自主调整
*   前端适配：工具管理页权限展示与调整、对话页 ToolSelector 隐藏 deny 工具、ask 确认卡片（复用 HITL 卡片范式）
*   覆盖路径：同步 chat、流式 chatStream、统一模式 UnifiedChatStream

### 8.2 不在本次范围（Out of Scope）

*   Workflow 工作流模块的工具权限管控——工作流有独立执行引擎，需额外适配，列入下期演进（可经 `ai-agent-evolution` 增量接入）
*   会话级/Agent 角色级权限覆盖（全局默认 + 会话临时调整的组合模式）——当前单 Agent 架构下全局工具级已满足，多角色场景待多 Agent 能力落地后再评估
*   参数级权限（如仅允许 FileRead 读取特定目录）——现有目录白名单已提供部分防护，参数级权限作为远期演进
*   权限审计日志（谁在何时变更了权限、deny 拦截记录）——演示场景优先级低，列入远期
*   权限配置的导入/导出、批量操作——管理页逐工具调整已满足当前规模

### 8.3 评估方式与通过标准

| 评估类别 | 方式 | 通过标准 |
|---------|------|---------|
| 自动化（后端单元测试） | 覆盖默认分级逻辑、加载期过滤、执行期拦截、ask 暂停恢复、拒绝回填 | 全部测试通过（`mvn test -pl {模块} -am`） |
| 手动验收（管理页） | 调整工具权限等级 → 重启服务 → 验证配置保留 | AC-N01 |

| 手动验收（路径差异） | 同步 chat 与流式 chat 分别对话，对比 ask 工具可见性 | AC-T02 |
| 手动验收（动态工具） | 新建/删除知识库，验证权限继承与清理 | AC-E01 |
