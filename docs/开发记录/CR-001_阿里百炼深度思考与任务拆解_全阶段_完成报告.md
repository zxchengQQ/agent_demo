## 六、关键技术决策

### 6.1 接口设计

`ThinkingStreamingChatModel` 接口包含两个方法：
- `stream(List<ChatMessage>, ThinkingStreamHandler)` — 单轮思考流式
- `stream(List<ChatMessage>, String toolsJson, ThinkingStreamHandler)` — ReAct 思考流式

**为何不抽象为更宽的接口**：保持接口最小化，避免引入不需要的抽象成本。`ThinkingStreamHandler` 已经统一了回调契约。

### 6.2 百炼实现策略

与方舟实现采用**完全相同的策略**：原生 `HttpURLConnection` 直连，手动解析 SSE 流。

**关键差异**（CR-001 解除原限制的核心）：
- 请求体**不发送** `thinking.type=enabled` 字段——百炼 DeepSeek 模型通过模型名称自身触发思考能力
- Base URL 使用阿里百炼 OpenAI 兼容协议地址 `/compatible-mode/v1`
- API Key 来源改为 `BailianProperties`

### 6.3 调用方适配

3 个调用方（TaskBreakdownStream、SimpleAgent、ReActThinkingStream、ArkThinkingTokenStream）全部将局部变量/字段类型从 `ArkThinkingStreamingChatModel` 改为 `ThinkingStreamingChatModel` 接口，**未修改任何业务逻辑**——这正是抽象接口带来的解耦价值。
