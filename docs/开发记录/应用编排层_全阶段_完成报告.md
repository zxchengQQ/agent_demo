## 5. 遇到的问题与解决方案

### 问题 1: `AgenticServices.agentBuilder()` beta API 方法签名不确定
- **原因**: langchain4j-agentic 为 beta 版本，需确认 `@Agent`/`TokenStream`/`AgentBuilder` 的包路径和方法
- **解决方案**: 通过 `jar tf` + `javap` 反编译本地 Maven 仓库 jar，确认 `@Agent`→`dev.langchain4j.agentic.Agent`、`TokenStream`→`dev.langchain4j.service.TokenStream`、`AgentBuilder` 支持 `streamingChatModel/tools/systemMessageProvider/build`
- **影响**: 无，桥接一次成功

### 问题 2: `response.content().text()` 旧 API 已废弃
- **原因**: 技术方案中的 `ChatResponse.content()` 为旧版 API，1.17.2 使用 `ChatResponse.aiMessage().text()`
- **解决方案**: 使用 `response.aiMessage().text()` 获取完整文本
- **影响**: 无

### 问题 3: `SseEmitter` 编译依赖缺失
- **原因**: `SseEmitter` 在 spring-webmvc 模块，agent-demo-app 未声明该依赖
- **解决方案**: app 模块 pom.xml 新增 `spring-webmvc` 依赖
- **影响**: 无

### 问题 4: mock TokenStream 链式 stubbing 触发 UnfinishedStubbing
- **原因**: TokenStream 多个回调方法返回 `TokenStream`，mock 链式 `when()` 嵌套导致 Mockito 状态异常
- **解决方案**: 创建真实 `TestTokenStream` 测试实现（实现 `onPartialResponse/onCompleteResponse/onError/start` 等），精确控制回调触发
- **影响**: 测试更稳定可控

### 问题 5: 超时阈值 5 分钟无法直接测试
- **原因**: 默认 `future.get(5, MINUTES)` 在单测中无法等待
- **解决方案**: 将超时阈值提取为构造器可注入字段（默认 5 分钟），测试注入 0 分钟
- **影响**: 无，生产默认值不变

### 问题 6: 既有 tools 模块测试失败（非本次改动）
- **原因**: `ToolSchemaConverter.java` 存在工作区未提交的先前会话改动，其测试 `ToolSchemaConverterTest` 3 个用例与实现不匹配（工具描述、前缀引导语）
- **解决方案**: 确认非本次功能引入（本次未触碰 tools 模块），通过过滤验证本次相关模块全部通过
- **影响**: 需单独处理该遗留问题（不属于本功能范围）
