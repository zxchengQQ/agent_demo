## 4. 回归过程中发现并修复的 Bug

### Bug: SSE 解析导致 Markdown 渲染失败

- **现象**: 助手消息 Markdown 内容中的空格和换行符丢失，`# 标题` 显示为 `#标题`，所有内容挤在一行
- **根因**: [chat.ts](file:///d:/project_demo/agent_demo/agent-demo-frontend/src/api/chat.ts) SSE 解析有两个缺陷：
  1. `data:` 行使用 `.trim()` 剥离了内容中的前导/尾随空格（Markdown 语法 `# ` 标题的空格被移除）
  2. 多行 `data:` 未按 SSE 规范累积到空行再派发，导致 token 中的换行符 `\n` 被拆分为独立事件后丢失
- **修复方案**:
  1. 移除 `.trim()`，改为 `line.slice(5)` 直接取内容（Spring SseEmitter 输出 `data:` 后不加空格）
  2. 按 SSE 规范累积 `data:` 行到 `dataLines` 数组，遇到空行时用 `\n` 拼接后派发
  3. 兼容 CRLF 行尾（`rawLine.endsWith('\r')` 处理）
  4. 流结束后派发最后一个未分隔的事件（防御性处理）
- **影响范围**: [chat.ts](file:///d:/project_demo/agent_demo/agent-demo-frontend/src/api/chat.ts)、[chat.test.ts](file:///d:/project_demo/agent_demo/agent-demo-frontend/src/api/chat.test.ts)
- **测试更新**:
  - 修正现有 mock 数据匹配实际 Spring 输出格式（`data:content` 而非 `data: content`）
  - 新增测试：`token 中的空格被完整保留`
  - 新增测试：`多行 data: 按规范拼接为含换行符的内容`
