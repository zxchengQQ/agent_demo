## 5. 遇到的问题和解决方案

### 问题 1: PSReadLine 控制台渲染 Bug

**问题描述**: PowerShell 5 存在 PSReadLine 渲染 Bug，长命令输出被乱码淹没，无法直接读取控制台输出。

**解决方案**: 所有命令通过 .ps1 脚本文件执行，命令输出重定向到文件（`> file.txt` 或 `| Out-File -FilePath file.txt`），然后用 Read 工具读取文件确认结果。

### 问题 2: T-22 类型测试的 RED 状态无法自动确认

**问题描述**: T-22 的测试属于"类型测试"，运行 vitest 时测试通过（vitest 运行时不做类型检查，对象字面量设置了 reasoning 属性就能通过），vue-tsc 也通过（tsconfig.json 中 `"exclude": ["src/**/*.test.ts"]` 排除了测试文件）。

**解决方案**: 任务说明已明确"T-22 已部分完成（测试已写，实现未做）"，RED 阶段已完成。类型测试的本质是确保类型定义符合需求，为后续任务（T-23、T-24）提供类型支持。直接进行 GREEN 阶段，修改 types/index.ts 使类型定义符合 CR-001 需求。

### 问题 3: T-23 streamChat 签名变更影响 ChatWindow.vue 调用方

**问题描述**: 修改 streamChat 函数签名后，vue-tsc 报告 `ChatWindow.vue(62,11): error TS2554: Expected 5 arguments, but got 4`。

**解决方案**: 根据接口变更全链路评估原则，更新 ChatWindow.vue 中的 streamChat 调用，添加 `false` 作为 enableThinking 参数保持现有行为（零回归）。ChatWindow 的完整适配（enableThinking 状态管理、onReasoning 回调）属于 T-28 的任务范围。

### 问题 4: vue-tsc 输出文件缓存问题

**问题描述**: 修改 ChatWindow.vue 后，vue-tsc 输出文件仍显示旧错误，但 VS Code 诊断显示无错误。

**解决方案**: Out-File 可能未正确覆盖旧文件。使用新文件名输出（t23-tsc-new.txt）或先删除旧文件再输出，确认 vue-tsc 实际无类型错误。VS Code 的 GetDiagnostics 工具是最可靠的类型检查结果来源。

### 问题 5: npm install 安全漏洞警告

**问题描述**: `npm install` 安装 marked 和 dompurify 后，报告 4 个安全漏洞（2 moderate, 1 high, 1 critical）。

**解决方案**: 漏洞来自间接依赖，不影响功能开发。DOMPurify 的白名单机制已提供 XSS 防护。后续可通过 `npm audit fix` 处理，但不在本次 CR-001 范围内。
