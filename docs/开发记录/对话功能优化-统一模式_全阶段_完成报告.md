## 5. 遇到的问题与解决方案

### 问题 1: 子任务级暂停-恢复（最高难度）
- **原因**: 子任务执行中模型调用 askUser 需暂停并保存完整拆解上下文
- **方案**: 子任务委托 HITLReActStream（DRY）；暂停时 saveInteraction（ReAct 上下文）+ attachBreakdownContext（tasks/currentTaskIndex/subtaskResults）；恢复时 loadInteraction→追加 Observation→续跑子任务 N→剩余→总结；恢复时重放 onPlan + 已完成子任务 onTaskComplete

### 问题 2: 四模式融合路由
- **方案**: Controller 层 hasPending 优先（不解析 /plan）→ /plan 解析（空内容友好提示不写记忆）→ forced 强制拆解（跳过判断）→ judge 规划判断（空列表直答/非空拆解）

### 问题 3: Maven 测试环境 JDK 不匹配
- **原因**: JAVA_HOME 指向 Java 8，而测试类为 Java 17 编译（class file 61.0）
- **方案**: 设 JAVA_HOME=D:\java\jdk-17.0.7；Oracle JRE 使用追踪文件被沙箱拦截→`JAVA_TOOL_OPTIONS=-Djdk.disableLastUsageTracking=true`

### 问题 4: .m2 中 agent-demo-app 构件过期导致 WorkflowControllerTest 失败
- **原因**: 本地仓库 app 构件（08-17）缺少 SupervisorDefinition/getSupervisor 等新类
- **方案**: 排除 mcp 模块后全 reactor 测试（`-pl '!agent-demo-mcp'`）用工作区源码构建依赖；确认 app 模块 git 零改动、与本功能无关

### 问题 5: curl 测试 JSON 中文乱码
- **原因**: PowerShell `Set-Content -Encoding ascii` 损坏非 ASCII 字符，导致模型误判"输入编码异常"而追问
- **方案**: 改用 `[System.IO.File]::WriteAllText(..., UTF8)` 写入请求体

### 问题 6: usage 估算低于 8.4 规划数
- **原因**: SimpleTokenEstimator 仅按字符估算"用户消息+最终回答"，不含 judge/思考 Token
- **结论**: 符合技术方案 8.4"估算基于 SimpleTokenEstimator 口径"设计；非缺陷，列为观测范围说明

## 7. 下一步建议（用户最终验收指引）

### 7.1 启动方式
1. 后端：`mvn -o spring-boot:run -pl agent-demo-bootstrap`（或运行 fat jar）
2. 前端：`npm run dev`（agent-demo-frontend）
3. 在设置页配置阿里百炼 API Key（环境变量 BAILIAN_API_KEY 已在本次验证中配置）

### 7.2 验收场景（对应 4 项待人工验收 AC）
- AC-T02: 触发 text 型 ask_user，卡片内嵌输入框填写提交 → Agent 恢复
- AC-T03: 触发 confirm 型 ask_user，垂直整行选项、hover 高亮、选中锁定
- AC-T04: 点"其他"展开自由输入 → 与点选等效回传
- 决策 7: 回答后刷新页面，卡片回看已答内容（localStorage 持久化）
- AC-H02: 等待态发送"取消"或点选取消选项 → 任务停止确认
- 双通道: 卡片回复与主输入框回复状态一致收敛

### 7.3 注意事项
- 当前已验证模型为阿里百炼 qwen3.7-plus（思考型）与 glm-5.2
- 模型在宽泛任务下会主动 askUser 澄清（HITL 设计行为），属预期
