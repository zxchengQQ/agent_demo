## 5. 遇到的问题和解决方案

### 问题 1：PowerShell 5 PSReadLine 渲染 Bug

- **现象**：长命令在 PowerShell 5 中被截断，mvn 输出被 PSReadLine 渲染乱码淹没，无法直接读取测试结果
- **解决方案**：用 .ps1 脚本文件执行 mvn 命令，运行后读取 surefire 报告文件（`target/surefire-reports/com.*.txt`）确认测试结果

### 问题 2：PowerShell 5 逗号参数解析问题

- **现象**：`-Dtest=TestClassA,TestClassB` 中的逗号被 PowerShell 解释为参数分隔符，导致 "Missing argument in parameter list" 错误
- **解决方案**：一次只运行一个测试类（单测试运行），或用引号包裹 `-pl` 参数值（多模块运行时）

### 问题 3：Spring BaseAgent 类型注入歧义（Task-21 关键问题）

- **现象**：AgentController 同时注入 BaseAgent 和 SimpleAgent 时，Spring 报 `NoUniqueBeanDefinitionException: expected single matching bean but found 2: BaseAgent#0, SimpleAgent#0`。原因是 SimpleAgent 实现了 BaseAgent 接口，导致 BaseAgent 类型有两个候选 bean。
- **尝试方案 1**：@Qualifier("agent") + @MockBean(name="agent")
  - 问题：生产环境中 SimpleAgent 的默认 bean 名称是 "simpleAgent"，没有名为 "agent" 的 bean，会导致生产环境启动失败
- **尝试方案 2**：@MockBean @Primary
  - 问题：@Primary 注解没有被正确应用到 @MockBean 创建的 mock bean 上，歧义未解决
- **最终解决方案**：AgentController 只注入 SimpleAgent（具体类型），不注入 BaseAgent 接口。SimpleAgent 实现了 BaseAgent 接口，chat()/chatStream()/chatThinkingStream() 均可调用，功能完全等价。生产环境只有一个 BaseAgent 实现（SimpleAgent），不会产生歧义。

### 问题 4：ArkThinkingTokenStream 模块归属

- **现象**：ThinkingStreamHandler 在 llm 模块，ThinkingTokenStream 在 agent 模块，llm 不依赖 agent，无法在 llm 模块创建同时访问两者的实现类
- **解决方案**：将 ArkThinkingTokenStream 放在 agent-demo-agent 模块（agent 依赖 llm，可同时访问 ArkThinkingStreamingChatModel 和 ThinkingTokenStream）
