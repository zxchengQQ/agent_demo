## 5. 遇到的问题和解决方案

### 问题 1: jsdom `getComputedStyle` 不反映动态内联样式变更

**现象**: T-26 中点击推理区块标题切换展开/折叠时，`isVisible()` 始终返回 `false`，即使内联 style 已从 `display: none` 变为 `display: block`。

**根因分析**: 通过调试脚本确认：
- 点击后 `isThinkingExpanded` 确实从 false 变为 true（icon 从 ▶ 变为 ▼）
- 内联 style 确实从 `display: none` 变为 `display: block`
- 但 `getComputedStyle(element).display` 仍返回 `none`（jsdom 缓存初始值）

`@vue/test-utils` 的 `isVisible()` 内部调用 `getComputedStyle(element)` 检查 `display` 属性，而 jsdom 24 的 `getComputedStyle` 不反映动态更新的内联样式。

**解决方案**:
- 组件层面：使用 `:style="{ display: isThinkingExpanded ? 'block' : 'none' }"` 替代 `v-show`（行为等效，但内联样式更明确）
- 测试层面：动态切换的验证从 `isVisible()` 改为 `attributes('style')` 检查内联样式（更直接、更可靠，绕过 jsdom 的 `getComputedStyle` 缓存问题）
- 初始状态的验证保留 `isVisible()`（初始渲染时 `getComputedStyle` 返回正确值）

### 问题 2: PowerShell PSReadLine 渲染 Bug

**现象**: PowerShell 5 控制台渲染 Bug 导致长命令输出被乱码淹没，无法直接读取测试结果。

**解决方案**: 严格遵循环境提示，所有命令通过 `.ps1` 脚本文件执行，输出重定向到 `.txt` 文件，然后用 Read 工具读取文件确认结果。全量测试使用 `cmd /c "npx vitest run > file.txt 2>&1"` 方式（PowerShell 的 `| Out-File` 管道对大量输出有缓冲问题）。
