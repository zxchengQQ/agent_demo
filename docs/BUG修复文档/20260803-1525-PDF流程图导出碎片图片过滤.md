- 严重级别：中
- 影响范围：CR-002 PDF 图片提取功能；上传 process.on 等流程图软件导出的 PDF 时，会提取出大量无意义碎片图片（背景块、节点框、边框）并送入视觉模型，浪费 Token 且描述无意义

## 问题描述
- 期望结果：流程图软件导出的 PDF（单页嵌入大量碎片图片，如背景块、流程图节点框、边框、分隔线）应被识别并整体过滤，不送入视觉模型进行 OCR/摘要
- 实际结果：当前 ImageExtractor 对所有嵌入图片无差别提取，process.on 导出的 PDF 在单页产生 56 张碎片图片（page1_img0 至 page1_img55），全部送入视觉模型生成无意义描述，浪费大量 Token

## 定位过程
- 关键线索：用户反馈流程图导出 PDF 产生的图片是"页面背景色和流程图元素框"；通过 PowerShell + System.Drawing 分析示例图片目录，确认 56 张图片中存在大量纯色背景（Colors=1）和细长边框，且单页图片数量异常多
- 排查路径：
  1. 列出示例目录 `data\rag\temp\images\114bc92d18fc46b1b4602a3bb1c776b2\`，发现 page1 共 56 张图片，page2 同样 56 张且与 page1 完全相同
  2. 分析图片元数据：发现 page1_img0 是 1955×5897 的单色图片（页面背景），9 张低色彩图片为纯色装饰元素
  3. 检查 [ImageExtractor.java](file:///d:/project_demo/agent_demo/agent-demo-splitter/src/main/java/com/agentdemo/splitter/splitter/image/ImageExtractor.java) 当前实现，确认无任何过滤逻辑
  4. 分析过滤策略：
     - 方案 A：颜色丰富度过滤（Colors < 阈值）— 能去掉 9 张低色图片，但流程图节点图标（Colors 60-76）仍会被保留
     - 方案 B：尺寸过滤（宽高 < 阈值）— 能去掉小图标，但 180x120 节点图标仍会被保留
     - 方案 C：单页图片数量过滤（数量 > 阈值）— 能精准命中"流程图导出"碎片化场景，整页跳过
- 根因说明：流程图软件导出 PDF 时将每个流程图元素（背景、节点框、边框、连接线）作为独立的图片对象嵌入，导致单页图片数量异常多（数十张）。这种碎片化场景下，单张图片单独 OCR/摘要无意义。当前 ImageExtractor 缺少对这种碎片化场景的识别和过滤。

## 修复方案
- 修改点说明：
  1. **SplitterProperties.PdfChunkConfig 新增 maxImagesPerPage 配置项**：单页图片数量上限，默认 15。可通过 `rag.splitter.pdf.max-images-per-page` 调整
  2. **ImageExtractor 注入 SplitterProperties**：构造函数新增 SplitterProperties 依赖，用于读取 maxImagesPerPage 阈值
  3. **碎片化过滤逻辑**：在 extractImages 方法中，先收集每页所有图片到临时列表，再判断数量：
     - 若 pageImages.size() > maxImagesPerPage：记录 INFO 日志说明跳过原因，清理已保存到磁盘的图片文件，跳过该页所有图片
     - 否则：将图片加入返回列表
  4. **磁盘清理**：跳过的碎片化页面，已保存的图片文件通过 `Files.deleteIfExists()` 清理，避免残留占用存储
  5. **配置兜底**：maxImagesPerPage 配置缺失或为 0 时，回退到默认值 15，确保过滤逻辑始终生效
- 影响评估：
  - 影响范围：仅 ImageExtractor 的提取行为，不影响文本分块、向量化、检索等流程
  - 行为变化：单页图片数 > 15 的页面不再产生图片描述分块（流程图导出 PDF 受影响）；正常 PDF（单页图片数 ≤ 15）行为不变
  - 向后兼容：方法签名不变，调用方无需修改
- 风险点：
  1. 阈值 15 可能在某些场景下误杀：如 PDF 是图文并茂的报告，单页含 16+ 张有意义的图表/截图。可通过调大 max-images-per-page 配置规避
  2. 现有已提取但未清理的碎片图片目录（如 114bc92d18fc46b1b4602a3bb1c776b2）需手动清理，新逻辑仅对后续上传生效
  3. 阈值固定不区分图片内容质量：未来可考虑结合颜色丰富度+尺寸综合判断（当前先用最简方案解决用户痛点）
- 回滚方案：将 max-images-per-page 配置为极大值（如 999999）即可禁用过滤；或恢复 ImageExtractor.java 至修复前版本
