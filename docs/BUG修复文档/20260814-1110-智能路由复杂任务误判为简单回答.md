# BUG 修复报告

## 基本信息
- 日期：2026-08-14
- 报告人：AI Assistant
- 模块/功能：智能路由工作流（SmartRoutingTemplate，P2 CONDITIONAL 模式）
- 严重级别（低/中/高）：**高**
- 影响范围：所有使用"智能路由"模板执行复杂任务请求的用户
- 严重级别依据：功能逻辑错误（复杂问题被路由到简单回答分支，输出无意义回复），阻断该模板的核心价值（自动路由），且无法通过配置绕过

## 问题描述
- 期望结果：输入复杂任务请求（如"帮我分阶段进行机器学习中分类、回归、聚合三个场景的算法模型的调研，然后给出一份总结报告给我"）应命中"复杂拆解"分支，走研究→分析→总结多 Agent 协作。
- 实际结果：被误判为"简单回答"分支，仅输出简单回答 Agent 的固定回复"您好，您似乎没有附上具体问题。请提供您想询问的内容，我会直接给出简洁准确的回答。"，未进行任务拆解和执行。

## 复现步骤（必须可复现）
1) 启动应用，进入前端"编排"页面
2) 点击"智能路由"模板卡片，进入执行视图
3) 在 question 参数输入：`帮我分阶段进行机器学习中分类、回归、聚合三个场景的算法模型的调研，然后给出一份总结报告给我`
4) 点击"执行"
5) 观察输出：未走复杂拆解，直接返回"您好，您似乎没有附上具体问题…"

## 复现环境
- 设备/系统：Windows / Java 17
- 应用版本/配置：应用编排层 P2（smart-routing 模板）
- 相关依赖或外部条件：智能路由模板分支判定逻辑

## 定位过程
- 关键线索：输出为 QuickAnswerAgent 的提示词回复，说明命中了"简单回答"分支。
- 排查路径：
  1) 查看 SmartRoutingTemplate 分支判定：`isSimpleQuestion` = 长度 ≤ 80 **且** 不含复杂关键词
  2) 对用户输入计算：长度约 42（≤80）✓；复杂关键词集合为 `(为什么|如何|分析|对比|方案|设计)`，输入含"调研/总结报告"但**不含现有关键词** → 判定为简单问题
  3) 确认根因：复杂关键词集合过窄，未覆盖"调研/总结/报告/规划"等任务意图词，且未识别"帮我/请"任务引导前缀
- 根因说明：**复杂问题判定规则不完善**——仅靠长度 + 有限关键词，无法识别带任务意图（命令动词 + 任务词）但长度较短的问题

## 修复方案
- 修改点说明：增强 SmartRoutingTemplate 复杂问题判定
  1) 扩充复杂关键词：增加 `怎么|调研|总结|报告|综述|规划|制定|评估|研究|讨论|阐述|解释`
  2) 新增任务引导前缀识别：以 `帮我|请|麻烦|请你|我想请你|帮我进行|请帮我|请给我` 开头的问题一律视为复杂任务请求
  3) 逻辑简化为 `isComplexQuestion = !isSimpleQuestion`（二者严格互补，避免判定分叉）
- 影响评估：仅影响"智能路由"模板的分支路由判定；简单问题（短、无任务词、无引导前缀）仍走简单回答分支，行为不变
- 风险点：关键词/前缀为启发式规则，极端情况仍可能误判（后续可引入 LLM 路由）；关键词扩充可能将个别原本走简单分支的含"研究/解释"问题改路由到复杂分支（语义上更合理，属预期）
- 回滚方案：回退 SmartRoutingTemplate 的 COMPLEX_KEYWORDS/TASK_PREFIX/isSimpleQuestion 改动即可恢复原行为
