# BUG 修复报告

## 基本信息
- 日期：2026-08-03 14:45
- 报告人：AI 开发助手
- 模块/功能：agent-demo-splitter / ImageExtractor（PDF 图片提取）
- 严重级别：中
- 影响范围：CR-002 PDF 图片提取与向量化功能；上传含 PDF 的知识库时，每页都会被错误地渲染为图片送入视觉模型
  - 严重级别依据（是否阻断/可绕过/影响用户数）：非阻断（图片描述仍能生成，但语义偏差、Token 浪费严重）；影响所有上传 PDF 的用户；可绕过（关闭 extract-images 即可）

## 问题描述
- 期望结果：检查 PDF 中是否存在嵌入的图片对象（PDImageXObject），仅提取真正的嵌入图片；无图 PDF 不应提取任何图片；同页多图应分别提取，索引递增
- 实际结果：使用 `PDFRenderer.renderImageWithDPI()` 将 PDF 每页整页（含文字+图片）渲染为 PNG，导致：
  1. 无图 PDF（纯文字）也被误提取为图片
  2. 文字页面被送入视觉模型，浪费 Token 且描述失真
  3. 单页多图被合并为单张整页渲染图，丢失原图分辨率

## 复现步骤（必须可复现）
1) 构造一个 3 页空白 PDF（仅含 PDPage，无嵌入图片 XObject）
2) 调用 `ImageExtractor.extractImages(pdfBytes, "docId", tempDir, 144)`
3) 期望返回空列表（无嵌入图片），实际返回 3 个 ImageInfo（每页被整页渲染为 PNG）

## 定位过程
- 关键线索：用户反馈"提取图片"应针对 PDF 中嵌入的图片对象，而非整页渲染；查看 ImageExtractor.java 第 62 行发现 `renderer.renderImageWithDPI()` 是整页渲染 API
- 排查路径：
  1. 阅读 [ImageExtractor.java](file:///d:/project_demo/agent_demo/agent-demo-splitter/src/main/java/com/agentdemo/splitter/splitter/image/ImageExtractor.java) 确认实现方式
  2. 阅读类注释发现明确写有"提取策略：整页渲染（含文字+图片），而非仅提取嵌入图片对象"
  3. 检查现有测试，发现 `提取多页PDF返回对应数量的ImageInfo` 测试在空白 PDF 上期望返回 3 张图片，验证了 BUG 存在
  4. 调研 PDFBox 3.0 API：`PDResources.getXObjectNames()` + `PDImageXObject` 可遍历嵌入图片对象
- 根因说明：设计阶段错误选择了"整页渲染"策略（误以为视觉模型会区分文字和图片内容），未实现真正的"提取嵌入图片对象"语义

## 修复方案
- 修改点说明：
  1. **ImageExtractor 重写**：移除 `PDFRenderer.renderImageWithDPI` 整页渲染逻辑，改为遍历每页 `PDResources` 中的 XObject，对 `PDImageXObject` 直接调用 `getImage()` 提取原始图片，对 `PDFormXObject` 递归提取其内部嵌入图片
  2. **方法签名兼容**：保留 `extractImages(byte[], String, Path, int dpi)` 方法签名（dpi 参数标记为已废弃），避免破坏既有调用方 `DocumentService`
  3. **配置项废弃**：`SplitterProperties.PdfChunkConfig.imageDpi` 标记为 `@Deprecated`，application.yml 注释更新说明已废弃
  4. **测试重写**：新增 `createPdfWithImages()` 辅助方法构造含真实嵌入图片的 PDF，覆盖空白 PDF、单图、同页多图、多页多图等核心场景
- 影响评估：
  - 影响范围：仅 PDF 图片提取逻辑，不影响文本分块、向量化、检索等流程
  - 行为变化：无图 PDF 不再产生"假图片"分块；含图 PDF 按原始分辨率提取每张嵌入图片
  - 向后兼容：方法签名、配置项保留，调用方无需修改
- 风险点：
  1. Form XObject 递归深度无限制可能导致栈溢出（实际 PDF 中 Form 嵌套极少，且通过 visitedFormNames 去重已基本消除风险）
  2. 某些 PDF 使用 InlineImage（内联图片）而非 XObject，当前实现无法提取（PDFBox 提取内联图片需解析内容流，复杂度高，暂不处理）
  3. 提取的图片格式统一保存为 PNG（无损），可能比原图大；如需优化可保留原格式（JPEG/JBIG2 等）
- 回滚方案：恢复 ImageExtractor.java 至修复前版本（使用 PDFRenderer 整页渲染），同时恢复测试与配置注释
