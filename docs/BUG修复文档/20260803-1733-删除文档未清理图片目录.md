# BUG 修复报告

## 基本信息
- 日期：2026-08-03
- 报告人：AI Agent
- 模块/功能：RAG 文档管理 - 文档删除
- 严重级别（低/中/高）：中
- 影响范围：所有通过「删除文档」功能删除的 PDF 文档（含图片提取）的图片目录残留；非 PDF 文档不受影响
  - 严重级别依据（是否阻断/可绕过/影响用户数）：不阻断主流程，文档元数据/向量/分块均正常删除，仅磁盘图片文件残留，长期累积可能占满磁盘；当前为开发期内存存储，影响开发环境磁盘

## 问题描述
- 期望结果：删除文档时，该文档在 PDF 图片提取阶段生成的图片目录（`{tempDir}/images/{documentId}/`）及其下所有图片文件应被同步递归清理。
- 实际结果：`DocumentService.delete()` 仅清理了向量、分块、元数据、知识库计数，未清理图片目录，导致磁盘残留孤儿图片数据。复现时 `data/rag/temp/images/` 下存在 9 个孤儿目录，部分含图片文件（最多 109 张）。

## 复现步骤（必须可复现）
1) 启动应用（`.\start.ps1 -Provider ark -ApiKey 'ark-xxxx'`），配置 `rag.splitter.pdf.extract-images: true` 和有效的视觉模型
2) 创建一个知识库
3) 上传一个含图片的 PDF 文档，等待处理完成（状态变为 COMPLETED）
4) 观察 `data/rag/temp/images/{documentId}/` 目录已生成图片文件
5) 调用删除文档接口 `DELETE /api/rag/knowledges/{kbId}/documents/{documentId}`（或前端点击删除）
6) 检查 `data/rag/temp/images/{documentId}/` 目录
   - 期望：目录已被递归删除
   - 实际（修复前）：目录及图片文件依然存在

## 复现环境
- 设备/系统：Windows 10 Pro
- 应用版本/配置：JDK 17.0.7、Spring Boot、`rag.store-type: memory`、`rag.splitter.pdf.extract-images: true`
- 相关依赖或外部条件：PDF 图片提取功能（CR-002）已启用；视觉模型可选（未配置时图片描述跳过，但图片文件仍会提取保存）

## 定位过程
- 关键线索：
  1. 用户反馈删除文档后图片目录残留
  2. 磁盘检查 `data/rag/temp/images/` 发现 9 个孤儿目录，部分含图片文件（1~109 张不等）
- 排查路径：
  1. 定位 `DocumentService.delete(String documentId)` 方法（DocumentService.java:326-350），确认其清理步骤：删除向量 → 删除分块 → 删除元数据 → 递减计数，**无图片目录清理步骤**
  2. 对比 `deleteTempFile(String documentId)`（DocumentService.java:384），该方法仅删除 `{tempDir}/{documentId}` 临时文件本身，路径与图片目录 `{tempDir}/images/{documentId}/` 不同，不构成图片清理
  3. 确认图片目录创建逻辑在 `ImageExtractor.extractImages` 中：`imageDir.resolve(documentId)` 即 `{tempDir}/images/{documentId}/`（DocumentService.java:476-479）
- 根因说明：`delete()` 方法遗漏了图片目录清理步骤，图片提取与文档删除的资源生命周期未闭环。删除文档时图片目录成为孤儿数据。

## 修复方案
- 修改点说明：
  1. `DocumentService.delete()` 在删除文档元数据、递减计数后，新增调用 `deleteImageDir(documentId)` 清理图片目录
  2. 新增私有方法 `deleteImageDir(String documentId)`：递归删除 `{tempDir}/images/{documentId}/` 目录及其下所有文件
- 影响评估：
  - 仅影响文档删除流程，新增一次磁盘 IO（递归删除图片目录）
  - 容错：目录不存在时直接返回（非 PDF 文档或未开启图片提取时无该目录，属正常情况）
  - 容错：单个文件删除失败仅记 WARN 继续清理，整体 IOException 不阻断删除主流程（文档元数据已删除，图片残留仅占磁盘不影响功能）
- 风险点：
  - 递归删除路径计算依赖 `ragProperties.getDocument().getTempDir()`，路径错误可能误删其他目录。已通过单测验证路径拼接正确性（`{tempDir}/images/{documentId}/`）
  - 图片目录与文档元数据非原子删除，若 deleteImageDir 失败会留下孤儿目录，但不影响功能正确性
- 回滚方案：从 `delete()` 方法中移除 `deleteImageDir(documentId)` 调用并删除 `deleteImageDir` 方法即可回滚到修复前状态（图片残留但不影响功能）
