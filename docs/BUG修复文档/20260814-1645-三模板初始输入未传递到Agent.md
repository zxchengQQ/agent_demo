# BUG 修复报告

## 基本信息
- 日期：2026-08-14
- 报告人：AI Agent
- 模块/功能：应用编排层 P2 - 条件分支/循环/并行执行策略
- 严重级别：高
- 影响范围：质量评分-修订（LOOP）、智能路由（CONDITIONAL）、多角度审查（PARALLEL）三个预置模板均无法正常执行
 - 严重级别依据：阻断所有 P2 模板的核心功能，用户输入的任务内容完全丢失，Agent 收到空输入，无法绕过

## 问题描述
- 期望结果：用户通过前端输入任务参数（如 content/question），参数值应传递给首个 Agent 作为输入，Agent 执行实际任务并返回结果
- 实际结果：Agent 收到空字符串作为输入，LLM 回复"请提供具体的研究主题"或"请提供您的问题"等提示性回复，任务未执行

3) 点击执行，观察输出结果为"您好，您似乎没有附上具体问题。请提供您想询问的内容..."而非任务拆解结果

## 定位过程
- 关键线索：三个不同编排模式的模板都返回"请提供..."类回复，表明 Agent 收到的输入为空，而非路由判定错误（上一个 BUG 已修复路由判定）
- 排查路径：
  1. 检查 AgentExecutor.executeStreaming() → `executeMethod.invoke(agent, input)` → input 来源
  2. 检查 AbstractExecutionStrategy.executeAgentList() → `String currentInput = ctx.readAsString("lastOutput")` → lastOutput 来源
  3. 检查 ConditionalExecutionStrategy/LoopExecutionStrategy → `params.forEach(ctx::write)` 写入了 "question"/"content" 到 ctx，但未写入 "lastOutput"
  4. 检查 ParallelExecutionStrategy → `ctx.write("params", params)` 仅存到 "params" 键，未展开到 ctx 顶层，也未初始化 "lastOutput"
  5. 检查 WorkflowContext.readAsString() → key 不存在时返回空字符串 `""`
- 根因说明：`executeAgentList()` 和 `executeGroup()` 读取 `ctx.readAsString("lastOutput")` 作为首个 Agent 的输入，但 ConditionalExecutionStrategy、LoopExecutionStrategy、ParallelExecutionStrategy 三个策略在执行前均未将用户输入参数写入 "lastOutput" 键。导致首个 Agent 收到空字符串，@UserMessage 模板中的 `{{content}}`/`{{question}}` 占位符被替换为空，LLM 无法看到实际任务内容。

## 修复方案
- 修改点说明：
  1. 在 `AbstractExecutionStrategy` 新增 `initializeLastOutput()` 静态方法：从模板参数定义中查找首个 required string 参数，将其值写入 ctx 的 "lastOutput" 键
  2. 在 `ConditionalExecutionStrategy.execute()` 的 `params.forEach(ctx::write)` 之后调用 `initializeLastOutput()`
  3. 在 `LoopExecutionStrategy.execute()` 的 `params.forEach(ctx::write)` 之后调用 `initializeLastOutput()`
  4. 在 `ParallelExecutionStrategy.execute()` 中新增 `params.forEach(ctx::write)` 展开 params 到 ctx 顶层，并调用 `initializeLastOutput()`
- 影响评估：仅影响 CONDITIONAL/LOOP/PARALLEL 三种编排模式的首个 Agent 输入初始化，不影响 SEQUENTIAL（已独立读取 params.topic），不影响后续 Agent（由 executeAgentList 内部 lastOutput 链式传递）
- 风险点：ParallelExecutionStrategy 多分组共享 ctx 的 "lastOutput" 键存在并发写竞争，但首个 Agent 读取初始值时无竞争（此时无其他写操作），后续 Agent 的链式传递在并行模式下本身存在设计限制（不在本次修复范围）
- 回滚方案：删除 `initializeLastOutput()` 方法及三处调用即可
