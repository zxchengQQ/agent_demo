# BUG 修复报告

## 基本信息
- 日期：2026-08-25
- 报告人：AI Agent
- 模块/功能：前端工作流执行视图 -- HITL（Human-in-the-Loop）人机交互
- 严重级别：高
- 影响范围：所有标注 @HumanCheckpoint 的工作流模板（研究-分析-总结、多角度审查、质量审查循环）执行时，前端无法显示确认 UI，用户无法操作确认，页面卡住
- 严重级别依据：阻断用户操作（无法确认/拒绝检查点），导致工作流无法继续执行；影响所有含 @HumanCheckpoint 注解的模板

## 问题描述
- 期望结果：执行带 @HumanCheckpoint 注解的工作流时，Agent 执行前应暂停并弹出确认卡片（ConfirmCard），用户点击"批准"后恢复执行，点击"拒绝"后终止
- 实际结果：后端正确进入 WAITING_USER 状态并推送 workflow_waiting 事件，但前端页面卡住，无确认 UI 弹出，用户无法进行下一步操作

## 复现步骤（必须可复现）
1) 启动后端（端口 8080）和前端开发服务器（端口 5173）
2) 在前端选择"研究-分析-总结"模板
3) 在参数输入框输入"神经网络学习"
4) 点击"执行"按钮
5) 等待约 30 秒（Agent 构建后触发检查点暂停）
6) 观察：页面无确认卡片弹出，无"批准/拒绝"按钮可操作
7) 切换到"执行历史"页面，可看到执行状态为"等待确认"（WAITING_USER）

## 复现环境
- 设备/系统：Windows
- 应用版本/配置：后端 Spring Boot 3.2.5（JDK 17），前端 Vue 3 + Vite 5
- 相关依赖：ResearchAgent 标注 @HumanCheckpoint（Task-13 新增），SequentialExecuteView 为串行模式实际渲染组件

## 定位过程
- 关键线索：后端日志 `工作流 HITL 暂停（等待用户）: mode=checkpoint` 确认后端正确触发检查点
- 排查路径：
  1. 检查后端 handleHITLPaused -> 确认正确推送 ask_user + workflow_waiting 事件
  2. 检查前端 parseSseStream/handleWorkflowEvent -> 确认正确解析和分发事件
  3. 检查前端 useWorkflowStream.buildCallbacks -> 确认正确注册 onWorkflowWaiting 回调
  4. 检查前端 WorkflowExecuteView.vue -> 确认有等待横幅模板
  5. **关键发现**：发现存在 5 个模式特定的执行视图组件（SequentialExecuteView/ParallelExecuteView/LoopExecuteView/ConditionalExecuteView/SupervisorExecuteView）
  6. 检查 SequentialExecuteView.vue -> **发现该组件独立使用 useWorkflowStream，但没有解构 HITL 状态变量、没有等待横幅模板、没有 import AskUserCard/ConfirmCard**
- 根因说明：Task-12（前端 HITL 等待 UI）只修改了 WorkflowExecuteView.vue（通用执行视图），但实际路由到的是模式特定的执行视图组件（如 SequentialExecuteView）。这些组件没有 HITL 等待横幅，导致用户看不到确认 UI。此外 useWorkflowStream.startExecution 未重置 HITL 状态变量，可能导致重复执行时残留等待横幅

## 修复方案
- 修改点说明：
  1. SequentialExecuteView.vue -- 添加 HITL 状态变量解构、AskUserCard/ConfirmCard import、等待横幅模板、按钮逻辑调整、CSS 样式
  2. ParallelExecuteView.vue -- 同上修改（多角度审查模板的安全/性能 Agent 标注了 @HumanCheckpoint）
  3. LoopExecuteView.vue -- 同上修改（质量审查循环模板的修订 Agent 标注了 @HumanCheckpoint）
  4. SupervisorExecuteView.vue -- 同上修改（任务拆解模板的研究 Worker Agent 标注了 @HumanCheckpoint）
  5. ConditionalExecuteView.vue -- 同上修改（当前无 @HumanCheckpoint Agent，为一致性和未来扩展预防性添加）
  6. useWorkflowStream.ts -- startExecution 方法添加 HITL 状态重置（isWaitingUser/waitingHitlMode/waitingAgentName/askUserData）
- 影响评估：修改范围限于前端组件模板和 composable 状态重置，不影响后端逻辑和其他前端功能。全部 5 个模式特定执行视图已统一添加 HITL 等待横幅
- 风险点：无（所有模式特定执行视图均已覆盖）
- 回滚方案：恢复 6 个文件的修改即可
