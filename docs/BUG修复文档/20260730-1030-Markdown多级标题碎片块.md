# BUG 修复报告

## 基本信息
- 日期：2026-07-30
- 报告人：AI Agent
- 模块/功能：agent-demo-splitter / MarkdownDocumentSplitter 文档分割
- 严重级别：中
- 影响范围：所有 Markdown 文档的分割结果质量
  - 严重级别依据：不阻断核心功能，但导致 RAG 检索精度下降和向量存储碎片化，影响所有含多级标题的 Markdown 文档

## 问题描述
- 期望结果：Markdown 文档分割后不应存在仅含标题行（如"## 9. 优缺点"）的碎片块，所有分块应具有足够的语义内容
- 实际结果：当父标题（如 `## 9. 优缺点`）后面紧跟子标题（如 `### 优点`）时，父标题被分割为仅含标题行的独立分块，无实际内容，产生碎片化 chunk

## 复现步骤（必须可复现）
1) 准备一个含多级标题的 Markdown 文件，结构如下：
   ```
   ## 9. 优缺点

   ### 优点
   - Rust 性能优势
   - 本地优先

   ### 缺点
   - 无 RAG 能力
   ```
2) 上传该文件到知识库，触发文档分割
3) 查看分割结果，发现 "## 9. 优缺点" 作为独立分块，仅含标题行无内容

## 复现环境
- 设备/系统：Windows / JDK 17
- 应用版本/配置：agent-demo-splitter 1.0.0，rag.splitter.md.min-size=400
- 相关依赖：commonmark-java 0.21.0（Markdown AST 解析）

## 定位过程
- 关键线索：用户反馈分割结果中存在 "## 9. 优缺点" 这样的仅含标题的碎片块
- 排查路径：
  1. 分析 MarkdownDocumentSplitter.collectSections() 方法
  2. 发现该方法对所有层级的 Heading 节点都开新 Section
  3. 当父标题 `##` 后紧跟子标题 `###` 时，父标题 Section 仅有标题行（units.size()==1），无内容块
  4. 该碎片 Section 被 ChunkMerger 按 headerText 分组合并时，因 headerText 不同（"9. 优缺点" vs "优点"）无法合并
- 根因说明：
  - **根因 1**：collectSections 对所有 Heading 层级一视同仁，父标题下有子标题时产生仅含标题的空内容 Section
  - **根因 2**：ChunkMerger 按 headerText 分组合并，不同标题的短块无法跨组合并，碎片块无法消除

## 修复方案
- 修改点说明：
  1. **collectSections 携带父标题**：当当前 Section 仅有标题行（units.size()==1）时，不保存为独立 Section，而是将标题行携带到下一个子标题 Section 作为内容前缀
  2. **MarkdownDocumentSplitter 改为全局合并**：将 ChunkMerger 从按 headerText 分组合并改为全局合并，因为 collectSections 已保证 Section 语义完整性，全局合并不破坏结构边界
- 影响评估：仅影响 Markdown 文档的分割结果，不影响 PDF/TXT/Generic 分割器
- 风险点：全局合并可能将不同顶级章节的短内容合并，但这符合"避免 chunk 太小太碎"的核心目标
- 回滚方案：恢复 collectSections 的原始逻辑（所有 Heading 开新 Section）+ 恢复按 headerText 分组合并

## 变更内容
- 代码/配置改动摘要：
  1. `MarkdownDocumentSplitter.collectSections()`：新增 carriedHeading 逻辑，父标题仅有标题行时携带到子标题 Section
  2. `MarkdownDocumentSplitter.split()`：合并策略从 `chunkMerger.merge(result, minSize, maxSize, "headerText")` 改为 `chunkMerger.merge(result, minSize, maxSize)`（全局合并）
