# BUG 修复报告

## 基本信息
- 日期：2026-08-17 15:10
- 报告人：AI Assistant
- 模块/功能：agent-demo-llm（ModelFactory）/ 应用编排层预置工作流模板
- 严重级别（低/中/高）：高
- 影响范围：全部 5 个预置工作流模板（P1/P2/P3）执行必现失败，工作流功能完全阻断；对话/任务拆解等按 UUID 传模型的链路不受影响
 - 严重级别依据（是否阻断/可绕过/影响用户数）：工作流执行 100% 阻断，无绕过手段（换任何模型名配置均报错）

## 问题描述
- 期望结果：用户在"LLM 厂商模型配置"中添加 glm-5.2 后，执行"任务拆解-执行-汇总"（Supervisor）工作流应正常拆解、派发、汇总
- 实际结果：执行即报错 `Agent [任务拆解(主控)] 配置的模型不存在: glm-5.2`（此前配置 doubao-seed-2.0-pro 时报同样错误，说明与具体模型无关）

## 复现步骤（必须可复现）
1) 进入"设置 → LLM 配置"添加厂商并配置 chat 模型 glm-5.2
2) 进入"编排"页面，选择"任务拆解-执行-汇总"模板
3) 输入任意任务（如"调研分类算法"），点击"执行"
4) 观察响应：立即返回错误 `Agent [任务拆解(主控)] 配置的模型不存在: glm-5.2`（实际结果），而非期望的拆解→派发→汇总流程

## 复现环境
- 设备/系统：Windows / JDK 17 / Spring Boot 3.2.5
- 应用版本/配置：main 分支（P3 完成后），LLM 厂商模型配置（LlmConfigStore 动态配置版）
- 相关依赖或外部条件：无外部依赖（错误发生在模型实例创建前的查找阶段）

## 定位过程
- 关键线索：更换模型名（doubao-seed-2.0-pro → glm-5.2）后报错随之变化但仍报"不存在"，排除"模型未配置"假设，指向查找逻辑本身
- 排查路径：
  1. 报错文案定位到 `AgenticAgentFactory.buildAgent` → `ModelFactory.getStreamingChatModelByModelId(agentDef.getModelId())`
  2. `ModelFactory` 内部调用 `LlmConfigStore.getModel(modelId)`
  3. 读 `LlmConfigStore.getModel` 源码发现按 `model.getId().equals(modelId)` 匹配——**只支持模型记录 UUID**
  4. 对照对话链路：前端模型选择器存储并传递模型记录 `id`（UUID），所以对话正常
  5. 对照预置模板：`TaskBreakdownSupervisorTemplate`（及 P1/P2 全部模板）的 `AgentDefinition.modelId` 填的是 `ModelConstants` 中的 **API 模型名**（如 glm-5.2）
- 根因说明：**modelId 两种引用形式语义错位**。`LlmConfigStore.getModel` 仅按记录 UUID 查找，而预置工作流模板引用的是 API 模型名（modelName），UUID 查找必然未命中 → 抛 `LLM_MODEL_NOT_FOUND` → 被包装为"配置的模型不存在"。此前未暴露是因为 P1/P2/P3 全部测试（含 AgenticAgentFactoryTest、集成测试）均 mock 了 ModelFactory，预置模板从未与真实 LlmConfigStore 集成验证

## 修复方案
- 修改点说明：`ModelFactory` 新增私有方法 `resolveChatModel(modelId)`——记录 UUID 精确匹配优先，未命中时按 modelName + chat 类型兜底解析；`getChatModelByModelId` / `getStreamingChatModelByModelId` / `getThinkingStreamingChatModelByModelId` 三个方法统一走该解析。`LlmConfigStore` 配套新增 `getModelByName(modelName, type)`
- 影响评估：
  - 对话链路（传 UUID）：UUID 优先精确匹配，行为完全不变
  - 预置模板链路（传 modelName）：由必现失败修复为正常解析
  - embedding 模型名兜底不命中（限定 type=chat），类型安全不破坏
- 风险点：同名 chat 模型配置在多个厂商时，兜底返回首个匹配（与 getFirstChatModel 遍历顺序一致）；用户如需精确指定厂商应使用记录 UUID
- 回滚方案：还原 `ModelFactory.java` 三个方法体内的 `resolveChatModel(modelId)` 为原 `configStore.getModel(modelId)` + 判空逻辑，删除 `LlmConfigStore.getModelByName`
