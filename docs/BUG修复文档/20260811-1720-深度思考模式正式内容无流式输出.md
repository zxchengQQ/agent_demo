# BUG 修复报告

## 基本信息
- 日期：2026-08-11
- 报告人：AI Agent
- 模块/功能：深度思考模式（ReAct）- 正式内容（主回复区）流式输出
- 严重级别：高
- 影响范围：
  - 深度思考模式（ReAct）下，正式内容（主回复区最终答案）无流式输出，所有内容一次性出现
  - 影响所有使用深度思考模式的对话
  - 严重级别依据：显著影响深度思考模式的流式体验，用户反馈明确

## 问题描述
- 期望结果：
  - 深度思考模式下，【已思考】和【推理过程】流式显示（已正常），正式内容（主回复区最终答案）也应**逐字流式输出**
  - 工具调用轮的思考内容仅在【推理过程】区显示，不进入主回复区
- 实际结果：
  - 【已思考】和【推理过程】能流式输出，但正式内容（主回复区）无流式输出
  - 主回复区在收到 final-answer 事件后一次性显示最终答案

## 复现步骤（必须可复现）
1) 启动后端和前端服务
2) 开启"深度思考"模式（不开启任务拆解）
3) 输入一个需要多轮 ReAct 推理的问题（如"现在几点？然后计算 123*456"）
4) 观察：【已思考】和【推理过程】正常流式显示，但主回复区一直为空（显示"生成中..."）
5) 等待 ReAct 循环全部完成后，主回复区一次性出现完整最终答案

## 复现环境
- 设备/系统：Windows / 任意浏览器
- 应用版本/配置：agent-demo v1.0.0
- 相关依赖或外部条件：深度思考模式（ReAct）必现

## 定位过程
- 关键线索：主回复区无流式输出，一次性出现
- 排查路径：
  1. 定位 [AgentController.java](file:///d:/project_demo/agent_demo/agent-demo-web/src/main/java/com/agentdemo/web/controller/AgentController.java) 深度思考分支（L258-282），确认**未注册 `onPartialResponse`**，因此不发 `token` 事件
  2. 定位 [ReActThinkingStream.java](file:///d:/project_demo/agent_demo/agent-demo-agent/src/main/java/com/agentdemo/agent/single/ReActThinkingStream.java) 的 `onPartialResponse`（L77-81），为**空实现**，不保存 responseConsumer
  3. 分析 createHandler 的 `onPartialResponse`：所有轮 content 都推给 thoughtConsumer（推理过程区），主回复区无 token
  4. 前端 [ChatWindow.vue](file:///d:/project_demo/agent_demo/agent-demo-frontend/src/components/ChatWindow.vue) `onFinalAnswer` 调用 `moveThoughtToContent` 一次性填充 content
  5. 确认根因：ReAct 模式下 LLM content 全被路由为 thought 事件，主回复区 content 只在 final-answer 时一次性填充，无流式输出
- 根因说明：ReAct 模式后端不发 `token` 事件，正式内容（最终答案）无法流式推送到主回复区。主回复区依赖 final-answer 事件 + `moveThoughtToContent` 一次性填充

## 修复方案
采用"仅最终答案流式"方案（经用户确认）：主回复区逐字流式显示最终答案；工具调用轮的思考仅保留在【推理过程】区。

- 修改点说明：
  1. `ReActThinkingStream`：保存 `responseConsumer`；`IterationResult` 新增 `roundTokens` 收集该轮 content 的逐 token；`onPartialResponse` 逐 token 追加到 `roundTokens`；`onComplete` 时仅当 `finishReason=stop`（最终答案轮）将 `roundTokens` 逐 token 回放到 `responseConsumer`（主回复区）。工具调用轮 content 仅作为 thought，不进入主回复区
  2. `AgentController`：深度思考分支注册 `.onPartialResponse(token -> sendEvent(emitter, "token", token))`，将最终答案以 token 事件流式推送
  3. `ChatWindow.vue`：移除 `onFinalAnswer` 中的 `moveThoughtToContent` 调用（避免 content 重复追加，因为最终答案已通过 token 流式累积）
- 影响评估：
  - 主回复区：最终答案逐字流式显示（修复核心诉求）
  - 推理过程区：仍流式显示所有轮的 thought/action/observation，不变
  - 工具调用轮思考：不进主回复区，仅保留在推理过程区（符合"仅最终答案"）
- 风险点：
  - 最终答案轮的 content 会同时作为 thought（推理过程区）和 token（主回复区）显示，最终答案在两个区域都出现。这是"仅最终答案流式"的预期行为
- 回滚方案：
  - 恢复 ReActThinkingStream 的 `onPartialResponse` 空实现、`onComplete` 不回放
  - 移除 AgentController 的 `.onPartialResponse` 注册
  - 恢复 ChatWindow 的 `moveThoughtToContent` 调用
