# BUG 修复报告

## 基本信息
- 日期：2026-08-12
- 报告人：AI 开发助手
- 模块/功能：前端工具选择器（ToolSelector）
- 严重级别：中
- 影响范围：使用 MCP 工具且从"工具选择弹窗"勾选工具的所有用户
- 严重级别依据：不阻断核心对话流程（可通过 `mcp:*` 通配符加载），但无法从弹窗直观区分同一 MCP 服务器下的具体工具，影响工具选择的可用性与体验

## 问题描述
- 期望结果：工具选择弹窗中，同一 MCP 服务器下的多个工具应展示各自不同的工具名，便于区分和选择。
- 实际结果：同一 MCP 服务器下的多个工具在弹窗中展示的名字一模一样（均为服务器名），无法区分具体是哪个工具。

## 复现步骤（必须可复现）
1) 启动后端服务（连接 mermaid-mcp / fetch 等含多个工具的 MCP Server）。
2) 打开前端对话页，在输入框上方点击"＋ 添加"按钮打开工具选择弹窗。
3) 展开"MCP 工具"分组，观察同一服务器（如 fetch）下的多个工具项名称。

## 复现环境
- 设备/系统：Windows，Vue 3 + Vite 5 前端
- 应用版本/配置：agent-demo 1.0.0（工具按需加载功能）
- 相关依赖或外部条件：需连接含多个工具的 MCP Server（如 fetch 含 6 个工具）

## 定位过程
- 关键线索：弹窗中 MCP 工具显示名相同，而内置工具显示名正常。
- 排查路径：
  1. 后端 `ToolRegistry.getAvailableTools()` 返回的 `ToolInfo` 中，MCP 工具 `id` 为 `mcp:{serverName}`（所有同 server 工具相同），`name` 为完整方法名 `mcp_{serverName}_{toolName}`（唯一）。
  2. 前端 `ToolSelector.vue` 的 `displayName(id)` 对所有类别统一去掉 `category:` 前缀展示，导致 MCP 工具显示为 `serverName`，同一服务器下多个工具显示相同。
- 根因说明：前端展示逻辑用 `id`（`mcp:{serverName}`）而非 `name`（唯一方法名），MCP 工具 id 仅到服务器粒度，无法区分具体工具。

## 修复方案
- 修改点说明：前端 `ToolSelector.vue` 新增 `formatToolName(tool)` 展示方法——MCP 类别改用 `tool.name`（完整方法名，唯一可区分），其他类别沿用 `id` 去前缀；标签栏与下拉选项均改用该方法。原 `displayName(id)` 被替换为基于 `ToolInfo` 的展示。
- 影响评估：仅影响工具选择弹窗与标签栏的显示文案，工具选择逻辑（id 双向绑定）不变。
- 风险点：MCP 工具显示名变为完整方法名（如 `mcp_fetch_fetch_html`），较长但可区分，样式已在标签/选项中允许显示。
- 回滚方案：恢复 `displayName(id)` 即可回到原展示。

## 变更内容
- 代码/配置改动摘要：`ToolSelector.vue` 新增 `formatToolName` / `displayToolName`，模板中所有 MCP 类别展示改用 `formatToolName(tool)`。
- 相关文件：
  - `agent-demo-frontend/src/components/ToolSelector.vue`
- 回归风险/可能受影响模块：工具选择弹窗、输入框上方工具标签栏

## 单元测试
