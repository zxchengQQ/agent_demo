# BUG 修复报告

## 基本信息
- 日期：2026-07-24
- 报告人：AI Agent
- 模块/功能：任务拆解模式（CR-002）- 总结阶段
- 严重级别：高
- 影响范围：开启任务拆解模式后，所有对话的最终总结结果无法持久化到会话记忆，且在 emitter 超时场景下总结内容静默丢失
  - 严重级别依据：功能阻断（总结结果不可用）、影响所有任务拆解模式用户、不可绕过

## 问题描述
- 期望结果：任务拆解模式下，所有子任务执行完成后，总结阶段的回复应逐字推送到前端展示，并完整写入会话记忆供后续多轮对话使用
- 实际结果：子任务执行过程正常展示，但总结阶段回复未写入会话记忆；在 emitter 超时场景下，总结 token 事件被 `parseSseLine` 的 `catch(Exception)` 静默吞掉，前端收不到最终结果

## 定位过程
- 关键线索：用户反馈"子任务执行正常但最终结果不显示"，对比三条 SSE 流式路径（default / enableThinking / enableTaskBreakdown）的回调实现
- 排查路径：
  1. 对比 `AgentController.chatStream()` 三条路径的 `onPartialResponse`/`onSummaryToken` 和 `onComplete`/`onCompleteResponse` 回调
  2. 发现任务拆解路径 `onSummaryToken` 仅调用 `sendEvent` 推送前端，未执行 `fullResponse.append(token)` 累积回复
  3. 发现任务拆解路径 `onComplete` 仅发送 `done` 事件，未调用 `memoryManager.addAssistantMessage()` 写入记忆
  4. 发现 `sendEvent` 方法仅捕获 `IOException`，未捕获 `IllegalStateException`（emitter 超时/已完成时抛出）
  5. 追踪 `IllegalStateException` 传播路径：`emitter.send()` → `onSummaryToken.accept()` → `handler.onPartialResponse()` → 被 `parseSseLine` 的 `catch(Exception e)` 静默吞掉
- 根因说明：
  1. **记忆缺失**：`onSummaryToken` 未累积回复，`onComplete` 未写入记忆（其他两条路径均有此逻辑）
  2. **异常吞没**：`sendEvent` 仅捕获 `IOException`，当 emitter 超时后 `emitter.send()` 抛出 `IllegalStateException`，该异常传播到 `ArkThinkingStreamingChatModel.parseSseLine()` 的 `catch(Exception e)` 被静默吞掉，导致总结阶段的 `token` 事件全部丢失，前端只收到 `done` 事件（或连 `done` 也丢失）

## 修复方案
- 修改点说明：
  1. `onSummaryToken` 回调：增加 `fullResponse.append(token)` 累积总结回复（与默认路径 `onPartialResponse` 对齐）
  2. `onComplete` 回调：增加 `memoryManager.addAssistantMessage(effectiveSessionId, fullResponse.toString())` 写入记忆（与 enableThinking 路径对齐），并增加空内容保护
  3. `sendEvent` 方法：将 `catch (IOException e)` 改为 `catch (Exception e)`，防止 `IllegalStateException` 中断后续 SSE 事件推送
- 影响评估：仅影响任务拆解路径，不影响默认路径和深度思考路径
- 风险点：`catch (Exception e)` 范围扩大可能掩盖其他异常，但通过 `log.warn` 记录日志保证可追溯
- 回滚方案：将三处改动恢复为原始代码即可

  2. `AgentController.java` 第 272-279 行：`sendEvent` 捕获 `Exception` 替代 `IOException`，移除未使用的 `IOException` import
