# BUG 修复报告

## 基本信息
- 日期：2026-07-24
- 报告人：AI Assistant
- 模块/功能：复杂任务拆解 - 前端展示
- 严重级别（低/中/高）：高
- 影响范围：任务拆解模式下所有用户
  - 严重级别依据：最终总结结果不可见属于功能阻断，但可通过手动滚动绕过

## 问题描述
- 期望结果：任务拆解模式执行完成后，页面应显示最终总结结果（在任务列表下方的消息气泡中）；子任务执行详情内容应有限高度，页面美观
- 实际结果：
  1. 任务执行完成后，最终总结结果不可见（被高大的任务列表区块推出视口外，且完成后不自动滚动到总结位置）
  2. 子任务展开后 ReAct 步骤和工具结果内容超长，导致页面极度拉长，不美观

## 复现步骤（必须可复现）
1) 开启「复杂任务拆解」模式
2) 发送一个复杂任务消息（如"帮我调研 Vue3 和 React 的区别，并给出技术选型建议"）
3) 等待所有子任务执行完成
4) 观察：任务列表区块占据大部分屏幕，最终总结结果不可见
5) 展开 any 子任务详情，观察：ReAct 步骤和工具结果内容超长，页面被拉得很长

## 复现环境
- 设备/系统：Windows / 任意浏览器
- 应用版本：agent-demo v1.0.0 (CR-001 变更后)
- 相关依赖：CR-001 新增的子任务自动展开功能导致 task-block 在执行期间非常高

## 定位过程
- 关键线索：CR-001 变更新增了子任务自动展开 watcher，执行中 ReAct 详情全部展开导致 task-block 极高
- 排查路径：
  1. 检查前端 `onToken` 回调注册 -> 确认已注册，`store.appendContent` 正常调用
  2. 检查后端 `onSummaryToken` 回调 -> 确认正确发送 `token` SSE 事件
  3. 检查 `MessageList.vue` 滚动行为 -> 发现 `scrollToBottom` watcher 仅追踪 `message.content`，不追踪 `message.status`
  4. 检查 `global.css` `.subtask-detail` 样式 -> 无 `max-height` 限制，内容无限增长
- 根因说明：
  - **Bug1**: `MessageList.vue` 的流式滚动 watcher 仅监听 `content` 变化。任务完成时 `markComplete` 只改 `status` 不改 `content`，不触发 `scrollToBottom`。task-block 折叠后总结气泡在视口下方但不自动滚动到可见位置
  - **Bug2**: `.subtask-detail` 和 `.tool-result-text` 无 `max-height` 限制，CR-001 自动展开后 ReAct 步骤和工具结果可以无限增长

## 修复方案
- 修改点说明：
  1. **Bug1**: `MessageList.vue` watcher 追踪值从 `m.content` 改为 `${m.content}:${m.status}`，使 `markComplete` 触发 `scrollToBottom`
  2. **Bug2**: `global.css` `.subtask-detail` 添加 `max-height: 300px; overflow-y: auto;`
  3. **Bug2**: `MessageItem.vue` `.tool-result-text` 添加 `max-height: 150px; overflow-y: auto;`
- 影响评估：仅影响前端展示行为，不触及数据流、事件处理、后端逻辑
- 风险点：极低。滚动 watcher 扩展为更宽松的触发条件，不影响原有 content 变化触发的滚动
- 回滚方案：将 watcher 改回 `m.content`，移除 CSS `max-height` 属性
