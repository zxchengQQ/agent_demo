# BUG 修复报告

## 基本信息
- 日期：2026-08-27
- 报告人：AI Assistant（bugfix-workflow）
- 模块/功能：Skill 能力域（agent-demo-frontend ChatWindow）— 技能加载反馈交互
- 严重级别（低/中/高）：中
- 影响范围：选中技能（/skill 指令或技能选择器）后发送消息的用户反馈可见性
- 严重级别依据（是否阻断/可绕过/影响用户数）：不阻断功能（技能实际已加载），但用户无法感知"技能已加载"，影响核心交互体验；全部使用技能功能用户均受影响。

## 问题描述
- 期望结果：
  1. 选中技能后发送消息，用户能在对话框中直观看到"选择了什么技能 / 技能已加载"（文本反馈）。
  2. Agent 加载技能的过程可见、可确认。
- 实际结果：
  1. 技能加载反馈以**页面【已激活技能】元素/【指定技能】区块**展示（输入区上方的徽标/区块），而非对话框文本；用户明确要求改为对话框内文本展示。
  2. 用户观察到 ReAct 过程中**没有 `load_skill` 工具调用**，据此认为 Agent 未加载技能。

## 复现步骤（必须可复现）
1) 启动应用，进入对话页
2) 输入 `/skill 数据查询助手 帮我查数据`（或通过技能选择器选中"数据查询助手"）
3) 点击发送
4) 观察：页面出现【已激活技能】徽标/【指定技能】区块，但对话框消息流中没有"选择了哪个技能"的文本；ReAct 面板中无 `load_skill` 工具调用

## 复现环境
- 设备/系统：WSL2（Linux），前端 Chrome
- 应用版本/配置：agent-demo（agent-skill CR-001 之后）
- 相关依赖或外部条件：需已配置 LLM（ARK_API_KEY）

## 定位过程
- 关键线索：用户反馈"没有看到使用 load_skill 工具进行加载 skill"+"希望在对话框中以文本展示选择了什么技能"。
- 排查路径：
  1. 后端 curl 复现：`POST /api/agent/chat/stream` 携带 `skills=["data-query-assistant"]` → 日志确认"技能手动指定"、`skill_activated(manual)` 事件下发（`boundToolIds=[skill_data_query_assistant_http_get]`）、SkillScriptToolRegistrar 生成并注册脚本工具、"合并激活技能脚本工具: 脚本工具数=1"。**后端加载技能链路完整正常**。
  2. 前端链路：`sendMessage` 传 `selectedSkills` → `streamChat`（参数顺序正确）→ 后端 `applySkillSelection`。前端链路完整。
  3. 定位根因：手动指定技能（AC-N03）的设计是**直接注入激活段**——`applyManualSelection` 将指定技能写入 `activeSkillIds`，`SkillPromptComposer.composeActivatedSegment` 将技能指令全文注入系统提示词，脚本工具经 `SessionToolResolver.mergeSkillScriptTools` 注入工具集。该路径**确定性加载**，**不依赖/不经过 `load_skill` 工具调用**，因此 ReAct 中不会出现 `load_skill`——这是设计行为而非缺陷。
  4. 真正的用户痛点：技能加载的**反馈载体不直观**——只有页面元素（激活徽标/指定技能区块），对话框消息流内无反馈，用户无法确认技能已加载。
- 根因说明：反馈载体选择不当。技能实际已加载（指令注入 + 脚本工具注册），但缺乏对话框内文本反馈，导致用户感知为"未加载"。同时页面激活元素（Task-22 AC-S04 徽标栏、CR-001 指定技能区块）展示方式与用户期望不符。

## 修复方案
- 修改点说明：将技能加载反馈由"页面元素"改为"对话框文本"：
  1. `skill_activated` 事件回调中，技能**首次激活**时在对话框消息流插入文本消息"已加载技能：{skillName}"（重复 manual 事件去重，不重复插入）。
  2. 移除页面【已激活技能】徽标栏（activated-skills-bar）与【指定技能】区块（manual-skills-bar）及对应死代码（activatedSkillDetails / handleExcludeSkill / selectedSkillDetails / clearManualSkills 及样式）。
  3. 保留技能选择器入口（SkillSelector）与 /skill 指令错误提示（cmd-error）。
- 影响评估：
  - 正向：对话框内直观展示"已加载技能：X"，满足用户期望（Bug 2）；技能实际仍确定性加载（指令注入 + 脚本工具），功能不受影响。
  - 副作用：页面【已激活技能】徽标移除后，原"一键排除"入口（×按钮，AC-S04）不再有 UI 入口；排除逻辑（selectedExcludedSkills → streamChat excludedSkills）仍保留生效，可通过 SkillSelector 取消选中恢复自动模式。
- 风险点：
  - manual 激活事件每次请求都下发，若不防重会导致"已加载技能"文本重复插入——已用会话级激活集合（activatedSkillsBySession）判重。
  - 用户若坚持要求 ReAct 中出现 `load_skill` 工具调用（改变手动指定为"由 LLM 加载"），需另行变更手动指定语义（涉及 applyManualSelection / 提示词引导 / EDD 评估），本修复未改动该语义。
- 回滚方案：还原 ChatWindow.vue 的 skill_activated 回调与页面元素即可；无数据库/持久化变更。
