## 一、任务概述

搭建 Maven 多模块工程骨架，建立 11 个子模块的基础结构与统一依赖版本管理。本阶段不编写业务代码，仅产出 POM 文件与空包结构，确保整个工程可编译通过。

## 二、依赖关系

### 2.1 前置依赖
- 无（工程初始化的第一步）

### 2.2 被依赖（下游影响）
- **阶段二（common）**：需要在 common 模块目录下编写代码
- **阶段三（llm）~ 阶段八（bootstrap）**：所有业务模块依赖 bom 的版本管理
- 若本阶段未完成，后续所有阶段无法启动

## 四、子任务详情

### 4.1 任务 1.1：创建根 POM 与 BOM 模块

#### 子任务 1.1.1：创建根 pom.xml
- **目标**：建立 parent POM，声明所有子模块，统一 properties
- **实现要点**：
  - groupId: `com.agentdemo`
  - artifactId: `agent-demo`
  - packaging: `pom`
  - parent: `spring-boot-starter-parent:3.2.x`
  - properties: 统一声明 `java.version=17`、`langchain4j.version=1.16.0`、`project.build.sourceEncoding=UTF-8`
  - modules: 声明 11 个子模块
- **产出物**：`d:\project_demo\agent_demo\pom.xml`

#### 子任务 1.1.2：创建 agent-demo-bom 模块
- **目标**：集中管理所有第三方依赖版本，供其他模块 import
- **实现要点**：
  - packaging: `pom`
  - dependencyManagement: 声明 LangChain4j 全家桶、Milvus、MyBatis-Plus、springdoc 等
  - 不包含任何业务代码
- **产出物**：`agent-demo-bom/pom.xml`

### 4.2 任务 1.2：创建 11 个子模块骨架

#### 子任务 1.2.1：创建核心业务模块 pom.xml
- **目标**：为 common、llm、tools、memory、rag、mcp、agent、app 创建 pom.xml
- **实现要点**：
  - 每个 pom 声明 parent 为根 pom
  - 引入 agent-demo-bom（import）
  - 按架构文档 4.1 节声明模块间依赖
  - 依赖关系：
    - common: 无业务依赖
    - llm: 依赖 common + langchain4j-open-ai
    - tools: 依赖 common
    - memory: 依赖 common + llm
    - rag: 依赖 common + llm + langchain4j-milvus
    - mcp: 依赖 common + tools + langchain4j-mcp
    - agent: 依赖 common + llm + tools + memory
    - app: 依赖 agent + rag + mcp

#### 子任务 1.2.2：创建 web 与 bootstrap 模块 pom.xml
- **目标**：为 web、bootstrap 创建 pom.xml
- **实现要点**：
  - web: 依赖 app + spring-boot-starter-web + springdoc
  - bootstrap: 依赖 web（聚合全部），声明 spring-boot-maven-plugin

#### 子任务 1.2.3：创建各模块基础包结构
- **目标**：建立标准化的 Java 包结构
- **实现要点**：
  - 根包: `com.agentdemo`
  - 子包按模块命名: `com.agentdemo.common`、`com.agentdemo.llm` 等
  - 每个模块创建对应的子包目录（constant/enums/exception 等，按架构文档）
  - 创建空的 `package-info.java`（可选）
- **产出物**：11 个模块的 src/main/java 目录结构

### 4.3 任务 1.3：工程编译验证
- **目标**：验证整个工程骨架可编译
- **验证命令**：`mvn clean compile -DskipTests`
- **验证标准**：BUILD SUCCESS，无编译错误

## 五、关键接口设计

本阶段不涉及业务接口，但需约定以下规范：
- **包名规范**：统一 `com.agentdemo.<module>.<sub>`
- **版本规范**：所有版本通过 bom 统一管理，禁止业务模块直接声明版本
- **模块命名**：`agent-demo-<module>`

## 六、验证标准

| 验证项 | 验证方式 | 通过标准 |
|---|---|---|
| 目录结构 | 检查 11 个模块目录 | 全部存在 |
| POM 有效性 | `mvn validate` | BUILD SUCCESS |
| 编译通过 | `mvn clean compile` | BUILD SUCCESS |
| 依赖树 | `mvn dependency:tree` | 无冲突、无缺失 |
| IDE 识别 | IDEA 导入 | 所有模块识别为 Maven 模块 |

## 七、风险与注意事项

1. **Spring Boot 版本与 LangChain4j 兼容性**：确认 Spring Boot 3.2.x 与 LangChain4j 1.16 的依赖兼容，避免版本冲突
2. **JDK 17 要求**：LangChain4j 要求 JDK 17+，需在 properties 中显式声明
3. **BOM import 顺序**：Spring Boot BOM 与自定义 BOM 的 import 顺序，避免版本覆盖
4. **模块循环依赖**：严格按架构文档 4.1 节的依赖方向，禁止反向依赖
5. **Windows 路径**：构建在 Windows 环境，注意路径分隔符与编码（UTF-8）
