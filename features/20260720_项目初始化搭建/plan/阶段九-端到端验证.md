## 四、子任务详情

### 4.1 任务 9.1：环境准备检查

- **目标**：确认运行环境满足要求
- **检查清单**：
  - [ ] JDK 版本：`java -version` 输出 17 或以上
  - [ ] Maven 版本：`mvn -version` 输出 3.8+
  - [ ] 环境变量：`echo $env:ARK_API_KEY`（PowerShell）非空
  - [ ] 网络连通：`curl https://ark.cn-beijing.volces.com` 可访问
  - [ ] 端口可用：8080 未被占用
  - [ ] 套餐余额：火山引擎 Coding Plan 套餐未耗尽
- **产出物**：环境检查通过确认

### 4.2 任务 9.2：应用启动验证

- **目标**：验证应用正常启动
- **执行命令**：
  ```powershell
  mvn clean package -DskipTests
  java -jar agent-demo-bootstrap/target/agent-demo-bootstrap-1.0.0.jar
  ```
  或开发模式：
  ```powershell
  mvn spring-boot:run -pl agent-demo-bootstrap
  ```
- **验证点**：
  - 启动日志含 `Started AgentDemoApplication`
  - ArkProperties 加载成功，apiKey 非空
  - ToolRegistry 注册工具数 ≥ 4
  - ModelFactory 初始化成功
  - 端口 8080 监听
- **产出物**：启动日志截图

### 4.3 任务 9.3：同步对话验证

- **目标**：验证 `/api/agent/chat` 同步对话接口
- **测试命令**：
  ```powershell
  curl -X POST http://localhost:8080/api/agent/chat `
    -H "Content-Type: application/json" `
    -d '{"message": "你好，请介绍一下自己"}'
  ```
- **验证点**：
  - HTTP 状态码 200
  - 返回 JSON 含 `code: 200`
  - `data.content` 非空，为合理的自我介绍
  - `data.sessionId` 非空（保存用于后续测试）
  - `data.duration` 合理（< 30s）
- **产出物**：响应 JSON 截图

### 4.4 任务 9.4：流式输出验证

- **目标**：验证 `/api/agent/stream` SSE 流式接口
- **测试命令**：
  ```powershell
  curl -X POST http://localhost:8080/api/agent/stream `
    -H "Content-Type: application/json" `
    -d '{"message": "用三句话介绍 Spring Boot"}' `
    -N
  ```
- **验证点**：
  - 收到多个 `data:` 事件（逐字/逐词返回）
  - 事件内容连贯，最终可拼成完整回答
  - 流以 `[DONE]` 标记结束
  - 无中断或超时
- **产出物**：SSE 事件流截图

### 4.5 任务 9.5：工具调用验证

- **目标**：验证 Agent 能自主决定调用工具
- **测试场景1（计算器）**：
  ```powershell
  curl -X POST http://localhost:8080/api/agent/chat `
    -H "Content-Type: application/json" `
    -d '{"message": "请计算 2 的 32 次方是多少"}'
  ```
  - 验证：响应中含正确结果 4294967296
  - 验证：`toolCalls` 字段含 CalculatorTool 调用记录
- **测试场景2（时间查询）**：
  ```powershell
  curl -X POST http://localhost:8080/api/agent/chat `
    -H "Content-Type: application/json" `
    -d '{"message": "现在几点了？"}'
  ```
  - 验证：响应中含当前时间
  - 验证：`toolCalls` 字段含 TimeTool 调用记录
- **产出物**：工具调用响应截图

### 4.6 任务 9.6：多轮记忆验证

- **目标**：验证 Agent 能记住多轮对话上下文
- **测试步骤**：
  1. 第一轮对话（使用上一步获取的 sessionId）：
     ```powershell
     curl -X POST http://localhost:8080/api/agent/chat `
       -H "Content-Type: application/json" `
       -d '{"sessionId": "<上一步的sessionId>", "message": "我叫张三，是一名 Java 开发者"}'
     ```
  2. 第二轮对话（同一 sessionId）：
     ```powershell
     curl -X POST http://localhost:8080/api/agent/chat `
       -H "Content-Type: application/json" `
       -d '{"sessionId": "<同一个sessionId>", "message": "我叫什么名字？从事什么职业？"}'
     ```
- **验证点**：
  - 第二轮响应能正确回答"张三"和"Java 开发者"
  - 证明 Agent 具备上下文保持能力
- **产出物**：两轮对话响应截图

### 4.7 任务 9.7：异常场景验证

## 六、风险与注意事项

1. **API Key 余额**：Coding Plan Lite 套餐每 5 小时 1200 次限制，验证时控制调用频率，避免耗尽额度
2. **网络依赖**：火山引擎 API 需要外网访问，内网环境需配置代理
3. **模型响应时间**：首次调用可能较慢（模型加载），timeout 配置 60s 足够
4. **Windows 环境差异**：curl 命令在 PowerShell 中的语法（反引号续行），注意与 Linux 区别
5. **工具调用不确定性**：LLM 是否调用工具取决于模型决策，同一问题多次调用可能行为不同，测试时使用明确的工具触发语句（如"计算 X"）
6. **记忆窗口**：默认 20 条消息，测试多轮记忆时不要超过窗口大小
7. **流式接口超时**：浏览器/客户端需配置较长超时，避免长回答被截断
8. **日志检查**：验证后检查日志文件，确认无隐藏错误（如工具执行失败但被 Agent 忽略）
9. **回归测试**：后续迭代（RAG/MCP/多 Agent）需重新执行本阶段验证，确保不破坏基础功能
